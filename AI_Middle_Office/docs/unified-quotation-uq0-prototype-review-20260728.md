# 统一报价 UQ-0 原型评审说明

> 2026-07-28 最新阶段决策：调试期恢复独立项目报价列表/新建表单，并与旧报价对话窗口双入口并存；流程全部验收后再做入口收敛，详见 `docs/unified-quotation-chat-entry-correction-20260728.md`。

更新日期：2026-07-28

关联设计：`docs/unified-quotation-product-detailed-design-20260728.md`

## 1. 本轮评审目标

本轮只确认产品操作方式，不确认视觉细节和代码实现。

需要重点判断：

1. 用户是否能在不理解“快速报价、标准化、预算项目”的情况下完成报价；
2. 正常项目是否足够安静，异常项目是否足够突出；
3. 报价核对页是否只保留必要的人工操作；
4. 最终确认前的阻断规则是否符合业务风险；
5. 普通用户是否看到过多成本和技术信息；
6. 报价完成后的下载、审计和可选推送是否清晰。

## 2. 原型覆盖页面

### 2.1 报价列表

目的：

- 合并旧“我的报价历史”和“预算项目列表”的用户认知；
- 让草稿、处理中、待核对和已完成报价出现在一个列表；
- 统一使用报价名称、客户、状态、项目数、金额和更新时间。

核心操作：

- 新建报价；
- 继续核对；
- 查看进度；
- 查看结果。

首版暂不把高级筛选、批量归档和运营统计放入原型。

### 2.2 新建报价

目的：

- 取消快速报价、标准需求单和预算项目三选一；
- 文字、图片和 Excel 从同一页面提交；
- 项目和客户信息变成可选字段。

提交后由系统决定：

- 是否保留原始工作簿；
- 是否需要 Excel 标准化；
- 是否需要图片识别；
- 是否创建内部预算项目；
- 使用哪一种计价策略。

### 2.3 处理中

目的：

- 只显示用户能理解的处理步骤；
- 明确允许关闭页面；
- 隐藏 N8N、Dify、Celery、模型名称、batch 和 revision。

处理步骤统一展示为：

1. 读取需求；
2. 整理报价项目；
3. 匹配企业报价依据；
4. 补充缺少的价格；
5. 检查完整性；
6. 准备报价核对。

### 2.4 报价核对

这是本轮最重要的页面。

默认只展示：

- 缺价格；
- 缺工程量；
- 单位冲突；
- 映射歧义；
- AI 估价建议复核；
- 价格偏差；
- 疑似漏项；
- 确认清单与报价结果不完整。

普通正常项目不占用用户注意力，可切换到“全部明细”查看。

### 2.5 报价结果

目的：

- 明确报价已经完成；
- 优先提供原格式 Excel 或标准模板下载；
- 展示最终版本、确认人、确认时间和人工修改摘要；
- 将钉钉放在可选操作；
- 告知人工学习项只进入账户定额 draft。

## 3. 报价核对字段

### 3.1 顶部摘要

| 字段 | 普通用户可见 | 可编辑 | 说明 |
| --- | --- | --- | --- |
| 报价名称 | 是 | 是 | 默认自动提取，可在确认前修改 |
| 客户名称 | 是 | 是 | 选填，不阻断解析 |
| 当前状态 | 是 | 否 | 使用统一中文状态 |
| 项目数 | 是 | 否 | 参与报价的标准行数量 |
| 阻断问题数 | 是 | 否 | 为 0 时才允许最终确认 |
| 建议复核数 | 是 | 否 | 不直接阻断，但必须展示 |
| 已计价小计 | 是 | 否 | 不包含缺价格项目 |
| 整单合计 | 是 | 否 | 存在阻断问题时显示“待完善” |
| 自动保存时间 | 是 | 否 | 草稿保存成功后的服务端时间 |

### 3.2 主表字段

| 字段 | 普通用户可见 | 可编辑 | 规则 |
| --- | --- | --- | --- |
| 施工项目 | 是 | 受控 | 修改后保留原始值 |
| 项目特征/规格 | 是 | 是 | 保存修改前后值 |
| 工程量 | 是 | 是 | 必须为有效正数，明确排除行除外 |
| 单位 | 是 | 是 | 变更后重新检查单位兼容和合计 |
| 报价单价 | 是 | 是 | 不允许空值或 0 元作为已完成报价 |
| 合价 | 是 | 否 | 工程量乘最终报价单价，后端重算 |
| 价格来源 | 是 | 否 | 企业定额、账户定额、AI 估价、人工确认 |
| 状态 | 是 | 否 | 阻断、建议复核、正常、已解决 |
| 备注 | 是 | 是 | 不作为绕过阻断的价格字段 |

### 3.3 行详情字段

| 字段 | 默认显示位置 | 权限 |
| --- | --- | --- |
| 原始 Sheet 和行号 | 行详情 | 普通用户可见 |
| 原始项目名称和规格 | 行详情 | 普通用户可见 |
| 系统标准化结果 | 行详情 | 普通用户可见 |
| 最终工程量、单位、单价 | 行详情 | 报价角色可编辑 |
| 修改原因 | 行详情 | 超阈值改价时必填 |
| 企业定额摘要 | 行详情 | 普通用户只看非敏感摘要 |
| 定额候选和匹配分数 | 高级详情 | 成本角色 |
| 人工、主材、辅材、机械等拆分 | 高级详情 | 成本查看角色 |
| AI 输入输出和内部调用信息 | 后台审计 | 管理员或运维 |
| 修改前后值、操作者和时间 | 审计记录 | 报价负责人及授权角色 |

## 4. 字段编辑规则

### 4.1 工程量

- 空、非数字、负数和不支持的精度为阻断；
- 明确的 0 工程量不得静默当作有效报价行；
- 修改工程量后，行合价和整单合计由服务端重新计算；
- 不覆盖原始 Excel 工程量，标准值与原始值同时保留；
- 若用户选择“不报价/不计入”，必须填写原因。

### 4.2 单位

- 单位修改后重新执行定额兼容校验；
- 不自动进行没有明确规则的单位换算；
- 名称匹配但单位冲突时不得自动采用候选价格；
- 单位冲突解除前，该行为阻断状态。

### 4.3 报价单价

- 必须为有效正数；
- 人工价格优先于当前模式生成的系统建议；
- 缺价格使用空值语义，不写 0；
- 使用系统建议后仍属于人工确认动作；
- 人工修改达到企业阈值时要求选择原因；
- 前端展示金额仅用于交互，正式金额由后端定点十进制计算。

### 4.4 修改原因

默认原因选项：

- 客户指定；
- 地区差异；
- 施工条件；
- 采购差异；
- 临时市场价；
- 其他。

首版不要求每次修改都输入长文本。只有选择“其他”或企业规则要求时，才补充说明。

## 5. 异常处理规则

### 5.1 阻断

| 异常 | 用户操作 | 解决条件 |
| --- | --- | --- |
| 缺工程量 | 填写工程量或明确排除 | 有效正数或有原因的排除 |
| 缺价格 | 采用建议价或人工补价 | 有效正数价格 |
| 单位冲突 | 选择正确单位或候选 | 单位兼容校验通过 |
| 关键字段映射歧义 | 选择正确字段 | 当前 Sheet 唯一映射 |
| AI 缺失占位 | 人工补价 | 不再是占位状态 |
| 报价完整性不一致 | 补齐或明确排除 | 确认清单逐行有处理结果 |
| 正式价格源不可用 | 管理员处理 | active 定额满足严格门禁 |
| 版本冲突 | 刷新并重新核对 | 基于最新版本保存 |

### 5.2 建议复核

| 异常 | 默认动作 | 是否阻断 |
| --- | --- | --- |
| AI 估价无定额依据 | 展示建议价和说明 | 否 |
| 与参考价格偏差较大 | 展示偏差和依据 | 否 |
| 人工改价幅度较大 | 要求选择原因 | 视企业规则 |
| 疑似漏项 | 展示建议，不自动新增 | 否 |
| 同名多规格 | 展示候选 | 选择价格前阻断 |
| 原格式部分字段无法回填 | 展示输出说明 | 关键价格列无法回填时阻断 |

## 6. 关键按钮规则

| 按钮 | 出现条件 | 行为 |
| --- | --- | --- |
| 开始生成报价 | 有文字或附件 | 创建统一报价任务 |
| 采用系统建议 | 存在有效建议值 | 填入编辑区，不直接确认 |
| 保存并解决 | 当前行字段通过校验 | 保存行并重新计算异常 |
| 保存草稿 | 核对阶段 | 保存当前修改，不改变正式状态 |
| 确认并生成报价 | 阻断问题为 0 | 创建不可变版本和输出任务 |
| 下载原格式 Excel | 原始文件可用且输出成功 | 下载回填文件 |
| 发送到钉钉 | 企业启用集成 | 可选推送，不改变报价完成状态 |

## 7. 四类验收场景

### 场景 A：文字需求

输入：

`客厅吊顶 50㎡，地面铺石材 80㎡，包含人工和辅材。`

预期：

- 自动创建报价工作空间和内部项目；
- 解析为标准报价行；
- 自动计价；
- 有 AI 估价时标明来源；
- 用户只处理异常并最终确认；
- 使用企业标准报价模板导出。

### 场景 B：图片需求

输入：

- 一张装修需求截图；
- 图片中包含项目名称、数量和单位。

预期：

- 图片识别结果转换为标准报价行；
- 低置信度数量或单位进入阻断问题；
- 用户可以查看原图证据；
- 不要求用户先选择“图片报价”流程；
- 使用企业标准报价模板导出。

### 场景 C：简单 Excel

输入：

- 单 Sheet；
- 项目名称、规格、工程量、单位字段明确。

预期：

- 自动识别字段；
- 无异常时不展示映射确认步骤；
- 自动进入计价；
- 保留原始文件；
- 最终回填原格式 Excel。

### 场景 D：复杂 Excel

输入：

- 多 Sheet；
- 表头不固定；
- 包含说明、汇总、价格和多工程量列。

预期：

- 自动识别业务 Sheet 和参考 Sheet；
- 价格、金额和分层工程量列按规则锁定；
- 只让用户处理低置信度关键映射；
- 高置信度 Sheet 自动通过；
- 形成唯一正式清单快照；
- 自动创建计价草稿并批量补价；
- 原格式导出不破坏原列、公式、合并单元格和样式。

## 8. UQ-0 通过标准

在进入 UQ-1 编码前，应确认：

- 唯一入口页面结构；
- 报价列表字段和状态；
- 报价核对主表字段；
- 行详情字段和成本权限；
- 阻断与建议复核边界；
- 最终确认按钮规则；
- 原格式 Excel 和标准模板输出选择；
- 企业默认计价模式；
- 是否需要负责人二次审批；
- 四类验收样例可用于后续回归。

## 9. 建议默认结论

- 企业默认模式：企业定额匹配 + AI 补充缺口；
- 普通用户不显示成本敏感拆分；
- 首版不增加负责人二次审批；
- 人工改价达到企业配置阈值时选择原因；
- “不报价/不计入”必须选择原因；
- Excel 优先原格式导出；
- 文字和图片使用企业标准模板；
- 钉钉首版保留为可选按钮；
- 旧报价历史先统一展示最近一年，完整历史继续从旧入口只读查询；
- 统一入口先按指定内部账户灰度。
