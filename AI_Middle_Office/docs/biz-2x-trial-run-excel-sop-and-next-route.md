## 2. Excel 操作 SOP

### 2.1 业务员填写对象

优先填写 `BIZ2x9h2_标准规则trace自动初判复核包_*.xlsx` 的 `标准规则trace复核` Sheet。

业务员只需要重点看这些列：

| 列名 | 怎么填 |
| --- | --- |
| `系统建议动作` | 系统判断列，优先处理 `建议采用` 和 `需人工确认` |
| `风险等级` | 高风险行必须慢一点核；中风险行可按证据快速核 |
| `是否采用（业务填写：是/否）` | 确认采用填 `是`，不采用填 `否` |
| `核验结论（业务填写：通过/有问题）` | 项目、特征、单位、工程量、扣减规则都确认后填 `通过`；任一项存疑填 `有问题` |
| `确认工程量（业务填写）` | 采用行必须是大于 0 的数字 |
| `确认单位（业务填写）` | 必须与标准单位兼容，例如 `㎡`、`m`、`个` |
| `项目名称（业务确认/可修改）` | 采用标准项目名称，不要随意改成施工口语 |
| `项目特征（业务填写，按标准字段口径）` | 字段名必须来自标准库，例如 `吊顶部位：...；吊顶形式、吊杆规格、高度：...` |
| `扣减/合并规则复核（业务填写）` | 说明是否已按标准规则处理扣减、合并、不展开、不扣除等 |
| `工程量来源说明（业务填写）` | 写清工程量来自 CAD 建议量、人工复核量或其他来源 |
| `问题说明（业务填写）` | 有问题时写原因；通过行可留空或写复核备注 |

### 2.2 通过/有问题的判定

填 `通过` 的条件：

- 标准项目选对了。
- 项目特征字段名是标准库口径，且不再包含 `待确认`、`待补`、`缺失`。
- 单位与标准单位兼容。
- 工程量大于 0。
- 工程量来源能追溯到 CAD 几何、标准规则或人工复核说明。
- 扣减/合并规则已按标准库工程量计算规则复核。

填 `有问题` 的条件：

- 标准项目不确定。
- 项目特征值缺失或无法从图纸支撑。
- 工程量边界不确定，例如节点/大样/图例被误当施工范围。
- 标准规则要求展开面积、洞口扣减、合并面积，但当前 CAD trace 证据不够。
- 图纸范围、图层、比例、单位或材料做法关联存在疑问。

## 3. 页面/API 化路线

Excel SOP 能支持技术试运行；为实现“最快舒服试运行”，当前已补充轻量 API 和页面入口。

当前轻量入口：

| 类型 | 路径 | 用途 |
| --- | --- | --- |
| 页面 | `/admin/dwg-trial` | 上传 9h-2 trace 复核工作簿，一键生成清单，查看问题并下载输出 |
| API | `POST /api/v1/admin/dwg-quantity-trial/convert` | 上传 `.xlsx/.xlsm` 复核表并运行 9h-3 转换 |
| API | `GET /api/v1/admin/dwg-quantity-trial/latest` | 读取最近一次试运行转换结果 |
| API | `GET /api/v1/admin/dwg-quantity-trial/files/{filename}` | 下载最终四字段 Excel、转换报告、问题 CSV 等输出文件 |

轻量页面/API 边界：

- 不新增数据库表。
- 不直接接报价。
- 不处理 DWG 全链路上传，只接收已生成/已填写的 9h-2 trace 复核工作簿。
- 仍然沿用 9h-3 的硬校验：未通过、项目特征有占位、工程量/单位/来源/扣减规则不完整时不生成最终四字段 Excel。

后续增强路线：

| 阶段 | 目标 | 建议内容 | 验收 |
| --- | --- | --- | --- |
| BIZ-2x-6b API 化增强 | 让前端和任务流可调用完整识图结果 | 新增图纸识别任务、DWG 上传、trace 复核读取、复核行提交、转换预检、最终清单导出接口 | API 可完成“DWG 上传到最终清单”的任务闭环 |
| BIZ-2x-6a 页面化增强 | 降低业务员 Excel 操作成本 | 页面展示系统建议采用/需人工确认/阻断行，支持逐行确认、批量通过、问题定位、导出清单 | 业务员不打开 Excel 即可完成确认 |
| BIZ-2x-6c 证据预览 | 降低误采纳风险 | 在行详情中展示来源 DWG/DXF、图层、CAD 公式、图元行号和标准规则 | 每条采用行能看到证据链 |

短期选择：

- 若要最快舒服试运行：使用 `/admin/dwg-trial` 轻量入口。
- 若业务员仍需要修改复核行：先在 9h-2 Excel 里改，再上传页面转换。
- 若要控制误判风险：优先做证据预览。

只有满足以下条件，才进入 BIZ-2x-7 报价接入：

4. 下发前仍沿用现有预审确认、成本库匹配、无底价处理和证据链规则。
