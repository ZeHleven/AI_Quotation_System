# 老板 5 分钟演示脚本

更新时间：2026-06-03

## 1. 演示目标

用 5 分钟说明系统已经从“功能很多”收束到“小范围试运行可观察”的状态。

本演示不承诺真实经营 ROI，不展示复杂跨部门规则，不现场讨论采购、合同、回款扩展。

## 2. 演示前准备

| 准备项 | 说明 |
|---|---|
| 服务状态 | `http://127.0.0.1:9000/health/ready` 返回 ready |
| 访问地址 | 使用当天 `logs/current_access_urls.txt` 中的 Local URL 或 LAN URL |
| 演示账号 | 使用管理员或管理层只读账号 |
| 样例数据 | 使用 `reports/trial_readiness/20260603_stage4/demo_sample_inventory.csv` 中标记为 sandbox 的文件 |
| 边界声明 | 先说明这是内网试运行演示，不是正式生产系统 |

## 3. 时间分配

### 0:00 - 0:40 说明当前定位

建议话术：

```text
这个系统现在不继续扩业务范围，先收束成小范围内网试运行版本。
今天看的是登录入口、报价链路、成本依据、项目进度和经营总览。
演示数据只验证系统流程可用，不代表真实经营 ROI。
```

### 0:40 - 1:20 登录与入口

页面：

```text
/login
```

展示点：

- 统一登录入口。
- 不同账号进入后看到不同模块。
- 这是内部系统，不开放公网。

不要展开：

- 不讲底层架构细节。
- 不现场创建一堆新账号。

### 1:20 - 2:20 经营总览

页面：

```text
/admin/dashboard
```

展示点：

- 报价趋势。
- 项目证据或风险摘要。
- 成本库和项目分布概览。
- 系统健康摘要。

建议话术：

```text
这个页面不是完整经营驾驶舱，只是试运行期间用来看系统有没有跑起来、哪里有风险、哪些链路需要人复核。
```

### 2:20 - 3:30 报价和需求单链路

页面：

```text
/admin/requirement-standardization
/index.html
```

展示点：

- 甲方需求单可以先做标准化。
- 只把人工确认、通过校验的行发起报价。
- 报价预审里可以看到成本库参考、无底价提示、人工改价和下发阻断。

建议话术：

```text
这里的重点不是让 AI 自动拍板，而是把需求、成本参考、人工确认和风险提示放到同一个工作台里。
```

### 3:30 - 4:20 成本库与项目进度

页面：

```text
/admin/cost-db
/admin/projects
```

展示点：

- 成本库区分 draft、active、archived。
- active 才参与报价参考。
- 项目进度只做轻量试运行，不提前固化复杂跨部门规则。

### 4:20 - 5:00 收束与下一步

建议话术：

```text
下一步不是继续堆模块，而是找一个小范围窗口试跑。
先验证业务员是否愿意用、报价复核是否更清楚、问题是否能被登记和追踪。
如果涉及跨部门规则或真实经营口径，需要等公司拍板后再固化。
```

## 4. 老板可能会问的问题

| 问题 | 建议回答 |
|---|---|
| 现在能不能正式上线？ | 还不建议。当前是 Windows 临时内网试运行，正式上线需要公司服务器、固定地址、HTTPS、备份、日志监控和运维机制。 |
| 演示数据能不能证明降本增效？ | 不能。演示数据只能证明系统流程可用，真实 ROI 要等真实业务样本和试运行记录。 |
| 能不能继续做合同、回款、采购？ | 现在不建议。跨部门对象、状态、责任、例外处理还没统一，先把报价和试运行闭环跑稳。 |
| 项目进度规则是不是已经定了？ | 没有。当前只是轻量模板和证据提示，正式规则需要公司拍板。 |
| 最大风险是什么？ | 临时 Windows 主机不具备生产稳定性，另一个风险是真实跨部门规则尚未统一。 |

## 5. 演示通过标准

- 5 分钟内能讲清系统当前价值和边界。
- 管理层能理解这是试运行准备，不是正式生产上线。
- 不把演示数据误认为真实经营成果。
- 不现场承诺新增跨部门大模块。
