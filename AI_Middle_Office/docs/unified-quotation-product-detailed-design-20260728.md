## 1. 背景

系统当前存在三种用户可感知的报价路径：

1. 快速报价：文字、图片或简单 Excel 进入旧 `index.html`，经过 AI 生成、人工预审和确认下发。
2. 标准需求单报价：复杂 Excel 先进入需求单标准化页面，完成字段映射和逐行确认后，再进入旧快速报价任务。
3. 预算项目计价：先创建预算项目，再导入 Excel、调整 Sheet 映射、确认批次、激活批次、创建计价草稿、选择计价模式、补价和导出。

这些路径分别积累了有价值的能力，但目前要求用户理解系统内部架构，并自行判断应该选择哪条流程。对外产品发布后，这会带来以下问题：

- 新用户不知道“快速报价”“标准需求单”“预算项目”的区别；
- 同一业务目标存在多个入口、多个任务状态和多个历史列表；
- 项目、批次、修订、激活、草稿、计价模式等内部概念暴露过多；
- 复杂 Excel 的人工确认步骤过长；
- 快速报价的易用性与预算项目的版本、审计、原格式导出能力没有形成统一体验；
- 两条价格链路的数据权威边界不同，不能通过简单页面拼接解决。

本设计的目标不是将两个页面机械合并，而是形成一个统一的报价产品。

---

## 2. 已确认的产品决策

### 2.1 唯一入口

普通用户只保留一个“新建报价”入口，不再选择快速报价、标准需求单报价或预算项目报价。

建议产品路由：

- `/quotes`：报价列表；
- `/quotes/new`：唯一新建报价入口；
- `/quotes/{quote_id}`：报价详情与处理进度；
- `/quotes/{quote_id}/review`：报价核对；
- `/quotes/{quote_id}/result`：报价结果、导出与分享。

现有 `/index.html?entry=new-quote&mode=quick`、`/admin/requirement-standardization` 和 `/admin/budget-projects/{id}` 在迁移期保留，不再作为新用户需要理解的入口。

### 2.2 长期业务底座

长期以预算项目、正式清单、企业定额、账户定额、计价草稿和不可变版本作为报价业务底座。

快速报价中已经成熟的输入、风险核对、预审草稿、人工改价、报价依据、历史恢复和确认下发能力，应迁入统一产品，而不是继续扩展旧页面。

### 2.3 一次必要人工确认

普通报价操作只保留一次必要人工确认：最终报价确认。

系统可以自动完成：

- 创建报价工作空间和内部预算项目；
- 判断输入类型；
- 解析和标准化；
- 高置信度字段映射；
- 内部清单批次确认和激活；
- 创建或恢复计价草稿；
- 按企业策略选择计价模式；
- 定额匹配和 AI 缺口估价；
- 完整性、漏项、单位和价格异常检查；
- 保存草稿、生成审计快照和准备输出文件。

自动处理不等于自动发布。系统不得在没有最终人工确认的情况下对外下发正式报价。

### 2.4 钉钉为可选集成

报价完成以生成可下载的报价文件为准。钉钉推送、企业消息和后续 CRM 集成均属于可选输出通道，不得成为报价完成的前置条件。

## 3. 设计原则

1. 用户只描述业务需求，不选择系统流程。
2. 正常项自动处理，页面优先展示异常项。
3. 缺价格不得伪装为 0 元，未解决时不得静默进入正式合计。
4. 高风险操作保留人工确认，低风险机械操作自动化。
5. 普通用户不接触批次、修订、内部指针和技术任务 ID。
6. 成本敏感字段按角色控制，不因统一页面扩大数据可见范围。
7. 原始输入、人工修改、价格依据和最终结果均可追溯。
8. 对外路由和产品状态稳定，内部引擎可以分阶段替换。
9. 迁移期不混用两套价格权威来源。
10. 所有新数据库结构或字段必须通过 Alembic revision 落地。

## 4. 目标用户与权限

### 4.1 普通报价人员

可以：

- 新建报价；
- 上传文字、图片、`.xlsx` 或 `.xlsm`；
- 查看自己或所属账户允许查看的报价；
- 处理报价异常；
- 修改允许修改的项目名称、规格、数量、单位、报价单价和备注；
- 完成最终确认；
- 下载报价结果；
- 恢复未完成草稿。

默认不能：

- 查看企业底层成本敏感拆分；
- 启用企业或账户定额；
- 修改企业级计价策略；
- 将学习候选直接设为 active；
- 查看其他账户的报价和项目。

### 4.2 报价负责人

在普通报价人员能力基础上，可以：

- 查看本账户报价；
- 接管、分配或复核报价；
- 查看人工改价和异常处理记录；
- 在企业策略允许时使用高级计价选项；
- 重新生成报价版本。

### 4.3 成本角色

根据现有 `cost_viewer`、`cost_editor`、`cost_approver`、`cost_exporter` 等角色继续控制：

- 成本构成查看；
- 企业/账户定额维护；
- 报价沉淀候选审核；
- 定额草稿启用；
- 成本敏感数据导出。

### 4.4 企业管理员

负责设置：

- 企业默认计价模式；
- 默认费率和报价模板；
- 异常阈值；
- 审批规则；
- 钉钉等集成；
- 用户、角色和账户权限。

## 5. 统一用户流程

```text
新建报价
  -> 输入文字、图片或 Excel
  -> 系统自动创建报价工作空间
  -> 自动解析、标准化和计价
  -> 无异常：直接进入报价核对
  -> 有异常：只展示待处理问题
  -> 用户处理阻断项
  -> 最终确认
  -> 生成报价文件和审计版本
  -> 下载、分享或可选推送
```

### 5.1 第一步：提交需求

页面只保留一个主工作区：

- 拖拽或选择文件；
- 输入文字需求；
- 粘贴图片；
- “开始生成报价”主按钮。

项目名称、客户名称、报价说明等字段默认折叠：

- Excel 有项目名称时自动提取；
- 没有名称时使用客户名、文件名或日期自动生成；
- 用户可在提交前修改，也可在报价核对时补充；
- 不因缺少客户名称阻塞报价解析。

输入支持边界：

- 文字：支持；
- 常见图片：支持；
- `.xlsx` / `.xlsm`：支持并保留原始工作簿；
- 旧 `.xls`：提示另存为 `.xlsx`；
- PDF、DWG 等文件是否进入首期，由单独能力评估决定，不在本次合并中自动扩大范围。

### 5.2 第二步：系统自动处理

用户看到的是业务语言进度：

1. 正在读取需求；
2. 正在整理报价项目；
3. 正在匹配企业报价依据；
4. 正在补充缺少的价格；
5. 正在检查完整性；
6. 报价已准备好。

页面不得显示：

- N8N、Dify、DeepSeek、Celery 等内部服务名；
- import batch、revision、active pointer；
- enterprise_ai、account_strict 等内部枚举；
- P2、BIZ 等研发阶段编号；
- 数据库表名和内部任务堆栈。

后台应支持安全重试和断点恢复。页面关闭后，用户从报价列表继续即可。

### 5.3 第三步：处理异常并核对报价

页面默认进入“待处理问题”视图，而不是先展示全部明细。

顶部摘要：

- 报价项目数；
- 已完成计价数；
- 阻断问题数；
- 建议复核数；
- 当前报价小计和整单合计；
- 最近自动保存时间。

建议标签：

- `待处理问题`
- `全部明细`
- `费用汇总`
- `报价依据`

普通用户主表字段：

- 施工项目；
- 项目特征/规格；
- 工程量；
- 单位；
- 报价单价；
- 合价；
- 价格来源；
- 状态；
- 操作。

成本拆分、候选匹配、原始行、AI 说明和审计证据放入行详情抽屉，不横向堆叠在主表中。

### 5.4 第四步：最终确认与输出

主操作固定为“确认并生成报价”。

确认前系统再次校验：

- 所有应报价行均有明确处理结果；
- 缺价格行已补价或被明确排除；
- 缺工程量和单位冲突已解决；
- 高风险改价已填写必要原因；
- 用户仍具备当前项目和报价权限；
- 使用的清单、定额和草稿版本没有在处理中被替换。

确认成功后：

- 生成不可变报价版本和审计事件；
- Excel 来源优先生成原格式回填文件；
- 文字或图片来源使用企业标准报价模板；
- 将符合条件的人工报价学习项写入账户定额 draft 或候选队列；
- 不自动启用企业定额或账户定额 active；
- 展示下载、复制链接和可选钉钉推送。

## 6. 异常分级与人工介入

### 6.1 阻断问题

以下问题未解决时，不允许最终确认：

- 应报价行缺少有效工程量；
- 单位冲突且无法确定换算关系；
- 应报价行缺少有效单价；
- AI 未返回且没有人工补价；
- 关键字段映射存在歧义；
- 确认清单与报价结果不完整；
- 正式企业定额处于 0 个、多个或不一致的 active 状态；
- 当前清单或计价草稿已被其他操作替换；
- 输出文件无法定位原始明细行；
- 权限或账户归属在处理期间发生变化。

允许用户明确将某一行标记为“不报价/不计入”，但必须选择原因，并保留原始行和操作记录。不得通过填写 0 元绕过阻断。

### 6.2 建议复核

以下问题可以继续，但必须在最终确认前被用户看到：

- 使用 AI 估价且没有定额依据；
- 与企业定额或历史合理区间偏差较大；
- 人工修改幅度超过企业阈值；
- 疑似漏项；
- AI 说明与清单字段存在冲突；
- 同名多规格候选；
- 使用了账户定额草稿来源的历史参考；
- 原始 Excel 存在无法回填的非关键字段。

对超过阈值的人工改价，只要求用户选择简短原因，例如：

- 客户指定；
- 地区差异；
- 施工条件；
- 采购差异；
- 临时市场价；
- 其他。

### 6.3 普通提示

以下内容只做信息展示：

- 自动采用企业定额；
- 已恢复上次草稿；
- 已自动映射高置信度字段；
- 已保留原工作簿；
- 已生成报价依据；
- 已自动保存。

## 7. 计价策略

### 7.1 普通用户不选择计价模式

现有“基础定额”和“账户定额”模式不再作为普通用户每次报价前的必选项。

企业管理员配置默认策略：

1. 标准智能模式：企业定额匹配，未匹配项目使用 AI 估价；
2. 账户严格模式：只使用当前账户 active 定额，不自动使用企业定额或 AI 补价。

只有具备相应权限的报价负责人或成本角色，才能在“高级设置”中临时变更允许的模式。

### 7.2 价格采用规则

统一页面显示“最终报价单价”，但必须保存来源。

建议采用优先级：

1. 有效人工确认价；
2. 当前计价模式产生的有效建议价；
3. 当前计价模式的定额基础价；
4. 未定价。

具体优先级必须服从现有 `enterprise_ai` 和 `account_strict` 的正式服务规则，不在前端重复计算或另造一套口径。

### 7.3 缺价格规则

- 缺价格显示为“待补价”，数据库和 API 使用空值语义；
- 不得用 0 元冒充已完成计价；
- AI 失败不导致整单任务丢失，应进入部分完成状态；
- 人工补价后必须记录来源、修改前后值和操作者；
- 只有全部阻断问题解决后，整单才可标记为可确认。

列表字段：

- 报价名称；
- 客户；
- 创建人；
- 来源类型；
- 当前状态；
- 项目数；
- 报价金额；
- 待处理问题；
- 更新时间；
- 操作。

统一状态展示：

- 处理中；
- 需要补充；
- 待核对；
- 可确认；
- 已完成；
- 失败；
- 已取消；
- 已归档。

列表不得要求用户分别进入“我的报价历史”和“预算项目列表”查找同一类业务。

### 8.2 新建报价 `/quotes/new`

页面结构：

```text
页面标题：新建报价

[拖入图片或 Excel，或点击选择文件]
[文字需求输入框                            ]

[项目和客户信息（可选，默认折叠）]
```

空状态示例可以保留，但应缩小为辅助提示，不继续使用对话聊天记录作为页面主体。

### 8.3 报价详情 `/quotes/{quote_id}`

页面结构：

```text
项目标题 / 客户 / 状态 / 自动保存时间

```

页面结构：

```text
人工修改摘要
待审核学习候选摘要
```

## 9. 产品状态机

### 9.1 对外状态

```text
draft
  -> processing
  -> needs_input
  -> needs_review
  -> ready_to_confirm
  -> confirmed
  -> completed

任意非终态
  -> failed
  -> cancelled

completed
  -> archived
```

状态含义：

- `draft`：已创建但尚未提交；
- `processing`：系统自动解析、计价或检查中；
- `needs_input`：存在阻断问题，需要用户补充；
- `needs_review`：报价已生成，需要人工核对；
- `ready_to_confirm`：阻断问题已解决，可以最终确认；
- `confirmed`：人工确认已完成，正在生成正式输出；
- `completed`：正式输出已生成；
- `failed`：系统错误，允许安全重试；
- `cancelled`：用户或管理员取消；
- `archived`：历史归档，只读。

### 9.2 内部处理阶段

`processing` 内部可以细分：

- `creating_workspace`
- `ingesting`
- `parsing`
- `standardizing`
- `validating_input`
- `preparing_pricing`
- `matching_quota`
- `estimating_gaps`
- `validating_quote`
- `preparing_review`
- `generating_output`

内部阶段用于任务恢复、日志和监控，对普通用户映射成简洁中文进度。

### 9.3 状态写入原则

- 后台任务状态必须可重入；
- 相同请求不得重复创建多个正式版本；
- 用户人工修改优先于后台迟到结果；
- 任务取消后不得继续写回 AI 结果；
- 版本指针变更时必须重新校验；
- 所有正式状态变化写入追加式事件记录。

## 10. 统一产品层与双链路过渡

### 10.1 统一报价工作空间

对外产品使用稳定的 `quote_id`，不向用户暴露 `quote_job_id`、`budget_project_id`、import batch ID 或 pricing run ID。

建议引入“统一报价工作空间”产品聚合：

```text
Quote Workspace
  -> 输入文件与文字
  -> 内部预算项目
  -> 标准清单版本
  -> 计价草稿
  -> 审核问题
  -> 最终报价版本
  -> 输出文件
  -> 审计事件
```

长期每个新报价工作空间都自动创建或关联一个预算项目。外部 `quote_id` 保持稳定，内部预算项目、清单批次和计价版本可以迭代。

是否新增独立 `quote_workspaces` 表，应在实施前结合现有模型完成数据库设计评审。若新增，必须通过 Alembic revision，不允许依赖启动时自动建表。

### 10.2 第一阶段适配

第一阶段通过统一产品服务或 BFF 层屏蔽现有差异：

```text
统一报价页面
  -> 统一报价 API
      -> 预算项目适配器
      -> 旧快速报价适配器（过渡）
```

适配器负责：

- 将内部状态转换为统一状态；
- 将不同明细结构转换为统一核对模型；
- 将错误转换为用户可理解的问题；
- 保留原始引擎的权限和审计规则；
- 为旧任务提供恢复入口。

第一阶段不要求两个后端立刻共用同一个价格源。

### 10.3 价格源硬边界

迁移期必须继续遵守：

- 旧快速报价链路的正式成本参考仍按其现有 `cost_items.active` 规则运行；
- 预算项目正式计价只读取严格唯一的 active 企业定额，以及当前模式允许的账户定额；
- 预算项目链路不得读取或写入旧 `cost_items`、旧 materials 或旧报价/RAG 价格源；
- 旧快速报价不得把预算项目定额静默复制为自己的权威价格源；
- 两条链路只能在统一产品层汇总状态和展示结果，不能混算价格；
- 新的人工学习项只能进入 draft 或候选，不得自动 active。

### 10.4 长期收敛

长期收敛路径：

1. Excel 输入直接进入预算项目标准清单和计价草稿；
2. 文本、图片解析结果转换为同一种标准清单行；
3. 快速报价的异常检查、草稿恢复、依据展示和确认能力迁入统一报价工作空间；
4. 所有新报价使用企业/账户定额底座；
5. 旧快速报价停止创建新任务，仅保留历史查询和迁移回退；
6. 完成观察期后退役旧写入接口和旧入口。

## 11. 概念 API 设计

以下为产品接口草案，不代表已经批准具体字段或立即实施：

- `POST /api/v1/quotes`：创建报价草稿；
- `POST /api/v1/quotes/{quote_id}/inputs`：上传文件或提交文字；
- `POST /api/v1/quotes/{quote_id}/generate`：启动统一处理任务；
- `GET /api/v1/quotes`：统一报价列表；
- `GET /api/v1/quotes/{quote_id}`：报价详情和进度；
- `GET /api/v1/quotes/{quote_id}/review`：核对摘要与明细；
- `PATCH /api/v1/quotes/{quote_id}/review-lines/{line_id}`：修改一行；
- `POST /api/v1/quotes/{quote_id}/review/resolve`：处理异常；
- `POST /api/v1/quotes/{quote_id}/confirm`：最终确认；
- `GET /api/v1/quotes/{quote_id}/versions`：历史版本；
- `GET /api/v1/quotes/{quote_id}/exports/{export_id}`：下载输出；
- `POST /api/v1/quotes/{quote_id}/integrations/dingtalk`：可选推送；
- `POST /api/v1/quotes/{quote_id}/cancel`：取消处理中任务；
- `POST /api/v1/quotes/{quote_id}/retry`：从安全节点重试。

接口设计要求：

- 所有写接口校验账户归属；
- 使用幂等键防止重复建单和重复确认；
- 版本号或 revision 用于乐观锁；
- 金额使用定点十进制字符串；
- 未定价使用 `null`，不用 0；
- 返回稳定的业务错误码和中文可读信息；
- 列表和详情默认不返回无权限查看的成本敏感字段；
- 最终确认必须验证当前输入、草稿和定额快照。

## 13. 分阶段实施

### 阶段 UQ-0：详细设计与验收样例

目标：

- 确认本设计；
- 确认页面线框和字段；
- 固化状态机、角色和异常分级；
- 准备文字、图片、简单 Excel、复杂 Excel 四类验收样例；

本阶段不改业务代码和数据库。

### 阶段 UQ-1：统一入口与产品外壳

目标：

- 新增 `/quotes`、`/quotes/new` 和统一详情壳；
- 主导航只保留一个报价入口；
- 建立统一状态和错误展示；
- 通过适配器继续调用现有链路；
- 旧入口保留，不立即重定向；

原则：

- 不改现有价格口径；
- 不删除旧页面；
- 不改变旧任务恢复能力；
- 不要求第一阶段立即合并数据库。

### 阶段 UQ-2：Excel 预算流程自动化

目标：

- 上传 Excel 后自动建项目；
- 自动标准化和高置信度映射；

- 自动运行企业定额匹配和 AI 缺口估价；
- 只把异常交给用户；
- 完成统一核对页和原格式导出。

### 阶段 UQ-3：文字和图片收敛

目标：

- 将文字和图片解析结果写入统一标准清单模型；
- 将快速报价的预审、风险、漏项、草稿、证据和确认能力迁入新核对页；
- 新建任务默认不再进入旧 `index.html`；
- 旧快速报价仅作为受控回退。

### 阶段 UQ-4：统一历史与旧链路退役

目标：

- 统一报价列表覆盖新任务和历史可访问任务；
- 旧 URL 跳转到对应统一页面；
- 旧快速报价停止创建新任务；
- 保留只读历史和回滚观察窗口；
- 观察稳定后退役旧写入入口。

## 14. 功能开关与回退

建议按账户而不是随机用户灰度，避免同一账户出现不同价格体验。

概念功能开关：

- `FEATURE_UNIFIED_QUOTES`
- `FEATURE_UNIFIED_QUOTE_EXCEL_AUTOMATION`
- `FEATURE_UNIFIED_QUOTE_TEXT_IMAGE`
- `FEATURE_UNIFIED_QUOTE_LEGACY_REDIRECT`

回退原则：

1. UQ-1/UQ-2 出现问题时，关闭统一入口开关即可恢复旧入口；
2. 不删除旧页面、旧 API 或历史数据；
3. 已创建的预算项目和报价任务继续按原规则处理；
4. 不通过数据库回滚解决普通页面问题；
5. 定额 active 状态和历史不可变版本不受入口切换影响；
6. 每次切换后使用固定样例验证文字、图片、Excel、人工改价、确认和导出。

## 15. 监控指标

产品指标：

- 新建报价入口到成功提交的转化率；
- 从提交到进入核对页的平均耗时；
- 每单需要用户点击的操作数；

- 人工改价率；
- 报价草稿恢复率；
- 最终确认完成率；
- 原格式导出成功率；
- 用户返回旧入口的比例。

稳定性指标：

- 解析失败率；
- AI 估价失败率和部分失败率；
- 任务重试成功率；
- 版本冲突率；

- 输出文件无法定位原始行的次数。

## 16. 分阶段验收标准

### 16.1 统一入口验收

- 普通用户主导航只有一个报价入口；
- 用户不需要选择快速、标准化或预算项目；
- 文字、图片和 Excel 均从同一页面提交；
- 页面不展示内部流程术语；
- 旧入口仍可回退。

### 16.2 自动化验收

- Excel 提交后自动创建内部项目；
- 高置信度映射无需用户点击确认；
- 低置信度映射只展示具体异常字段；
- 无异常清单自动进入计价；
- 不要求用户手工确认批次、激活批次或创建草稿；
- AI 批量补价失败时保留已成功结果。

### 16.3 核对页验收

- 默认只展示待处理问题；
- 用户可以切换查看全部明细；
- 普通用户看不到无权限的成本敏感字段；
- 修改数量或单价时合计正确联动；
- 所有修改自动保存并可恢复；
- 阻断问题未解决时最终确认按钮不可用；
- 缺价格不显示为 0 元。

### 16.4 输出验收

- Excel 来源可以导出原格式报价文件；
- 原项目和工程量列不被静默覆盖；
- 缺少目标价格列时只在安全位置追加；
- 文字或图片来源可以导出标准报价模板；
- 最终文件保存报价版本、操作者和时间；
- 钉钉不可用不影响文件生成。

### 16.5 权限与审计验收

- 账户 A 无法读取账户 B 的报价、项目和文件；
- 普通报价人员无法查看未授权成本拆分；
- 最终确认前后数据快照可追溯；
- 人工改价保存修改前后值和原因；
- 学习项只进入 draft 或候选；
- 不自动修改企业/账户定额 active；
- 旧、新价格权威来源没有跨链路混算。

## 17. 实施前必须确认的设计项

以下事项不影响本方案方向，但必须在开始写代码前完成确认：

1. 统一 `quote_id` 是否使用新的报价工作空间表，或先映射现有业务 ID；
2. 企业默认采用标准智能模式还是账户严格模式；
3. 普通报价人员是否可以看到最终报价的成本拆分；
4. 人工改价达到什么比例时必须填写原因；
5. “不报价/不计入”允许哪些原因；
6. 文字和图片生成的标准报价模板样式；
7. 报价完成后是否需要负责人二次审批；
8. UQ-1 首批灰度账户和回退负责人；
9. 旧报价历史需要迁移到统一列表的时间范围；
10. 钉钉推送在首期是保留、隐藏还是仅管理员配置后显示。

## 18. 当前结论

推荐的实施路径是：

```text
先统一产品入口和状态
  -> 再自动化 Excel 预算流程
  -> 再让文字和图片汇入同一标准清单与计价底座
  -> 最后统一历史并退役旧快速报价写入
```

不推荐：

- 直接把两个现有页面嵌在同一页面；
- 只做菜单跳转而保留用户流程选择；
- 一次性删除旧链路；
- 将旧 `cost_items.active` 与企业/账户定额混算；
- 为了减少点击而取消最终人工确认；
- 自动把 AI 或人工报价直接写成 active 定额；
- 用 0 元填补缺价格并生成“完整报价”。

该设计确认后，下一步应先完成 UQ-0 的页面线框、字段级交互和四类验收样例，再进入 UQ-1 代码实施。
