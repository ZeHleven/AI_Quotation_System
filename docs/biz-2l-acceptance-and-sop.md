# BIZ-2l 甲方需求单标准化到报价预审验收记录与操作 SOP

> 状态：当前环境业务验收已完成（2026-05-27）
> 适用范围：内网验证阶段的甲方需求单标准化、人工确认、发起异步报价、AI 预审复核、缺失占位补价和确认推送。
> 系统边界：不作为正式生产上线；`PUBLIC_ACCESS_ENABLED=false`；不改变报价规则、价格口径、无底价自动处理和成本库沉淀逻辑。

## 1. 当前结论

BIZ-2l 主链路已经完成当前环境业务验收：甲方 Excel 需求单可以先进入标准化确认工作台，经人工列映射、行确认和阻断行校验后，再发起现有异步报价任务；旧报价工作台继续接管报价进度和 AI 预审弹窗；预审阶段能对账确认清单与 AI 返回行，发现不完整预审、无底价参考和缺失占位；未补价的占位行不能确认推送。

本阶段只解决“甲方需求单格式不固定如何稳定进入报价链路”的问题，不解决“成本库材料数据不足”问题。更多材料数据仍需等待业务部门补充。

## 5. 操作 SOP

### 5.1 准备工作

1. 确认后端可访问：打开 `http://localhost:9000/`。
2. 确认当前使用内网环境，`PUBLIC_ACCESS_ENABLED=false`。
3. 确认待处理需求单为 `.xlsx` 或 `.xlsm`。
4. 如果是旧 `.xls`，先另存为 `.xlsx`。
5. 登录管理员或具备报价操作权限的账号。

建议管理员先检查：

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:9000/health/ready
```

如需要确认数据库版本：

```powershell
cd C:\Users\12521\Documents\Codex\2026-04-25\ai-pycharm\Clear_test\AI_Middle_Office
& 'C:\Users\12521\miniconda3\python.exe' -m alembic current
```

### 5.2 上传并解析甲方需求单

1. 打开 `/admin/requirement-standardization`。
2. 上传 `.xlsx` 或 `.xlsm` 需求单。
3. 等待系统按 Sheet 输出解析预览。
4. 先查看 Sheet 列表，确认是否解析到所有应处理的 Sheet。
5. 查看系统识别出的项目名称、规格、数量、单位、备注和原始行号。

验收口径：

- 所有业务相关 Sheet 应可见。
- 原始行号、原始字段、原始文本应能追溯。
- 合计行、说明行、空白行不应直接进入报价。
- 低置信度或缺数量、缺单位行应提示人工确认。

### 5.3 人工列映射

1. 按 Sheet 检查系统自动识别的列映射。
2. 如果系统把列猜错，手动指定：
   - 项目名称
   - 规格/项目特征
   - 数量/工程量
   - 单位/计量单位
   - 备注/说明
3. 重新生成当前 Sheet 的标准化行。
4. 用搜索和筛选检查低置信度、有警告、多数量候选和缺字段行。

验收口径：

- 项目名称不能把“项目特征”误当成主名称。
- 数量必须来自业务确认的工程量列。
- 多工程量候选时必须选择正确数量来源。
- 甲方表格中的单价、合价、金额只保留原始信息，不参与系统定价。

### 5.4 行确认与剔除

1. 按 Sheet 查看标准化行。
2. 对有效施工项进行确认。
3. 对说明行、汇总行、空白行、无法报价行执行剔除。
4. 对低置信度行逐条核对项目名称、规格、数量、单位。
5. 需要批量操作时，可按当前筛选结果全选、取消选择、批量确认或批量撤回确认。

验收口径：

- 只有人工确认的标准行可以进入报价。
- 阻断行不能进入报价。
- 剔除行、说明行、汇总行、空白行不能进入报价。
- 每个确认行都必须能追溯 Sheet 和原始行号。

### 5.5 生成确认清单并发起报价

1. 点击生成确认清单。
2. 如存在阻断行，先处理问题面板中的行。
3. 确认无阻断问题后，点击发起报价。
4. 系统会重新校验当前确认行。
5. 创建异步报价任务后，页面会跳转旧报价工作台 `/index.html` 接管进度。

验收口径：

- 发起报价前必须重新校验确认行。
- 阻断行存在时，系统应展示中文原因并定位到对应原始行。
- 报价任务只包含已确认且通过校验的标准行。
- 不新增报价规则，不改变价格口径。

### 5.6 查看报价进度与 AI 预审

1. 在旧报价工作台等待异步报价完成。
2. 大清单会自动分批进入现有 N8N/Dify 报价链路。
3. AI 返回后，系统弹出原有预审弹窗。
4. 检查预审弹窗中的确认清单行数、AI 预审行数和完整性提示。
5. 查看每行成本库参考、AI 报价来源、风险标签和复核原因。

验收口径：

- 确认清单与预审单数量差异必须明确提示。
- 无底价参考应标为需复核。
- AI 预审不完整时不能直接确认推送。
- 报价运营详情中应能继续查看具体预审条目、风险原因和检查项。

### 5.7 缺失占位补价

当 AI 没有返回某些确认行时，系统会生成占位预审行。

占位行特征：

- `requirement_placeholder=true`
- `quote_source=requirement_placeholder`
- 单价默认为 0
- 系统合计默认为 0
- 文案提示“AI 未返回，需人工补价”
- 保留数量、单位、Sheet、原始行号和原始备注

业务员必须人工填写：

- 单价
- 系统合计
- 必要时补充备注或依据

验收口径：

- 占位行不触发成本库底价自动兜底。
- 未补单价和系统合计前不能确认推送。
- `/confirm_push` 对未补价占位行返回 409。

### 5.8 确认推送或打回

可以确认推送的条件：

- 预审行已覆盖全部确认行，或缺失行已用占位保留并完成人工补价。
- 没有未处理的阻断项。
- 没有未补价的占位行。
- 业务员已确认单价、系统合计和备注。

必须打回或重新发起报价的条件：

- AI 预审不完整且缺失行没有占位或无法人工补价。
- 关键项目名称、数量、单位明显错误。
- 业务员无法确认无底价项目价格。
- N8N/Dify 返回异常内容，导致预审不可用。

## 6. 管理员复核 SOP

### 6.1 报价运营详情复核

1. 打开 `/admin/dashboard`。
2. 进入报价运营相关视图。
3. 找到对应报价任务。
4. 查看任务详情和预审条目。
5. 核对：
   - 确认清单行数
   - AI 预审行数
   - 匹配行数
   - 缺失行数
   - 占位行数
   - 无底价参考数量
   - 高风险数量
   - 需复核数量

### 6.2 API 复核

管理员可通过接口查看对账详情：

```text
GET /api/v1/quote/jobs/{job_id}/review-detail
```

典型验收任务的复核摘要：

```json
{
  "integrity_status": "complete_with_placeholders",
  "requirement_row_count": 169,
  "preview_row_count": 169,
  "matched_count": 169,
  "missing_count": 0,
  "placeholder_count": 169,
  "no_cost_reference_count": 153,
  "review_required_count": 169,
  "high_risk_count": 169
}
```

### 6.3 后端阻断复核

未补价占位行推送时，`/confirm_push` 应返回：

```text
409
预审单中还有 169 行是 AI 未返回的占位行，请先人工填写单价和系统合计后再下发。
```

不完整预审推送时，`/confirm_push` 应返回：

```text
409
AI 预审不完整：确认清单 N 行，AI 预审返回 M 行，仍有 K 行未匹配到预审报价。请打回重填或重新发起报价。
```

## 7. 常见异常处理

| 异常 | 处理方式 |
|------|----------|
| 页面无法访问 | 先检查后端是否启动，再检查 9000 端口是否被旧进程占用 |
| Celery worker 未加载新代码 | 使用 `start_all.ps1 -Restart` 或 `start_celery_worker.ps1 -Restart` 重启 |
| `/health/ready` worker 不正常 | 检查 Redis、Celery worker 和 Windows 后端日志 |
| `.xls` 无法上传 | 另存为 `.xlsx` 后再上传 |
| 列映射明显错误 | 按 Sheet 手动指定列映射后重新确认 |
| 数量识别错 | 切换标准数量来源或手动修改数量 |
| 有阻断行不能报价 | 按问题面板定位原始行，补齐字段或剔除该行 |
| AI 返回少量行 | 系统会补报 1 次；仍缺失则生成占位行 |
| 占位行无法确认推送 | 人工补单价和系统合计后再推送 |
| N8N/Dify 空响应 | 检查 N8N Respond to Webhook、Dify 工作流和模型响应 |
| 结果写库超长 | 当前已通过 `20260526_0023` 将大 JSON 字段扩为 `LONGTEXT` |

## 9. 交接说明

业务员操作重点：

- 先确认列映射，再确认行。
- 不要让说明行、汇总行、空白行进入报价。
- 多数量候选时必须确认哪个是工程量。
- AI 未返回的占位行必须人工补单价和系统合计。
- 无底价参考不是系统错误，而是提示业务员复核价格依据。

管理员复核重点：

- 看 `review-detail` 或报价运营详情中的行数对账。
- 看缺失行、占位行、高风险、无底价参考数量。
- 检查 `/confirm_push` 是否仍对不完整预审和未补价占位行返回 409。
- 如重启服务，优先确认 Celery worker 是否加载新代码。

仍未解决的业务问题：

- 更多材料数据需要等待业务部门补充。
- 无底价项目是否允许 AI 估价、是否必须补库后报价，仍需另行定规则。
- 成本价查看、修改、导出和同步权限仍需生产前梳理。
- 正式生产上线 Runbook 尚未完成。
