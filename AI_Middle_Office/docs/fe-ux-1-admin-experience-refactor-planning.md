# FE-UX-1 前端体验重构一期执行规划

> 状态：FE-UX-1 前端保守型体验重构一期已完成并通过人工验收（2026-06-02），覆盖 FE-UX-1-1 应用外壳与视觉基础、FE-UX-1-2 报价工作台流程优化、FE-UX-1-3 AI 预审弹窗重构、FE-UX-1-4 成本库高级表格优化、FE-UX-1-5 经营总览与项目进度体验补强、FE-UX-1-6 试运行体验验收包。本阶段不新增数据库结构、不新增 Alembic、不更换技术栈、不整站套模板重写。
> 定位：在成本数据库、报价功能、项目进度、经营总览轻量 MVP 均已形成可试运行能力后，统一企业中后台视觉和高频业务流程交互，让业务员、成本部、管理员在小范围内网试运行时更容易理解、操作和复核。

## 一、为什么现在做

当前系统功能已经相对完整，但前端体验存在三个现实问题：

1. **页面能力增长快，视觉组织跟不上**
   Vite 管理台已经承载权限、驾驶舱、报价运营、需求单标准化、商务台账、成本库、项目进度、会议纪要等页面；旧报价工作台 `index.html` 也承载大量关键交互。功能能用，但页面密度、层级、状态反馈和操作动线还不够统一。

2. **试运行前，高频页面必须更顺**
   报价工作台、AI 预审弹窗、成本库是业务员和成本部最常用的入口。如果这些页面不够清晰，会直接影响试运行质量，甚至让用户误以为系统不稳定。

3. **不能为了美观牺牲已有业务稳定性**
   报价、成本库、项目进度和经营总览已经有大量业务规则和验收记录。现阶段不适合整站重写、换 UI 库或搬入大型模板工程，应该以“参考模板 + 局部重构 + 分步验收”为主。

## 二、模板参考选择

| 模板 | 用途 | 是否直接迁移 |
|---|---|---|
| `vue-pure-admin` | 主参考。参考 Vue3 / Vite / Element Plus 后台壳、菜单、标签、表格、权限、移动适配 | 不直接迁移 |
| `Vue3 Element Admin` | 参考企业后台页面组织、筛选区、表单、列表、详情页 | 不直接迁移 |
| `Ant Design Pro` | 参考信息架构、工作台、列表页、详情页、异常页、任务流 | 不迁移 React |
| `PrimeVue Sakai` | 参考干净视觉、留白、登录页、dashboard 密度 | 不切 UI 库 |
| `Vben Admin` | 参考大型后台工程化、动态菜单、主题、按钮权限 | 只参考，不照搬 |
| `vue-element-admin` | 参考经典后台模式、Excel、错误日志、权限、表格能力 | Vue2 老模板，不迁移 |

本系统主参考口径：

- **结构风格**：以 `vue-pure-admin` / `Vue3 Element Admin` 为主。
- **信息架构**：参考 `Ant Design Pro` 的工作台、列表、详情和异常页。
- **视觉克制**：参考 `PrimeVue Sakai` 的干净度，不做深色炫酷大屏。
- **技术策略**：继续使用 Vue3 + Vite + Element Plus，不换 React、不换 UI 库。

## 三、设计原则

1. **企业中后台，不是官网**
   不做 hero、大图、营销文案、炫酷动效。界面要适合反复使用、快速扫描和稳定操作。

2. **高频流程优先**
   先改报价工作台、预审弹窗、成本库，再逐步处理经营总览、项目进度、需求单标准化等页面。

3. **统一语言和状态**
   同类状态统一颜色、标签、按钮文案、错误提示和空状态。比如成本库 `draft / active / archived`、报价 `草稿 / 待预审 / 已下发 / 失败`、项目 `阻塞 / 缺证据 / 放行`。

4. **不破坏业务规则**
   前端体验重构不得改变报价价格口径、成本库 active 规则、RAG 同步规则、硬门禁规则、权限边界和审计记录。

5. **小步验收**
   每一个子阶段都必须能单独构建、单独验收、必要时回退；不做长时间大分支重构。

## 四、范围边界

本期做：

- 统一 Vite 管理台应用外壳、导航、标题、操作区、空状态、错误状态、加载态。
- 优化报价工作台和 AI 预审弹窗的流程可读性。
- 优化成本库高级表格、筛选、批量操作、详情抽屉、审计入口。
- 优化经营总览和项目进度的工作台式信息呈现。
- 形成前端体验验收清单和问题登记模板。

本期不做：

- 不引入新的 UI 库。
- 不整体搬入任何 admin 模板。
- 不把旧 `index.html` 一次性迁移到 Vite。
- 不重写报价核心逻辑。
- 不新增数据库结构。
- 不改变权限规则。
- 不做官网、营销页、深色大屏或纯视觉装饰。

## 五、当前前端结构判断

| 区域 | 当前状态 | 风险 |
|---|---|---|
| Vite 管理台 `ai-web/src/App.vue` | 已承载大量页面，功能集中 | 单文件过大，视觉和交互模式不够统一 |
| Vite 样式 `ai-web/src/style.css` | 已有基础样式和页面局部样式 | 缺少稳定设计 token、组件级复用类和页面规范 |
| 旧报价工作台 `index.html` | 报价主流程仍依赖它，预审弹窗能力完整 | 交互密度高，视觉层级和流程提示不够清晰 |
| 旧登录门户 `app.html` / `admin.html` | 仍保留兼容入口 | 品牌一致性需要逐步统一 |
| Element Plus | 当前主 UI 库 | 可继续使用，无需切换 |

### FE-UX-1-2：报价工作台流程优化

1. 旧报价工作台 `index.html`

- 业务员能在 30 秒内理解当前报价卡在哪一步。

### FE-UX-1-3：AI 预审弹窗重构

目标：

- 预审弹窗从“大表格堆信息”改为“价格依据可读 + 风险可处理 + 人工确认顺手”。

建议改动：

1. 信息分层
   - 顶部：任务摘要、总价、风险数量、完整性状态。
   - 主表：施工项目、数量、单位、成本库依据、预审参考价、人工确认价、人工确认合计。
   - 右侧/下方：当前行依据详情、AI 原始备注、成本证据、风险解释。

2. 风险提示
   - 无底价参考。
   - 偏离成本库依据。
   - 多候选未确认。
   - AI 备注与成本依据不一致。
   - 占位未补价。

3. 操作
   - 批量确认无风险行。
   - 快速定位阻断行。
   - 固定确认下发 / 保存草稿 / 打回重填按钮。

验收标准：

- 不改变 `/confirm_push` 阻断规则。
- 不改变成本库参考价和人工确认价口径。
- 有风险时能定位到具体行和原因。

执行记录（2026-06-02）：

- `index.html` AI 预审弹窗已新增顶部指挥区，集中展示最终总价、施工项目数、复核风险、成本依据覆盖率和人工修改/草稿状态。
- 已将阻断与复核提示从分散告警收束为“阻断与复核”面板，复用既有完整性、占位补价、人工确认价、成本候选、AI 改写、AI 备注、疑似未报价、无底价参考、疑似漏项和行级风险判断。
- 已在逐行表格上方新增导读栏和状态标签，提示业务员优先处理红/黄风险行、确认成本库依据并填写人工确认价与合计。
- 底部操作区已改为“状态说明 + 操作按钮”结构，保存草稿、关闭、打回重填、确认下发按钮的事件、禁用条件和文案口径保持不变。
- 本阶段未修改 `/confirm_push`、报价任务接口、成本库匹配、预审阻断、草稿保存、知识候选、推送或价格计算逻辑。
- `index.html` 内联脚本解析通过；`http://127.0.0.1:9000/index.html` 返回 200；`ai-web` 的 `npm.cmd run build` 通过，仅保留既有 chunk size warning。
- 当前会话 in-app Browser 控制仍连接失败，未完成截图级视觉验收；需由人工打开旧报价工作台并触发 AI 预审弹窗，检查顶部指挥区、阻断面板、表格导读、底部操作区在桌面与窄屏下是否有错位、遮挡或横向溢出。

### FE-UX-1-4：成本库高级表格优化

目标：

- 成本库更像标准企业后台，适合成本部长期维护。

建议改动：

- 固定筛选区：状态、来源、关键词、分类、更新时间、风险类型。
- 批量操作栏：核定 active、恢复 draft、归档、导出、同步 RAG。
- 行详情抽屉：价格拆分、生命周期、报价引用、审计记录、RAG 同步记录。
- 状态标签统一：draft / active / archived / AI 建议 / 人工 / 导入。
- 高风险提示：重复 active、相似条目、无规格、价格异常、RAG 未同步。

验收标准：

- 成本部能快速筛出待审核 draft 和 AI 建议来源。
- 管理员能快速查看某条成本的来源、去向和审计。
- 普通 staff 仍不能浏览完整成本库。

执行记录（2026-06-02）：

- `/admin/cost-db` 已新增“成本库维护工作台”摘要区，展示筛选结果、当前页 draft/active/archived 状态、已选条目和 RAG 同步状态。
- 批量核定 active、批量恢复 draft、批量归档和全选全部已从页面标题区下沉为专门的“批量操作”条，选择数量与可操作状态更清楚。
- 原有导入 Excel、同步 active 到 RAG、同步记录、导出、审计记录、状态与流向、新建条目、刷新入口保留在标题操作区。
- 本阶段未修改成本库 API、权限、active 规则、价格口径、RAG 同步、审计记录、状态流向或重复防护逻辑。
- `ai-web` 的 `npm.cmd run build` 通过；`http://127.0.0.1:9000/admin/cost-db` 返回 200。
- 用户已确认 FE-UX-1-4 页面验收通过。

6. FE-UX-1-6 试运行体验验收包，已完成文档层交付。

当前结论：

- FE-UX-1 前端保守型体验重构一期已完成。
- 后续若需要更明显的视觉变化，可另行启动“视觉统一增强”专项；该专项应继续保持不改业务规则和数据口径。

## 八、验收标准总表

| 维度 | 标准 |
|---|---|
| 技术栈 | 仍为 Vue3 + Vite + Element Plus |
| 构建 | 每阶段 `npm.cmd run build` 通过 |
| 业务逻辑 | 不改变报价、成本库、项目进度、权限和审计规则 |
| 视觉 | 页面层级清晰，按钮/标签/状态一致 |
| 操作 | 高频动作可见、阻断原因明确、下一步清楚 |
| 响应式 | 桌面优先，窄屏不明显溢出或重叠 |
| 文档 | 每阶段同步 ROADMAP / CLAUDE / AGENTS |

## 九、风险与控制

| 风险 | 控制方式 |
|---|---|
| 前端大重构拖慢试运行 | 分阶段、小步验收，不整站重写 |
| 模板引入造成依赖膨胀 | 只参考，不搬工程 |
| 美观改动误伤业务规则 | 每阶段明确“不改业务逻辑”，保留关键测试 |
| 旧报价工作台和 Vite 风格割裂 | 先统一视觉 token，再逐步优化旧页面 |
| 用户觉得变化太大 | 高频流程优先，保留熟悉入口和操作 |

## 十、当前结论

前端体验重构一期应作为系统进入小范围试运行前的关键补强，但它不是新业务功能，也不是完整前端重写。

本期成功标准不是“看起来像某个模板”，而是：

- 业务员知道下一步该做什么。
- 成本部知道哪些成本要审、依据在哪里。
- 管理员知道系统哪里异常、该跳到哪里处理。
- 管理层能用经营总览快速判断试运行状态。
