# BIZ-2w-6 补充修复：AI 占位项目名保护

> 日期：2026-05-29  
> 状态：已通过当前环境手工验收（2026-05-29）  
> 性质：预审行身份修复，不改变报价规则、价格口径或成本库 active 规则

## 背景

在 BIZ-2w-6 列名与报价来源口径调整后，手工验收发现部分预审行的“施工项目”会显示为 `item_2` 这类 AI/工作流内部占位名，而不是业务员输入的原始项目名称。

该问题不是列名调整导致项目列隐藏，而是后置成本库匹配只保留了“已命中成本库”的原始需求行身份。若某一行暂未命中成本库，同时 AI 返回 `item_1`、`item_2` 等占位项目名，前端会直接展示该占位名，导致业务员误以为预审项目丢失。

## 修复内容

- 成本库前置上下文现在会保留所有自由文本拆分出的原始需求行，包括未命中成本库的行。
- 后置成本库匹配在处理预审行时，若 AI 返回的 `project_name` 是 `item_1`、`item_2`、`project_1`、`row_1`、`line_1` 等内部占位名，会使用对应原始需求行的项目名称替换。
- 该替换只针对明确占位名；正常的 AI 返回项目名不会被覆盖。
- 原始需求行的工程量、单位、规格仍按既有“缺失或异常时补齐”的规则处理。

## 边界

- 不新增数据库结构，不需要 Alembic。
- 不修改 N8N / Dify 工作流。
- 不修改报价规则或价格口径。
- 不自动新增报价行。
- 不自动改变人工确认价。
- 不自动沉淀 active 成本库。
