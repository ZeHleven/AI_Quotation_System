# 小范围内网试运行风险边界说明

更新时间：2026-06-03

## 1. 一句话说明

当前系统是企业内部 AI 报价/项目协作系统的小范围内网试运行版本，不是正式生产系统。

## 2. 当前能验证什么

当前试运行可以验证：

- 系统能否在 Windows 临时内网服务器上稳定启动。
- 业务员是否能理解报价工作台流程。
- 需求单标准化是否能提升整理效率。
- 成本库参考价是否能辅助人工预审。
- 报价运营和看板是否能支撑复核。
- 项目进度页面是否能承载轻量任务跟踪。
- 管理层是否能看懂核心结果。
- 账号权限和备份机制是否足够支撑小范围试用。

## 3. 当前不能证明什么

当前不能证明：

- 真实业务 ROI。
- 公司全流程降本增效结论。
- 跨部门协作规则已经成熟。
- 采购、合同、回款和完整经营模型已经可上线。
- 系统已经具备正式生产 SLA。
- AI 判断可以替代人工审核。

## 4. 部署边界

当前部署方式：

- Windows 电脑作为临时内网服务器。
- 其他电脑通过 Windows 当前内网 IP 访问。
- CentOS 虚拟机提供 MySQL、Redis、RAG、N8N、MinIO、Milvus 等依赖。

风险：

- Windows 关机，系统不可用。
- Windows 换网络，访问 IP 可能变化。
- Windows 服务停止，其他人打不开。
- CentOS 虚拟机停止，数据库/RAG/队列不可用。
- 当前未配置正式 HTTPS、固定域名和生产监控。

## 5. 数据边界

试运行数据分为：

- 演示数据。
- 测试样本。
- 少量真实试运行样本。

要求：

- 演示数据不能包装成真实成效。
- 真实样本录入前后建议备份。
- `.env`、备份包、成本库导出属于敏感资料。
- 成本库导出必须有授权。

## 6. 业务规则边界

当前公司还没有正式统一定义：

- 统一对象。
- 统一状态。
- 统一交接。
- 统一责任。
- 统一例外处理。

因此当前不把以下规则写死：

- 跨部门项目流转。
- 采购/合同/回款流程。
- 完整经营驾驶舱口径。
- 项目节点最终证据规则。
- 异常上报最终制度。

试运行中发现规则问题，先登记，再由负责人后续拍板。

## 7. AI 使用边界

AI 输出用于辅助：

- 需求解析。
- 报价预审。
- 成本库参考。
- 漏项提示。
- 无底价 draft 沉淀。

AI 输出不替代：

- 人工报价确认。
- 成本负责人审核。
- 项目负责人判断。
- 公司最终业务制度。

## 8. 扩大使用前必须补齐

扩大到正式生产前，应补齐：

- 公司内网服务器或云服务器。
- 固定 IP/域名。
- HTTPS。
- 正式备份保留策略。
- 恢复演练。
- 日志监控。
- 权限审计。
- 账号停用和密码重置正式流程。
- 业务规则拍板。
- 正式上线 Runbook。

## 9. 对参与人员的说明口径

可以这样说明：

```text
这个系统现在是内网小范围试运行版，目的是验证核心流程能不能用、操作是否顺畅、哪些规则需要公司后续拍板。它不是正式生产系统，AI 结果需要人工确认，演示数据不代表真实 ROI。试运行期间发现的问题请登记，不现场临时改规则。
```
