## 一、专项目标

本专项目标是把“DWG 图纸识别”从当前的工程诊断能力，推进到可按业务员期望直接输出四字段清单：

```text
上传 DWG 图纸
  -> 识别真实施工项目
  -> 匹配 GB/T 50854-2024 标准项目与项目特征口径
  -> 判断项目应查看的图纸类型和算量场景
  -> 绑定 CAD 房间/区域/构件/材料编号证据
  -> 按标准库工程量计算规则算量
  -> 输出 Excel：项目名称、项目特征、单位、工程量
```

本专项以用户提供的真实样例作为“答案样本”：

- 图纸目录：`AI识图练习图纸/AI识图练习图纸/职工餐厅装饰、电气给排水施工图`
- 人工答案清单：`AI识图练习图纸/AI识图练习图纸/信达公司职工食堂装修改造工程量清单.xlsx`
- 当前系统四字段输出：`outputs/biz2x_trial/BIZ2x_DWG识图四字段清单_20260615_014109.xlsx`
- 样例答案反推报告：`outputs/biz2x_rule_reverse/BIZ2x_样例答案反推规则_20260615_014109.md`

## 二、当前基线

已完成第一轮样例答案对齐，结论如下：

| 指标 | 当前结果 |
| --- | ---: |
| 人工四字段清单行数 | 127 |
| 系统识别四字段行数 | 18 |
| 初步匹配行数 | 8 |
| 人工有、系统未识别 | 119 |
| 系统有、人工未列 | 10 |
| 专项算量阻断 | 15 |

当前最大问题不是单纯“算量公式没写完”，而是分为三层：

1. **项目识别覆盖不足**：拆除类、地面材料类、墙面材料类、吊顶细分类、门窗五金洁具灯具、保护/运输/保洁等大量人工清单项目没有进入系统列项。
2. **标准项目映射不足**：系统目前偏向 GB/T 装饰装修主项目，很多人工清单中的拆除、安装、成品、措施、机电给排水/电气项目需要明确是 GB/T 内项目、补充清单项目，还是暂不纳入本专项。
3. **CAD 几何绑定不足**：即使识别到项目，也常缺少房间、区域、材料编号、洞口扣减、墙高、净周长、展开面积等证据，不能直接写最终工程量。

## 三、路线分阶段

### R0. 样例答案解析与差异基线

状态：已完成首轮。

已完成内容：

- 解析人工清单四字段。
- 读取当前 DWG 识图四字段输出。
- 生成对齐明细、规则反推表、Markdown 报告和 JSON 摘要。

验收标准：

- 能稳定输出人工清单行数、系统行数、匹配/漏项/误识别统计。
- 能按规则类型分组输出：`demolition`、`floor`、`ceiling`、`wall`、`waterproof`、`linear_finish`、`baseboard`、`other`、`cad_region_binding`。

### R1. 项目识别覆盖增强

目标：先让系统“看见”人工清单里的真实项目，再谈算量。

具体工作：

1. 建立样例答案项目词库：
   - 拆除类：门拆除、地砖拆除、木地板拆除、天花拆除、墙砖拆除、洁具拆除、管线拆除等。
   - 地面类：CT、ST、门槛石、瓷砖美缝、石材地面、成品保护等。
   - 墙面类：墙砖、石材、人造石、墙布、木饰面、玻璃隔断、圆形不锈钢隔断等。
   - 吊顶类：铝扣板、石膏板、防水石膏板、木饰面天花、灯槽、造型吊顶等。
   - 线性类：踢脚线、金属线条、窗帘盒、窗台板、挡水条等。
   - 成品/设备类：门、门套、台盆、龙头、厕纸架、地漏、开关、灯具等。
2. 增强 `drawing_project_recognizer` 的图纸文字识别规则：
   - 优先平面图、材料表、门表、图例、设计说明中的项目型短语。
   - 降低纯工序、说明句、节点说明对主项目的干扰。
   - 保留材料编号证据，例如 `CT-01`、`ST-02`、`MT-01`、`MR-02`、`PM-01`。
3. 增加“人工答案覆盖率”回归指标：
   - 不再只看系统生成了多少项目。
   - 必须对比人工清单，统计漏识别、误识别、弱匹配。

验收标准：

- 第一轮目标：当前样例系统识别项目从 18 条提升到不少于 70 条候选。
- 第二轮目标：人工清单覆盖率达到 80% 以上。
- 系统误识别项必须可解释并可过滤，不能为了追求数量把说明、节点、材料碎片混进最终四字段。

### R2. 标准项目映射与范围边界确认

目标：每个识别项目都要明确属于哪种清单口径。

具体工作：

1. 将识别项目分成四类：
   - `GB/T 标准项目`：可直接匹配 GB/T 50854-2024 标准库。
   - `GB/T 可归并项目`：名称不同，但可归并到标准库中的项目名称和项目特征。
   - `补充清单项目`：人工清单中存在，但当前标准库未覆盖或属于其它专业/措施/成品设备。
   - `暂不纳入项目`：纯说明、图例、非报价行、无施工实体。
2. 对单位口径冲突做强校验：
   - 例如窗帘盒、窗台板、踢脚线、金属线条，需要确认按 `m`、`㎡`、`个` 还是成品项。
   - 单位不一致时不得直接继承系统工程量。
3. 对机电给排水、电气、洁具、灯具、开关等项目建立范围标记：
   - 若本专项暂只做建筑装饰，则进入“补充/待扩展专业”。
   - 若业务要求一起列项，则需要新增相应标准库或补充清单规则。

验收标准：

- 人工清单 127 行都要有映射状态。
- `GB/T 标准项目` 和 `GB/T 可归并项目` 必须能输出标准项目名称、项目特征字段口径、单位、工程量规则。
- `补充清单项目` 不得误写成 GB/T 项目，但可以先进入四字段候选并标记规则来源。

### R2.5. 图纸类型识别与算量场景路由

目标：把“项目应该看哪张图、取哪类证据”显式化，避免系统只按 CAD 图元盲目匹配。

本阶段根据用户补充的识图算量业务说明，将成本经理真实看图顺序固化为系统路由：

| 算量场景 | 主要查看图纸 | 核心取证对象 | 典型阻断原因 |
| --- | --- | --- | --- |
| 地面工程 | 建筑平面图、地面铺装图 | 房间/区域闭合边界、地面材料文字、材料编号、柱/墙占用范围 | 缺闭合铺装区域、材料文字只命中图例、面积包络过小 |
| 踢脚线/线条 | 建筑平面图、墙身/节点图 | 房间净周长、门洞宽度、无踢脚线墙段、线条材料 | 缺净周长、缺门洞扣减、线条材料未绑定 |
| 墙面工程 | 建筑平面图、墙面装饰图、立面图 | 房间净周长、墙高、墙面材料、门窗洞口面积 | 缺墙高、缺洞口尺寸、材料分区不清 |
| 吊顶工程 | 吊顶平面图、节点/大样图 | 吊顶闭合区域、吊顶材料、灯槽/跌级边界、展开节点 | 缺吊顶区域、展开面积证据不足、灯槽/跌级未拆分 |
| 防水工程 | 建筑平面图、卫生间/厨房详图、节点图 | 地面防水面积、墙面防水高度、门洞/翻边规则 | 缺防水高度、缺房间边界、翻边规则待确认 |
| 门窗/洁具/灯具/开关 | 门表、设备表、图例、平面块引用 | 门表数量、设备表数量、块引用计数、规格型号 | 缺表格结构、图例和实际布置未区分 |
| 家具/固定装置/特殊做法 | 立面图、大样图、节点图 | 定制柜、背景墙、隔断、特殊构件尺寸与数量 | 只在大样图出现、缺展开尺寸或安装范围 |
| 措施/保护/运输/保洁 | 说明、清单、补充规则 | 保护范围、运输次数、清理范围、人工清单依据 | 不属于装饰实体算量、需补充清单口径 |

验收标准：

- 每个识别项目都要有 `drawing_route`：图纸类型、算量场景、主证据、缺失证据。
- 前端四字段仍只显示项目名称、项目特征、单位、工程量；路由和阻断原因保留在后台诊断。
- 不得因为某类 CAD 图元存在就直接算量，必须先满足对应场景的证据组合。

### R3. CAD 证据定位与材料编号绑定

目标：按 R2.5 的场景路由，把“项目”绑定到图纸里的具体房间、区域、构件、材料编号或表格/图例证据。

具体工作：

1. 建立项目到图纸类型的路由：
   - 地面类先看地面铺装图，再回到建筑平面图校验房间边界和柱/墙占用。
   - 墙面类先看墙面装饰图/立面图，再回到建筑平面图取净周长和门窗洞口。
   - 吊顶类先看吊顶平面图，再查节点/大样判断灯槽、跌级、展开面积。
   - 计数类优先看门表、设备表、图例和实际平面块引用。
2. 建立材料编号映射：
   - `CT-*`：瓷砖地面/墙面。
   - `ST-*`：石材地面/墙面/门槛石。
   - `MT-*`：金属/不锈钢饰面或门套。
   - `MR-*`：墙面材料或洁净墙面。
   - `PM-*`：窗台石、人造石等。
3. 用人工清单工程量反查 CAD 候选：
   - 面积类：候选 CAD 区域面积与人工工程量在容差内，形成高置信绑定。
   - 长度类：候选线段/净周长/门窗宽度累计与人工工程量在容差内，形成高置信绑定。
   - 数量类：块参照、门表、设备表、灯具/开关图例计数与人工数量对齐。
4. 输出训练用绑定表：
   - 人工项目。
   - 标准项目。
   - 材料编号。
   - 来源图纸。
   - 房间/区域。
   - CAD 候选编号。
   - 人工工程量。
   - CAD 候选量。
   - 误差率。
   - 是否可沉淀为自动规则。

验收标准：

- 地面、吊顶、防水、踢脚线、墙面饰面至少形成一批可解释绑定样本。
- 不允许 `0.0001㎡` 这类碎片进入高置信绑定。
- 每条可写工程量必须有来源图纸、CAD 区域/构件、计算公式和标准规则。

### R4. 工程量计算规则扩展

目标：把样例答案中高频项目变成可执行算量规则。

优先规则按成本经理看图顺序拆分：

1. 地面面层：先看建筑平面图和地面铺装图，按闭合区域面积计算，按材料编号和房间范围区分，扣柱/墙体占用。
2. 踢脚线/线条：沿墙净长度计算，扣门洞，排除无踢脚线墙段，材料编号或节点做法必须可追溯。
3. 墙面饰面：按净周长 × 墙高计算，扣门窗洞口，按乳胶漆/墙纸/硬包/石材/墙砖等材料分开。
4. 吊顶/天棚：按吊顶平面图闭合区域计算水平投影面积，灯槽、跌级、异形吊顶需结合节点/大样另算展开面积。
5. 防水：地面防水按面积，墙面防水按净周长 × 高度，门洞、翻边、上返高度按标准规则和项目说明处理。
6. 拆除类：按原构件面积、长度或数量计算，优先复用原平面、门表、材料表和拆除范围说明。
7. 门窗/洁具/灯具/开关：按门表、设备表、图例和实际平面块引用计数，区分“图例符号”和“实际布置”。
8. 家具/固定装置/特殊做法：按立面图、大样图、节点图提取背景墙、定制柜、隔断等数量、面积或长度。
9. 措施类：保护、运输、保洁等先进入补充清单规则，避免误套装饰实体算量。

验收标准：

- 每个规则模板必须绑定标准库工程量规则文本。
- 标准库规则不支持或证据不足时，输出“待算量/待补证据”，不伪造工程量。
- 当前样例优先把地面、踢脚线/线条、墙面、吊顶、计数类各打通一批。

### R5. 四字段输出与前端试运行

目标：业务员前端只看最终四字段，后台保留诊断。

具体工作：

1. 前端 `/admin/dwg-trial` 继续只展示：
   - 项目名称。
   - 项目特征。
   - 单位。
   - 工程量。
2. 后台保留但不默认展示：
   - 图纸线索。
   - 标准匹配。
   - CAD 绑定。
   - 算量 trace。
   - 人工答案对齐报告。
3. 输出 Excel 分两类：
   - 业务试运行版：只含四字段。
   - 管理员诊断版：含规则来源、CAD 证据、误差、阻断原因。

验收标准：

- 前端上传本样例 DWG 后，业务主表只出现四字段。
- 工程量有证据则填数值，无证据则显示“待算量”，并且后台能说明为什么。
- 可下载四字段 Excel，与人工答案清单做对比。

### R6. 样例回归与验收指标

目标：建立可重复验收标准，而不是每次靠主观判断。

当前样例验收指标：

| 指标 | 第一目标 | 试运行目标 |
| --- | ---: | ---: |
| 人工项目覆盖率 | >= 70% | >= 90% |
| 系统误识别率 | <= 15% | <= 8% |
| 可自动算量项目占比 | >= 30% | >= 60% |
| 面积/长度类工程量误差 | <= 10% | <= 5% |
| 数量类工程量误差 | 0 | 0 |
| 四字段 Excel 可导出 | 是 | 是 |

验收方式：

1. 每次规则增强后重跑本样例。
2. 生成系统四字段 Excel。
3. 与人工清单自动对齐。
4. 输出漏项、误识别、单位差异、工程量误差、阻断原因。
5. 只把通过回归的规则沉淀到正式识图链路。

## 四、业务确认最小化原则

本专项不要求业务员大量逐行填表。业务员只需要在以下少数问题上确认：

1. 人工清单中哪些项目属于 GB/T 50854-2024 范围，哪些属于补充清单或其它专业。
2. 单位冲突项目的口径，例如窗帘盒、窗台板、金属线条、门套按长度、面积还是数量。
3. 材料编号含义，例如 `CT`、`ST`、`MT`、`MR`、`PM` 在本项目中的对应材料。
4. 防水高度、墙高、门洞扣减、灯槽/异形吊顶是否另算等关键规则。
5. 对系统反推的高置信绑定样本做抽查确认，而不是逐行从零录入。

## 五、立即执行顺序

下一步不继续泛泛优化 CAD 几何，而是按下面顺序执行：

1. **R1-1 项目词库沉淀**：从人工 127 行清单生成识别词库和分类规则。
