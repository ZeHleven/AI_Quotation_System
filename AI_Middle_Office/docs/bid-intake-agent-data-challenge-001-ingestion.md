# 报价资料研判 Agent：DATA-CHALLENGE-001 接入与通用解析优化

日期：2026-07-29
项目：余干蓝城·明月江南二期公区精装修工程
阶段定位：新项目 Challenge 数据准备与唯一一次泛化盲测，不参与既有 Development/Holdout 参数回调。

## 为什么做这次优化

经理提供的真实招标资料包含 1 份招标文件、1 份施工合同和 1 份约 43.5 MB 的复杂工程量清单。清单内部有 25 个 Sheet，部分 Sheet 的 OOXML 声明区域被放大到接近整张工作表。如果继续直接依赖工作表声明维度遍历，解析时间和内存会被无效空单元格放大，真实资料可能无法稳定进入 Agent 的证据链。

本轮目标不是为“蓝城”编写项目专属规则，而是建立一套对其他复杂招标 Excel 同样有效的安全解析边界。

## 唯一主要变量

将 XLSX 读取从“按工作表声明维度遍历”改成“流式读取 OOXML 中实际存在的单元格，并按有效内容计算实际区域”，同时增加通用资源上限和异常 Sheet 隔离。

## 通用实现

- 不再用 `iter_rows()`追随异常的 `max_row/max_column`。
- 从 XLSX 压缩包流式读取共享字符串、工作表关系和真实单元格。
- 仅根据有意义的单元格计算有效行列范围。
- 设置压缩包条目、解压体积、Sheet 数、有效行、有效列和文本总量上限。
- 记录“声明区域膨胀、截列、截行、文本达到上限”等解析诊断。
- 完全重复的 Sheet 只保留一份有效证据，重复副本进入隔离清单。
- 文件名项目期次与 Sheet 身份标识明显冲突时隔离异常 Sheet；规则基于通用的一期/二期/三期等期次标识，不绑定项目名。
- Excel 解析完成后把诊断摘要写入解析事件，便于前端和审计追踪。

## 接入过程中发现并修复的问题

### 1. 施工合同被误识别为图纸

原自动分类器缺少 `contract` 类型，施工合同中的“图纸”等高频词导致其被归为图纸。现已增加合同文件名和正文结构信号，并把 `contract` 纳入后端接口和前端类型显示。

### 2. 自动分类后的源文件无法用新分类规则重跑

原管线会把已自动分类的类型当成人工指定类型，解析器升级后无法重新分类同一源文件。现仅对明确的人工类型冲突继续阻断；自动重跑会把源文件类型恢复为 `auto`，再执行当前分类器，同时复用原始对象，避免重复上传。

### 3. Gold 标注不能依赖生产检索候选池

新增只读标注辅助脚本，遍历项目全部有效证据块并从 MinIO 读取正文，用于人工查找 Gold 证据。它明确绕过生产候选深度，不能被 Agent 运行时调用，从而避免“用当前检索器给自己标答案”的评测污染。

## 本轮思维判断

这次优化首先解决的是“证据能否安全、完整、可审计地进入检索系统”，不是排序参数问题。如果输入层因为异常声明维度而超时、误分类或混入冲突 Sheet，后续 Hit@5、Recall@5、MRR 和 nDCG@5 都失去意义。

这条路线具有通用性，因为限制和隔离依据是 OOXML 结构、资源预算、重复内容和期次身份冲突，而不是“蓝城”“明月江南”等项目关键词。

## 下一步优化方向及原因

1. 本 Challenge 永久锁定，不重跑、不改 Gold、不用于参数选择。
2. 从全新项目建立新的 Development 集，重点增加无结果、长表结构、四事实以上和跨文档覆盖问题。
3. 第一优先级用新的正负样本验证证据充分性/拒答门，不能直接根据本 Challenge 的一个负样本确定阈值。
4. 第二优先级验证 Sheet 标题、楼栋、分区和表头等通用结构元数据召回。
5. 第三优先级验证固定 Top 5 下的多事实覆盖和跨文档多样性。
6. 所有实验不得加入“蓝城”“明月江南”或本项目楼栋编号等专属规则。
