# 核心前端体验验收说明

更新时间：2026-06-03

## 1. 验收目的

本验收用于判断系统是否已经具备“小范围试运行当天可操作”的前端体验。

验收重点是入口、路径、提示、空状态、加载状态、错误反馈和角色可见范围，不评判真实业务规则是否最终合理。

## 2. 验收原则

- 业务员能少学习、少跳转、少猜测。
- 管理层先看关键结果，不被复杂表格淹没。
- 成本敏感信息只给应看角色。
- 失败、空数据、加载中要能看懂。
- 发现业务规则不确定时先登记，不现场写死。

## 3. 核心路径

| 编号 | 路径 | 角色 | 通过标准 |
|---|---|---|---|
| FE-PATH-01 | 登录到首页 | 全部角色 | 登录成功后入口清楚，错误提示可理解 |
| FE-PATH-02 | 需求单上传到行确认 | 业务员 | 能看懂 Sheet、列映射、阻断行、确认状态 |
| FE-PATH-03 | 确认清单发起报价 | 业务员 | 只允许通过校验的行进入报价，失败原因清楚 |
| FE-PATH-04 | 报价任务到预审弹窗 | 业务员 | 任务进度、失败恢复、预审入口清楚 |
| FE-PATH-05 | 预审人工确认 | 业务员 | 总价、成本依据、风险、人工改价、草稿、下发按钮清楚 |
| FE-PATH-06 | 成本库 draft 审核 | 成本人员 | 状态、筛选、批量操作、详情、流向清楚 |
| FE-PATH-07 | 项目进度巡检 | 项目经理 | 风险项目、缺证据、硬门禁提示清楚 |
| FE-PATH-08 | 经营总览巡检 | 管理层 | 先看关键结果、趋势、风险和系统健康 |

## 4. 角色可见性检查

| 角色 | 应看 | 不应看 |
|---|---|---|
| 业务员 | 报价工作台、需求单标准化、自己的报价历史 | 成本库敏感维护、权限管理 |
| 成本人员 | 成本库维护、相关审计与状态流向 | 系统权限管理 |
| 项目经理 | 项目列表、项目详情、任务证据 | 成本库敏感导出，除非另授 |
| 管理层只读 | 经营总览、必要汇总 | 成本明细维护、账号维护 |
| 系统管理员 | 权限、健康、关键后台页面 | 不代表可代替业务员做业务确认 |

## 5. 桌面与窄屏检查

建议检查宽度：

```text
390px / 768px / 1366px
```

重点看：

- 顶部按钮是否遮挡标题。
- 表格是否能横向滚动。
- 弹窗底部按钮是否可见。
- 错误提示是否被遮住。
- 指标卡文字是否溢出。
- 加载状态是否让用户误以为卡死。

## 6. 通过与暂缓标准

通过：

- P0 前端阻断问题为 0。
- P1 问题有临时处理办法。
- 核心路径至少能完成一次演示或彩排。
- 所有不确定业务规则已登记为待确认项。

暂缓：

- 登录后无法看到应有入口。
- 业务员无法进入报价预审。
- 预审弹窗无法保存、打回或确认。
- 管理层经营总览打不开。
- 普通角色能看到明显不该看的成本敏感入口。
