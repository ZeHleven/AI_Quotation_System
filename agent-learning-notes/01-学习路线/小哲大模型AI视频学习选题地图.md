# 小哲大模型 AI 视频学习选题地图

## 目标

这份地图不是按发布时间机械刷视频，而是围绕两个目标选题：

1. 能独立设计、开发、上线和运维生产级 Agent；
2. 把 AI 智能报价中台整理成可用于大厂 AI Agent 工程师、AI 工程师和 FDE 面试的项目证据。

每次只选择一组相互关联的视频，先查重，再合并成可复习、可检索的知识手册。

## 盘点范围与边界

- 主页公开作品数：101。
- 本次从公开主页读取最近 42 条作品标题与简介。
- 此前已接收该博主的 22 条 RAG、Memory 和 Agent 视频。
- 两部分有 10 条重复，合并后得到 54 条唯一视频样本。
- 还有 47 条历史作品未进入本次标题级盘点。

因此，下面的主题结构和优先级足以指导当前选题，但不是 101 条作品的逐条完整目录。未选择的视频只依据标题和简介初筛；正式写笔记时仍需分析视频内容，核对事实，并结合项目代码判断其适用范围。

## 优先级规则

| 级别 | 含义 |
|---|---|
| P0 | 当前求职和项目都需要，优先分析并形成项目证据 |
| P1 | 重要工程能力，完成 P0 后继续 |

主题的职业重要度与当前是否需要再写笔记是两回事。例如 RAG 本身属于 P0，但现有 13 条视频已经被合并成多篇笔记，所以短期行动是复习和项目验证，而不是继续重复写概念。

## 为什么前三类排在最前

当前项目已经不是“只会调用 API”的 Demo：

- FastAPI、Celery、n8n、Dify、RAG、Milvus 和数据库共同参与长任务；
- 报价任务与资料研判 Agent 已涉及重试、租约、Checkpoint、Human-in-the-loop 和事件追踪；
- MCP、JWT、RBAC、成本数据和报价下发都存在真实权限边界；
- Prompt 回归、RAG 评测、报价证据和运行图谱已有基础。

现在最值得补的，不是再学一遍“什么是 RAG”，而是把可靠性、安全和评测讲深，并把项目中的真实故障、修复和指标整理成面试故事。

## 从“看视频”转成“求职证据”

每个选题最终都要回答四个问题：

1. 原理：它解决什么生产问题？
2. 设计：有哪些关键状态、接口、指标和失败模式？
3. 项目：报价中台哪里已经实现，哪里仍有缺口？
4. 面试：怎样用一次真实问题、一次修复和一组验证结果讲清楚？

推荐采用以下输出模板：

```text
概念与边界
→ 生产失败模式
→ 设计模式与取舍
→ 报价中台现状
→ 可执行改进
```
