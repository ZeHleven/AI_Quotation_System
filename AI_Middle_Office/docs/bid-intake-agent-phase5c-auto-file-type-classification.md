# 报价资料研判 Agent Phase 5c：招标资料类型自动识别

## 本阶段结论

用户上传资料时不再需要提前选择文件类型。系统在证据解析管线中读取文件名
与已抽取内容，自动判断：

- 招标文件 `tender_document`
- 答疑/澄清文件 `clarification`
- 补遗/变更文件 `addendum`
- 项目图纸 `drawing`
- 工程量清单 `bill_of_quantities`
- 其他资料 `other`

无法可靠归类的资料进入 `other`，仍可进入证据清单，不会为了“强行分类”
阻断项目。

## 处理位置

自动识别位于资料解析与证据入库之间：

```text
上传原件
  -> 异步文本抽取
  -> 文件名 + 解析内容分类
  -> 将识别类型写入 parsed BidProjectFile
  -> 将识别类型写入 BidEvidenceDocument
  -> 生成 active manifest
  -> Agent readiness 自动刷新
```

该能力属于 Agent 的确定性前置认知层，不占用 ReAct Tool 预算，也不需要用户
先向 Agent 提供答案。

## 识别原则

- 文件名信号权重大于正文中的零散词；
- 答疑、补遗优先于正文中通用的“招标文件”字样；
- Excel 同时出现项目编码、项目名称、工程量、综合单价、合价等字段时优先识别
  为工程量清单；
- 通用 PDF 可根据投标人须知、评标办法、图纸目录、图号、比例等结构信号识别；
- 分类结果写入解析任务事件，保留识别类型和置信度审计；
- 显式类型参数仍保留为 API 兼容能力，但前端统一使用 `auto`。

## 前端变化

- 删除“本批资料类型”下拉框；
- 固定展示“系统自动识别”；
- 任务排队时显示“等待自动识别”；
- 解析完成后任务列表展示识别出的中文资料类型；
- 其他上传、进度、失败重试和证据门逻辑不变。

## 数据与业务边界

- 不新增 Alembic；
- 不修改原件、证据 block、manifest 的不可变语义；
- 不改变总经办立项标准、ReAct 研判、报价或成本库规则；
- 旧的显式分类资料保持原类型；
- 自动分类只在来源类型为 `auto` 时执行。

## 自动化验证

- 自动分类覆盖招标文件、答疑/澄清、补遗/变更、图纸、工程量清单和
  `other` 兜底；
- 端到端管线验证识别结果进入 source、parsed file、evidence document
  和任务事件；
- Agent 前端契约、证据解析、证据存储、Runtime 与 SPA 路由联合回归：
  `32 passed`；
- Python compileall、Vite production build 和 `git diff --check` 通过。

## 验收

1. 刷新“报价资料研判 Agent”。
2. 确认页面不再出现“本批资料类型”下拉框。
3. 上传命名清楚的招标文件、答疑、补遗、图纸或清单。
4. 任务排队时确认显示“等待自动识别”。
5. 任务完成后确认列表展示正确识别类型。
6. 确认证据清单版本和可用资料数量自动更新。
