# BIZ-2w-6 报价来源口径与预审列名调整

> 日期：2026-05-29  
> 状态：已通过当前环境手工验收（2026-05-29）  
> 阶段性质：展示口径修正，不改变报价规则和价格计算

## 背景

BIZ-2w-5 修复同名不同规格自由文本拆行后，预审单可以更稳定地把规格和工程量传给成本库前置上下文。但业务验收中进一步确认了一个产品口径问题：

- 命中 `cost_items.active` 成本库时，成本库应是定价主依据；
- AI 不应被理解为独立重新定价器；
- 无成本库命中时，AI 估价才作为临时参考，且仍必须人工确认；
- 旧预审列名“AI 建议单价(元)”容易让业务员误以为 AI 在替代成本库定价。

因此本阶段只调整旧预审弹窗的可见文案，让系统表达更符合当前业务原则。

## 阶段目标

- 将预审弹窗从“AI 建议价”口径调整为“预审参考价 / 成本库依据 / 人工确认价”口径；
- 成本库命中时，突出成本库是依据；
- 无成本库命中时，保留“AI 估价，仅供人工确认”的提示；
- 最终下发仍以人工确认价和人工确认合计为准。

## 不做事项

- 不改报价规则；
- 不改价格口径；
- 不自动改总价；
- 不自动新增报价行；
- 不改无底价自动处理原则；
- 不自动沉淀 active 成本库；
- 不改 N8N / Dify 工作流；
- 不改 RAG 同步逻辑；
- 不新增数据库结构，不新增 Alembic；
- 不迁移旧 `index.html` / `admin.html` / `app.html`；
- 不生成新 HTML 页面。

## 涉及文件

- `index.html`
  - 预审弹窗标题改为“报价明细预审 (成本库优先，人工确认)”；
  - “AI 建议单价(元)”改为“预审参考单价(元)”；
  - “成本库参考”改为“成本库依据”；
  - “人工改价(元)”改为“人工确认价(元)”；
  - “系统合计(元)”改为“人工确认合计(元)”；
  - 按行展示预审单价来源标签，例如“成本库依据价”“无成本库参考，AI估价”“偏离成本库依据”；
  - “采用AI建议”按钮改为按来源显示“采用参考价 / 采用AI估价 / 采用预审价”；
  - 查看依据弹窗中“AI 报价来源 / AI 报价依据”改为“预审单价来源 / 预审生成依据”。

## 验证方式

代码层验证：

```powershell
node <inline-script-syntax-check>
```

建议手工验收：

1. 成本库命中样例  
   打开预审后应看到“预审参考单价”“成本库依据”“人工确认价”“人工确认合计”等口径，不再把命中成本库的主价格称为 AI 建议价。

2. 无成本库样例  
   无成本库行仍应显示“无成本库参考价，AI 估价，仅供参考，请人工确认价格依据”。

3. 人工确认  
   修改人工确认价或点击采用按钮后，人工确认价和人工确认合计仍按原规则联动，确认下发边界不变。

4. 查看依据  
   查看依据弹窗应显示“预审单价来源”和“预审生成依据”，并保留成本库依据、工作流返回单价、系统合计和备注等审计信息。

## 回滚方式

本阶段只修改 `index.html` 文案和少量来源标签函数。如手工验收认为文案不合适，可直接回滚 `index.html` 本阶段改动及本说明文档，不涉及数据库或后端状态回滚。
