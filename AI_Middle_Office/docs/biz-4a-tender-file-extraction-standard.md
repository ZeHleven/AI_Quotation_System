# BIZ-4a 招标文件分析提取标准

版本：v1.0
参考样板：`output/documents/东莞香港中心项目装修专业分包工程_投标重要信息提取.docx`

## 目标

招标文件分析的目标不是把原文分段展示，也不是遇到关键词就摘第一句，而是为投标负责人、预算员、技术负责人和法务生成可复核的回标工作资料。

系统输出必须回答四个问题：

1. 这个项目怎么投：基础信息、时间、联系人、递交、标书制作和封标要求。
2. 这个项目怎么报：承包方式、报价口径、工程量规则、保证金、付款和工期。
3. 这个项目怎么评：评标原则、评分细则、废标条件和中标确定方式。
4. 这个项目哪里要复核：空白项、冲突项、风险条款、影响报价或影响废标的未决事项。

## 成果结构

首版成果仍保持四类业务输出：

1. `结构化信息摘要表`
2. `评分细则表`
3. `风险条款清单`
4. `待复核项 / 回标前优先澄清清单`

内部业务对象、原始段落、规则命中结果只作为证据层，不默认展示给业务经理。

## 结构化信息摘要表

摘要表按业务分组提取。每个信息项必须有：`重点内容`、`来源文件`、`页码/章节`、`状态`。如果文件未填写或前后冲突，不得留空装作已完成，应明确写“未填写 / 需澄清 / 存在冲突”。

| 信息项 | 必提内容 | 有效来源优先级 | 缺失/冲突处理 |
| --- | --- | --- | --- |
| 项目概况 | 招标工程名称、工程地点、招标单位、总承包单位、工程规模及特征、招标范围 | 招标公告、前附表、工程概况、招标范围 | 多区域/多楼栋要分别写清；不能只取封面标题 |
| 答疑时间 | 答疑截至时间、澄清回复时间、答疑联系人、邮箱/联系方式 | 前附表、投标须知、答疑/澄清条款 | 日期、邮箱、联系人空白时标记需澄清 |
| 报价方式 | 合同形式、工程承包方式、综合单价包含范围、工程量规则、包干项目、漏填报价风险 | 工程承包方式、报价须知、工程量清单说明、合同计价条款 | 优先提取“工程承包方式”原文，不用泛化推断 |
| 保证金 | 投标担保金额、缴交时间、形式、账户、保函有效期、未提交后果、没收情形、履约担保 | 投标保证金、投标保函、担保条款 | 金额/时间/形式至少缺一项时进入待复核 |
| 联系人 | 招投标联系人、答疑联系人、踏勘/现场预约联系人、递交联系人及电话/邮箱 | 邀请函、前附表、答疑条款、踏勘条款、递交条款 | 只写“联系人”但角色不明时，不能替代答疑或踏勘联系人 |
| 踏勘时间地点 | 是否统一踏勘、踏勘时间要求、地点、预约联系人、现场进入要求 | 现场踏勘、投标须知、前附表 | 未列明联系人或进入要求时标记需澄清 |
| 标书制作要求 | 投标人资质、商务标/技术标/电子标份数、商务标内容、技术标内容、格式、装订、签署盖章、报价填报要求 | 投标文件组成、投标书编制、投标文件要求、投标文件格式 | 不能只写“按招标文件要求”；商务标和技术标内容要分开 |
| 封标要求 | 商务标、技术标、电子标内外密封袋拆分方式，封套标识，工程名称/投标人名称，封口封条和骑缝盖章 | 投标文件的密封和标记、递交要求 | 缺封套数量、标识、盖章要求任一项时进入待复核 |
| 截标时间 | 具体截标/递交截止日期时间、递交地点、递交联系人 | 前附表、投标须知、递交条款、邀请函 | 日期时间空白必须写空白，不得猜测 |
| 评标标准 | 评标原则/办法、确定中标人口径、投标人数不足处理、废标/无效标条件 | 评标办法、评分标准、废标条件、确定中标人 | 没有分值时不要编造评分项；废标条件要完整归纳 |
| 工期 | 暂定开工时间、实际开工依据、合同工期、是否含周末节假日、分区/分楼栋工期 | 工期要求、合同工期、合同主要条款、投标书格式 | 投标格式与合同工期不一致时标记冲突 |
| 付款方式 | 预付款、履约保函对付款的影响、进度款申报、进度款支付比例/时限/最低额、累计支付上限、结算款、质保金、开办费 | 合同价款支付、付款条款、合同主要条款 | 只提取“按合同支付”不合格，必须提取比例和条件 |
| 回标前优先澄清清单 | 截标时间空白、答疑邮箱/联系人空白、踏勘联系人缺失、工期冲突、下浮率空白、清单/电子文件是否另行提供等 | 全文冲突、空白项、前附表、投标书格式、补遗提示 | 作为待复核/答疑输入，不标记为普通已确认 |

## 评分细则表

评分细则表只提取招标文件真实出现的评标信息。

合格标准：

- 能拆分的，拆成评分项、满分值、评分标准说明、所属标书、建议负责人。
- 不能拆分的，保留为父项或待复核项，不凭空生成技术分、商务分、报价分。
- “综合评标法”只能作为评标原则，不能替代评分细则。
- “废标条件”“确定中标人”“投标人数不足处理”属于评标标准有效信息，即使没有分值也要进入摘要表。

## 风险条款清单

风险条款只展示会影响报价、履约、废标或合同责任的条款。

合格标准：

- 同类风险合并为一条汇总风险，细分条款可展开查看。
- 必须保留条款原文摘要、所在章节、风险等级、风险说明、建议应对方式。
- 风险等级按影响后果定义，不按关键词强弱定义。
- 高风险优先包括：付款不利、工期违约、漏项责任、固定总价/包干、甲方免责、保证金/履约担保、废标条件、材料品牌/样板、封标递交错误。

## 待复核项

待复核项不是系统失败列表，而是回标工作清单。

进入待复核的情况：

- 招标文件本身空白或未填写。
- 招标文件前后不一致。
- 影响报价、工期、封标、废标、付款、保证金、材料样板或投标文件组成。
- LLM 置信度低或证据不足。
- 风险条款等级为高，或建议动作包含法务/预算/技术复核。

待复核项标题必须是中文业务标题，不能展示内部枚举名。

## LLM 抽取原则

结构化摘要使用 DeepSeek 语义识别优先，规则仅做候选证据召回和兜底。

LLM 必须遵守：

- 只能从当前招标文件候选片段中选择证据。
- 不因为关键词命中就直接摘取，要判断是否是该字段的真正有效信息。
- 不补全文件中没有写的日期、金额、联系人和比例。
- 对空白、未填写、冲突和需补遗的信息，要显式输出。
- 长条款压缩成业务要点，不整段复制原文。
- 每个结果必须带来源证据，便于人工复核。

## 验收标准

拿给业务经理验收前，至少满足：

- `结构化信息摘要表`覆盖上述 13 个信息项，关键项缺失时有明确缺失/需澄清提示。
- `评分细则表`不只有泛化评标原则，能提取真实评分项；没有分值时不编造。
- `风险条款清单`同类风险已合并，细分项可展开。
- `待复核项`聚焦空白、冲突和高影响事项，不展示英文内部枚举。
- Excel 成果包只展示业务重点信息，保留来源入口，不铺开系统调试字段。
