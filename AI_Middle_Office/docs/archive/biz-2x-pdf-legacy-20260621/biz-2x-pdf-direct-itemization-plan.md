# BIZ-2x PDF 直接列项路线规划

## 目标

先实现一条不依赖 DWG/DXF 证据融合的业务路线：

`正式 PDF -> LLM 看图列项 -> GB/T 标准库映射 -> 四字段清单`

这条路线优先解决“业务员能否得到像人工看图一样的项目清单候选”。工程量不追求自动精准计算，默认输出 `待算量`，后续再由 DXF、人工复核或专项算量补充。

## 业务边界

1. PDF 是主输入，不要求同步上传 DWG/DXF。
2. LLM 负责从图纸页面/分块中识别项目候选、空间、材料编号、做法描述和证据文本。
3. 标准库负责约束项目名称、项目特征字段口径和单位，不允许 LLM 自造 GB/T 编码或单位。
4. 四字段输出为 `项目名称、项目特征、单位、工程量`。
5. 工程量默认 `待算量`；视觉模型不得估算面积、长度或数量。
6. DXF/PDF 证据融合降为后置增强，不阻塞 PDF 直接列项。

## 实施阶段

### PDF-Direct-1 上传与渲染

- 新增 PDF-only 上传接口。
- 保存业务员上传的正式 PDF。
- 复用现有 PDF 基础解析、高清 PNG 渲染和分块能力。
- 若 Poppler/pdftoppm 不可用，返回清晰问题：PDF 视觉列项未执行，不伪造结果。

### PDF-Direct-2 LLM 看图列项

- 新增专用视觉 Prompt：要求输出施工图项目候选，而不是证据碎片。
- 每个页面/关键分块返回结构化 JSON：
  - 项目名称候选
  - 空间/部位
  - 材料编号
  - 做法/规格
  - 证据文本
  - 置信度
  - 是否需人工复核
- 明确禁止估算工程量。

### PDF-Direct-3 标准库映射

- 对每个 LLM 项目候选调用标准库索引搜索。
- 优先路由 GB/T 50854 与 GB/T 50856。
- 选取得分最高的标准项目作为候选映射。
- 无可靠标准候选时保留 LLM 项目名，并标记需人工确认。

### PDF-Direct-4 四字段清单

- 生成业务可见 Excel/CSV：
  - 项目名称：优先使用标准库项目名称。
  - 项目特征：合并空间、材料编号、做法/规格、图纸证据。
  - 单位：优先使用标准库允许单位。
  - 工程量：统一 `待算量`。
- 输出目录继续按业务/调试分离：
  - `outputs/biz2x_trial/business/<timestamp>/`
  - `outputs/biz2x_trial/debug/<timestamp>/`

### PDF-Direct-5 前端验收入口

- 在现有识图页面支持只上传 PDF。
- 只上传 PDF 时调用 PDF 直接列项接口。
- 业务员默认只看到四字段清单和下载按钮。
- LLM 原始项目、标准映射、渲染/分块状态放入调试文件，不作为业务主界面内容。

## 验收口径

1. 只上传 PDF，不上传 DWG，也能返回四字段清单结构。
2. 前端可直接下载四字段 Excel。
3. 若 PNG 渲染不可用，系统明确显示失败原因，不展示空白“证据链成果”。
4. LLM 不生成工程量，工程量字段为 `待算量`。
5. 标准库映射结果可在调试输出中追溯。

结论：继续堆总览图 GLM 批次的收益很低。下一轮应改为更细粒度的 03 装饰图节点/材料表裁剪，或者人工从图纸可见标注填充 evidence 字段；不能把 `墙面装饰材料/地面装饰材料/天花板` 一类泛化词当作项目候选。

下一步升级顺序必须围绕阶段 2、3、6 推进：先处理 `12` 条 `missing_candidate` 中的基层/保护层、挡水条、黑色防潮无机涂料、隔断底座、玻璃造型柱和通用措施证据，再处理 `62` 条 `feature_review` 与 `8` 条 `weak_match_review` 的平级/造型/规格拆分。只有严格门禁达到 `127/127` 且 `missing_candidate=feature_review=unit_conflict=weak_match=0` 后，才允许进入阶段 7 工程量。
