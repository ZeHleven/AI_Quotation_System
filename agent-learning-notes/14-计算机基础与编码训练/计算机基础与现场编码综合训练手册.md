# 计算机基础与现场编码综合训练手册

## 1. 学习目标

AI 应用岗位不要求成为算法竞赛选手，但大厂社招会验证：

- 能否写出正确、可测试、复杂度合理的代码；
- 能否理解进程、线程、内存、网络和数据库行为；
- 能否在并发、超时和故障条件下保护业务正确性；
- 能否现场推导，而不是只会背 Agent 名词。

最低目标：

```text
算法题能写对并解释复杂度
SQL 能写对并解释执行计划
Python 能写出生产可读代码
并发代码能处理竞态、取消和超时
系统故障能从 OS、网络和数据库继续向下定位
```

## 2. 数据结构与算法主线

| 主题 | 必须掌握 | AI 工程映射 |
|---|---|---|
| 数组与字符串 | 双指针、滑动窗口、前缀和 | 文本切片、窗口预算 |
| 哈希表 | 去重、计数、索引 | 幂等键、缓存、Chunk 去重 |
| 栈与队列 | 单调栈、BFS、生产消费 | 任务队列、Workflow |
| 堆 | Top-K、优先级队列 | 检索候选、任务调度 |
| 链表 | 指针操作、LRU | 缓存淘汰 |
| 树 | 遍历、递归、B+ 树概念 | JSON/AST、数据库索引 |
| 图 | BFS、DFS、拓扑排序、最短路 | Agent DAG、依赖调度 |
| 排序与二分 | 边界、稳定性、复杂度 | 版本查找、阈值选择 |
| 动态规划 | 状态、转移、空间优化 | 训练推导能力 |

复杂度回答必须包含：

- 输入规模是什么；
- 时间和空间复杂度；
- 最坏情况；
- 数据量增长后瓶颈在哪；
- 是否可以用索引、缓存、分治或并行换取性能。

### 必做编码题型

- LRU Cache；
- Top-K 高频元素；
- 合并区间；
- 滑动窗口限流；
- 带优先级和超时的任务队列；
- DAG 拓扑排序与环检测；
- Trie 或倒排索引；
- 最近请求去重；
- 指数退避与抖动；
- 并发安全的幂等记录。

## 3. 操作系统主线

### 进程、线程和协程

- 进程拥有独立地址空间，隔离强、切换成本高；
- 线程共享进程内存，需要同步；
- 协程由运行时调度，适合大量 I/O 等待；
- Python 异步任务不是操作系统线程。

必须能够解释：

- FastAPI 的异步接口为什么不能执行长时间 CPU 计算；
- Celery Worker 为什么可以使用多进程；
- 一个进程内的全局锁为什么不能保护多实例；
- 阻塞调用如何拖住事件循环。

### 内存与虚拟内存

需要理解：

- 栈、堆和对象生命周期；
- 虚拟地址、页、缺页和 Swap；
- 内存泄漏与内存峰值；
- Copy-on-write；
- 文件映射；
- 容器内存限制与 OOM。

实验：

1. 逐步扩大文档批处理大小；
2. 记录 RSS、对象数量和 GC；
3. 制造内存峰值；
4. 比较流式处理和一次性加载；
5. 给出限流、分批和背压方案。

### 文件、系统调用和 I/O

需要理解：

- 用户态和内核态；
- 文件描述符；
- 阻塞与非阻塞 I/O；
- Page Cache；
- fsync 与持久化；
- 临时文件、原子重命名和文件锁。

Agent 工程中的直接问题：

- 上传大文件为什么耗尽文件描述符；
- Checkpoint 写入成功是否等于已经落盘；
- 多 Worker 同时处理同一临时文件会发生什么。

## 4. 计算机网络主线

### 从域名到响应

```text
DNS
→ TCP 建连
→ TLS 握手
→ HTTP 请求
→ 负载均衡
→ 应用连接池
→ 下游服务
→ 流式或完整响应
```

必须掌握：

- TCP 三次握手、重传、拥塞控制和连接关闭；
- HTTP/1.1、HTTP/2 的基本差异；
- TLS 证书校验与握手；
- DNS 缓存和故障；
- Keep-Alive、连接池和端口耗尽；
- 反向代理、负载均衡和健康检查；
- SSE、WebSocket 和 gRPC Streaming 的边界。

### Timeout 不是一个数字

需要区分：

- 连接超时；
- 读取超时；
- 写入超时；
- 连接池等待超时；
- 上游总预算；
- 客户端取消。

可靠的预算应逐层递减：

```text
用户总预算
> 网关预算
> 应用预算
> 下游调用预算
> 单次重试预算
```

### 网络故障实验

- DNS 解析失败；
- TCP 连接拒绝；
- TLS 证书错误；
- 下游慢响应；
- 响应到一半断开；
- 429 与 Retry-After；
- 连接池耗尽；
- SSE 客户端取消。

每次记录：错误码、超时类型、重试次数、连接池状态、Trace 和用户体验。

## 5. Python 语言底层

### 对象与内存

需要掌握：

- 名称绑定而不是变量盒子；
- 可变对象与不可变对象；
- 浅拷贝与深拷贝；
- 引用计数和循环垃圾回收；
- `__eq__`、`__hash__` 与字典键；
- Dataclass、Pydantic Model 和普通对象的边界。

### 迭代器、生成器与流式处理

需要能够从空文件实现：

- 迭代器协议；
- 生成器；
- 分批读取；
- 惰性流水线；
- 带取消的异步生成器；
- SSE 事件流。

### 装饰器、上下文管理器与异常

训练题：

- 实现耗时和 trace_id 装饰器；
- 实现数据库事务上下文管理器；
- 定义可重试与不可重试异常；
- 保留异常链，避免只记录字符串；
- 实现资源清理和取消传播。

### GIL

准确表达：

- GIL 限制同一 CPython 进程内多个线程并行执行 Python 字节码；
- I/O 等待时线程仍有价值；
- CPU 密集任务可使用多进程、原生扩展或外部计算服务；
- GIL 不会自动消除业务竞态。

## 6. 并发编程

### 四类执行模型

| 模型 | 适合 | 主要风险 |
|---|---|---|
| 同步线程 | 阻塞 I/O、兼容旧库 | 竞态、线程池耗尽 |
| 多进程 | CPU 密集、隔离 | 序列化、进程成本 |
| AsyncIO | 大量 I/O 并发 | 阻塞事件循环、取消泄漏 |
| 分布式 Worker | 长任务、弹性 | 重复投递、状态一致性 |

### 必须掌握的并发原语

- Lock、RLock；
- Semaphore；
- Condition/Event；
- Queue；
- Future/Task；
- 原子数据库更新；
- 乐观锁；
- 分布式锁；
- Lease 与 Fencing Token。

### 并发编码题

1. 限制模型并发数的异步信号量；
2. 带超时和取消的任务组；
3. 多生产者、多消费者队列；
4. 只允许一个 Worker 领取任务的原子 SQL；
5. 防止缓存击穿的单飞机制；
6. 带租约续期和 Fencing Token 的任务执行器；
7. 幂等下发与重复结果复用；
8. 有界重试和指数退避。

每题必须增加竞态测试，而不是只跑一次 happy path。

## 7. 数据库深层原理

### B+ 树与索引

需要解释：

- 为什么 B+ 树适合磁盘和范围扫描；
- 联合索引最左前缀；
- 覆盖索引和回表；
- 聚簇与二级索引；
- 高选择性并不是唯一设计依据；
- 为什么函数、隐式转换和前导模糊可能导致索引失效。

### 事务与 MVCC

需要理解：

- 原子性、一致性、隔离性、持久性；
- Read View；
- Undo、Redo 和 WAL；
- Read Committed 与 Repeatable Read；
- 当前读与快照读；
- 间隙锁、Next-Key Lock；
- 幻读、写偏差和丢失更新。

### 死锁和并发更新

实验：

1. 两个事务以相反顺序更新两行；
2. 观察死锁检测；
3. 调整访问顺序；
4. 缩短事务；
5. 增加索引；
6. 实现可重试异常分类。

### 查询优化

不能只背“加索引”，而要按以下证据链：

```text
慢查询样本
→ Rows Examined
→ EXPLAIN ANALYZE
→ 访问路径
→ 排序、临时表和回表
→ 锁等待
→ 连接池
→ 修改一个变量
→ 对比延迟与写入成本
```

## 8. SQL 现场题

最低题型：

- 分组 Top-N；
- 窗口函数；
- 去重和保留最新版本；
- 游标分页；
- 任务原子领取；
- 乐观锁更新；
- 幂等唯一约束；
- Outbox 扫描；
- 按时间窗口聚合 P95 所需原始数据；
- 查找连续失败；
- 递归 CTE；
- 慢查询索引设计。

回答必须包含：

- SQL；
- 索引候选；
- 并发语义；
- 空值和重复数据；
- 用 EXPLAIN ANALYZE 验证的方法。

## 9. 现场编码标准

面试代码至少满足：

- 输入输出清晰；
- 边界条件明确；
- 命名可读；
- 错误不会被吞掉；
- 时间空间复杂度可解释；
- 有两个正常用例和两个异常用例；
- 并发题说明竞态；
- 数据库题说明事务和幂等。

推荐流程：

```text
复述问题
→ 澄清输入、规模和约束
→ 给朴素方案
→ 推导复杂度
→ 选择数据结构
→ 写代码
→ 手工走样例
→ 补边界和测试
```

## 10. 四十题训练配额

| 类别 | 数量 | 目标 |
|---|---:|---|
| 数组、字符串、哈希 | 10 | 正确率和速度 |
| 栈、队列、堆 | 6 | 调度和 Top-K |
| 树、图 | 8 | 遍历、依赖和环 |
| 并发与可靠性 | 8 | 正确性和故障 |
| Python 工程题 | 8 | 可读、可测、可取消 |

题目要在 1 天、3 天、7 天后重做。只有不看答案仍能完成，才从错题本移除。

## 11. 与报价中台结合但不被它限制

可用于练习的报价中台题目：

- 优先级报价任务队列；
- 169 行结果完整性校验；
- 成本条目 Top-K；
- 原子领取任务；
- 幂等确认下发；
- 大 Excel 流式解析；
- RAG 候选合并；
- 任务超时与取消传播。

每完成一个题，再替换业务名词重做一次：

- 报价任务换成客服工单；
- 成本条目换成合同条款；
- 图纸页换成代码文件；
- 人工预审换成高风险操作审批。

## 12. 验收标准

达到以下条件才算补齐计算机基础主线：

- [ ] 40 道编码题中至少 32 道可独立重做
- [ ] 20 道 SQL 中至少 16 道可解释执行计划
- [ ] 能解释进程、线程、协程和 GIL
- [ ] 能画出一次 HTTPS 请求完整路径
- [ ] 能定位连接池、事件循环和数据库锁等待
- [ ] 能实现取消、超时、幂等和有界重试
- [ ] 能制造并复盘至少 8 类基础设施故障
- [ ] 能在 45 分钟内完成一题中等系统编码

> Agent 框架会变化，但复杂度、并发、网络、事务和故障不会消失。
