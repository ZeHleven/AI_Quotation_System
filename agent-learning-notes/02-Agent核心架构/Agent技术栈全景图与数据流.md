# Agent 技术栈全景图与数据流

## 为什么要先理解全景

孤立地学习 LLM、RAG、Memory、MCP 等技术，很容易记住概念却不清楚它们如何协作。

更有效的理解方式是先建立一个完整模型：

```text
用户提出目标
    ↓
Agent 理解与规划
    ↓
调用工具获取信息或执行操作
    ↓
检查结果并继续决策
    ↓
向用户交付结果
```

Agent 并不是若干热门技术的简单拼接，而是一个围绕任务状态运行的闭环系统。

### 一项重要修正

LLM 是 Agent 的推理组件，但 `Agent Runtime` 才是运行时核心。它负责：

- 保存任务状态
- 拼装模型上下文
- 执行模型生成的工具调用
- 把工具结果返回模型
- 控制循环和终止条件
- 处理超时、重试、审批和异常

因此，不能简单地把“LLM”等同于“Agent”。

## 一次任务的完整数据流

一个简化的 Agent 生命周期如下：

```text
1. 用户提出目标
       │
       ▼
2. 接入层完成鉴权、限流和请求解析
       │
       ▼
3. Runtime 读取任务状态并拼装上下文
       │
       ▼
4. LLM 理解任务并决定下一步
       │
       ▼
5. Planner / Workflow 确定执行路径
       │
       ▼
6. 是否需要工具？
       │
       ├── 否 ──► 生成回答或结束任务
       │
       ▼
7. 生成并校验工具调用参数
       │
       ▼
8. 执行 MCP / API / SQL / Python 等工具
       │
       ▼
9. 保存工具结果与任务事件
       │
       ▼
10. 将结果返回 LLM，检查是否继续
       │
       ├── 继续 ──► 回到第 4～8 步
       │
       ▼
11. 生成最终结果并返回用户
```

真实 Agent 通常不是一次直线调用，而是一个有明确上限和终止条件的循环：

```text
思考 → 行动 → 观察 → 再思考
```

还可能在高风险动作前暂停，等待人工审批。

## RAG 数据流

当任务需要企业知识或外部资料时，可以使用 RAG：

```text
用户需求
   │
   ▼
查询理解 / 查询改写
   │
   ├──────────────┐
   ▼              ▼
Embedding       关键词检索
   │              │
   ▼              ▼
向量数据库        BM25
   │              │
   └──────┬───────┘
          ▼
      融合 / 重排
          │
          ▼
  相关片段与来源信息
          │
          ▼
         LLM
          │
          ▼
  有依据的回答或决策
```

Embedding 的作用是生成可用于语义检索的向量表示。它不只用于“查资料”，也可用于聚类、去重、推荐和语义记忆。

RAG 结果应尽量携带来源、版本和权限信息，以支持引用、审计和数据隔离。

## Tool Calling 数据流

例如用户要求生成 Excel：

```text
用户提出生成 Excel
        │
        ▼
LLM 选择 Excel 生成工具
        │
        ▼
Runtime 校验参数和权限
        │
        ▼
Python / openpyxl 执行
        │
        ▼
生成并校验 .xlsx 文件
        │
        ▼
LLM 或 Runtime 返回下载结果
```

这里需要区分：

- LLM 负责理解意图、选择工具和生成参数
- Python/openpyxl 等工具负责真正创建文件
- Runtime 负责连接模型和工具，并处理执行过程

## MCP 数据流

例如读取 GitHub 中的最新 PR：

```text
用户请求
   │
   ▼
LLM 选择工具
   │
   ▼
MCP Client
   │
   ▼
GitHub MCP Server
   │
   ▼
GitHub API / 数据
   │
   ▼
结构化工具结果
   │
   ▼
LLM 总结
   │
   ▼
用户
```

MCP 与 Tool Calling 的关系：

- Tool Calling 是模型表达“我要调用某个工具”的能力和机制
- MCP 是客户端与外部工具、资源进行标准化连接的协议
- MCP 是工具接入方式之一，并不是所有工具调用都必须经过 MCP

把 MCP 类比为“USB 接口”有助于入门，但生产实践还需理解能力发现、Schema、传输、鉴权和权限控制。

## Memory 数据流

例如用户询问“昨天的报价做到哪里了”：

```text
用户请求
   │
   ▼
识别用户和当前任务
   │
   ▼
查询 Memory / 任务状态库
   │
   ▼
返回昨日状态及依据
   │
   ▼
LLM 组织回答或继续执行
```

### Memory 与 RAG 的区别

| 维度 | Memory | RAG |
|---|---|---|
| 主要内容 | 用户、会话、任务状态和偏好 | 企业文档、规范、知识和资料 |
| 典型问题 | “我上次做到哪里？” | “公司的报价规范是什么？” |
| 数据更新 | 随交互和任务持续变化 | 通常经过采集、切片、索引 |
| 常见存储 | Redis、关系数据库、向量库 | 搜索引擎、向量库、文档库 |
| 权限重点 | 用户身份与会话隔离 | 文档权限与知识域隔离 |

边界并非绝对：长期语义记忆也可能采用向量检索，但它与企业知识库在数据来源、生命周期和权限模型上仍应分开设计。

## Workflow 数据流

以工程成本测算为例：

```text
上传图纸或清单
       │
       ▼
文件解析 / OCR / VLM
       │
       ▼
项目识别与标准化
       │
       ▼
查询成本库与 RAG
       │
       ▼
报价计算与完整性校验
       │
       ▼
人工预审
       │
       ▼
确认下发 / 生成 Excel
```

Workflow 与 Agent 的职责可以这样划分：

- Workflow：保证必须经过哪些阶段、状态如何迁移
- Agent：在允许的阶段内理解信息并作出有限决策
- 业务代码：执行确定性的计算、校验和权限规则
- 人工审核：处理高风险、不确定或不可逆操作

生产系统通常应把关键业务规则写进代码或工作流约束，而不是只依靠 Prompt。

## 横切能力：Evaluation 与 Observability

评测和可观测性不应放在流程末尾补做，而应贯穿所有组件。

```text
                     Agent Runtime
                          │
            ┌─────────────┴─────────────┐
            ▼                           ▼
       Evaluation                  Observability
          评测                         可观测性
            │                           │
   ┌────────┼────────┐        ┌─────────┼─────────┐
   ▼        ▼        ▼        ▼         ▼         ▼
准确率    完成率   工具成功率  Traces    Metrics    Logs
回归集    人工评分  成本延迟    调用链     指标       日志
```

### Evaluation 关注

- 任务是否完成
- 结果是否准确
- 工具是否选对、参数是否正确
- RAG 是否召回正确依据
- 改动模型或 Prompt 后是否退化
- 延迟和成本是否可接受

### Observability 关注

- 一次任务经过了哪些组件
- 每一步的输入、输出、延迟和状态
- 错误发生在哪里
- Token、模型、工具和基础设施成本
- 是否需要触发告警或人工接管

“开发占 30%、评测运维占 70%”可作为提醒，但不是固定行业统计。准确结论是：Agent 上线后，评测、调优和运维通常会成为持续且重要的工作。

## FDE 应掌握的最终知识树

```text
Agent
│
├── 接入层
│   ├── API Gateway
│   ├── 鉴权与权限
│   └── 限流与安全
│
├── Agent Runtime
│   ├── LLM
│   ├── Prompt / Context
│   ├── Planner
│   ├── Workflow
│   └── 状态与执行循环
│
├── Tool Calling
│   ├── MCP
│   ├── HTTP API
│   ├── Python
│   ├── SQL
│   └── Shell
│
├── Memory
│   ├── 会话记忆
│   ├── 长期偏好
│   └── 任务状态
│
├── RAG
│   ├── 文档解析与切片
│   ├── Embedding
│   ├── 向量数据库
│   ├── 关键词检索
│   └── 融合与重排
│
├── Evaluation
├── Observability
│
└── Deployment
    ├── Task Queue
    ├── Redis / Database
    ├── Docker / Kubernetes
    ├── CI/CD
    └── 监控、日志与告警
```
