# 从答案手册到能力训练体系：八周闭环训练计划

## 1. 这份手册应该怎样使用

这份手册可以提供知识框架、项目表达和参考答案，但不能替代训练。

最危险的学习错觉是：

> 看答案时觉得理解，关掉文档后却不能独立画架构、写代码、制造故障、定位指标和解释取舍。

每一节必须完成以下闭环：

```text
阅读一节
→ 关掉文档口述
→ 画出数据流和状态
→ 写最小代码
→ 主动制造故障
→ 用日志、指标和 Trace 定位
→ 写复盘并重新口述
```

没有训练产物，就不能把该知识点标记为“已掌握”。

## 2. 六级掌握标准

| 等级 | 能力表现 | 是否算掌握 |
|---|---|---|
| L0 看过 | 能认出名词 | 否 |
| L1 复述 | 不看资料说清定义与边界 | 部分 |
| L2 画图 | 画出组件、数据流、状态与失败路径 | 部分 |
| L3 编码 | 独立写出最小可运行实现和测试 | 是 |
| L4 排障 | 能制造故障并用证据定位 | 是 |
| L5 迁移 | 能迁移到陌生业务并解释取舍 | 深度掌握 |

面试复习的目标不是把所有内容停在 L1，而是：

- 核心主线达到 L4；
- 高频系统设计达到 L5；
- 辅助知识至少达到 L2。

## 3. 每节训练卡

每学完一节，填写一张训练卡。

```text
主题：
日期：

1. 30 秒口述：
2. 2 分钟方案：
3. 架构图或时序图：
4. 最小代码：
5. 自动化测试：
6. 注入的故障：
7. 观察的指标和日志：
8. 根因与修复：
9. 迁移到另一个业务时的变化：
10. 仍不确定的边界：
```

训练证据应保存到独立目录：

```text
training-evidence/
├── diagrams/
├── coding/
├── tests/
├── fault-labs/
├── metrics/
├── design-cases/
└── interview-records/
```

## 4. 一次训练的时间盒

推荐一个主题使用 90 至 120 分钟：

| 阶段 | 时间 | 输出 |
|---|---:|---|
| 阅读与提炼 | 15 分钟 | 五条结论 |
| 关文档口述 | 10 分钟 | 录音或文字 |
| 画图 | 15 分钟 | 数据流、状态机或时序图 |
| 编码与测试 | 30 至 45 分钟 | 可运行代码和测试 |
| 故障实验 | 15 至 25 分钟 | 故障证据和定位过程 |
| 复盘 | 10 分钟 | 错误分类与下一次动作 |

遇到不会的地方先记录假设，再查资料；不要边看答案边照抄代码。

## 5. 八周主训练计划

每周建议投入 10 至 15 小时。工作日做小训练，周末做综合实验。

### 第 1 周：Python、HTTP 与接口工程

目标：

- 掌握 Python 对象、迭代器、生成器、异常、上下文管理器；
- 掌握 FastAPI 请求生命周期、依赖注入、校验和错误处理；
- 掌握 HTTP、超时、连接池、SSE 和幂等键。

必须完成：

- 手写一个异步任务提交、查询、取消接口；
- 为输入 Schema、权限和状态转移编写测试；
- 制造下游超时、断连和非法 JSON；
- 记录 P50/P95、错误码和 Trace。

### 第 2 周：数据结构、算法、SQL 与事务

目标：

- 能分析时间与空间复杂度；
- 掌握哈希、队列、堆、树、图和常见搜索；
- 掌握 B+ 树、MVCC、事务隔离、锁和死锁；
- 能写中等难度 SQL 和解释执行计划。

必须完成：

- 10 道数据结构与算法题；
- 8 道 SQL 题；
- 手写优先级任务队列和 Top-K；
- 制造死锁、慢查询和索引失效；
- 使用 EXPLAIN ANALYZE 给出优化前后证据。

### 第 3 周：Redis、消息队列与分布式可靠性

目标：

- 掌握 Cache Aside、热点、穿透、击穿和雪崩；
- 掌握至少一次投递、幂等消费、Outbox 和死信；
- 掌握租约、Fencing Token、重试、熔断和降级。

必须完成：

- 实现带随机过期和互斥重建的缓存；
- 实现幂等消费记录；
- 制造重复消息、消息积压、缓存穿透和 Worker 崩溃；
- 观察队列年龄、重试次数、重复率和恢复时间。

### 第 4 周：RAG 数据与检索实验

目标：

- 掌握解析、切片、元数据、Embedding 和索引；
- 掌握 Dense、BM25、RRF、Rerank 和权限过滤；
- 掌握测试集、Recall@K、MRR、NDCG 和无答案处理。

必须完成：

- 准备 30 至 50 条小型 Gold 测试集；
- 分别运行 Dense、BM25、RRF、Rerank；
- 记录每一步的增益、延迟和成本；
- 制造扫描 PDF、错误页码、旧版本和越权文档问题。

### 第 5 周：Agent Runtime 与工具执行

目标：

- 掌握 State、Planner、Workflow、Tool Calling 和 MCP；
- 掌握 Checkpoint、恢复、终止条件和 Human-in-the-loop；
- 掌握工具 Schema、权限作用域、幂等与审计。

必须完成：

- 实现一个带三种工具的最小 Agent；
- 限制循环、Token、工具次数和总时长；
- 制造工具超时、重复调用、非法参数和中途崩溃；
- 验证从 Checkpoint 恢复且不重复产生业务副作用。

### 第 6 周：可观测、安全与发布治理

目标：

- 掌握 Logs、Metrics、Traces 和 SLO；
- 掌握 Prompt Injection、RBAC、脱敏和审计；
- 掌握测试集、版本冻结、回归门、灰度和回滚。

必须完成：

- 为一次 Agent Run 记录完整 Trace；
- 增加 Prompt 注入和越权工具测试；
- 建立错误分类和回归报告；
- 配置一个质量、延迟、成本、安全联合发布门。

### 第 7 周：跨场景迁移

目标：

- 不依赖报价业务也能完成系统设计；
- 能识别不同场景的状态、工具、RAG、人工门禁和评测差异。

必须完成：

- 分别设计企业知识助手、客服 Agent、合同审核系统；
- 从手机助理、代码 Agent、高并发 Agent 平台中再抽两题；
- 每题限时 35 分钟：5 分钟澄清、15 分钟架构、10 分钟故障与指标、5 分钟取舍。

### 第 8 周：综合项目与模拟面试

目标：

- 把知识、编码、排障和表达合并成可验证能力；
- 能在陌生追问下继续推导，而不是背标准答案。

必须完成：

- 一次 90 分钟综合编码；
- 一次 60 分钟系统设计；
- 两次技术模拟面试；
- 一次项目故障复盘；
- 整理最终证据包和薄弱项清单。

## 6. 每周固定节奏

| 时间 | 训练内容 |
|---|---|
| 周一 | 原理口述和架构图 |
| 周二 | 数据结构、算法或 SQL |
| 周三 | 系统编码 |
| 周四 | 故障注入与排障 |
| 周五 | 指标、测试和复盘 |
| 周六 | 综合系统设计或项目实验 |
| 周日 | 模拟面试、错题回归和下周计划 |

## 7. 现场编码训练量

八周最低训练量：

- 数据结构与算法：40 题；
- SQL：20 题；
- Python/FastAPI：12 个小实现；
- 并发与可靠性：8 个实验；
- RAG：4 组消融实验；
- Agent：4 个状态与工具实验；
- 故障实验：12 个；
- 系统设计：8 题；
- 模拟面试：4 次。

只记录通过数量没有意义，还要记录：

- 首次完成时间；
- 是否查看提示；
- 测试覆盖；
- 失败原因；
- 一周后能否独立重做。

## 8. 故障实验标准

每个故障实验必须包含：

```text
正常基线
→ 注入单一故障
→ 记录用户现象
→ 查看 RED/USE 指标
→ 沿 Trace 定位最早偏差
→ 提出临时止损
→ 完成根因修复
→ 增加回归测试和告警
```

可重复使用的故障清单：

- 数据库锁等待和死锁；
- Redis 热点失效；
- 消息重复、延迟和积压；
- 下游 429、超时和半成功；
- Agent 无限循环；
- Checkpoint 写入失败；
- RAG 无召回、错版本和越权召回；
- 模型非法 JSON；
- Prompt Injection；
- 日志缺少 trace_id；
- 灰度版本质量下降；
- 回滚后数据库不兼容。

## 9. 每周验收

每周结束只回答四个问题：

1. 我能否不看资料说清原理和取舍？
2. 我能否从空文件写出最小实现和测试？
3. 我能否主动制造故障并用证据定位？
4. 我能否迁移到另一个业务场景？

任意一项为否，就不能只靠继续阅读解决，必须增加对应训练。

## 10. 面试答案怎样从训练中产生

标准答案应当是训练结果的压缩，而不是训练起点。

```text
真实实现
→ 自动化测试
→ 故障和指标
→ 设计取舍
→ 项目复盘
→ 2 分钟回答
→ 30 秒速答
```

一段可信的面试回答至少包含：

- 场景与约束；
- 方案与关键机制；
- 一项真实故障或指标；
- 一个没有完成或需要权衡的边界。

## 11. 最终能力证据包

投递前至少准备：

- 8 张可独立讲解的架构图；
- 12 个可运行小项目或代码片段；
- 12 份故障实验记录；
- 4 份评测报告；
- 8 道系统设计题；
- 5 个 STAR 项目故事；
- 4 次模拟面试复盘；
- 一份明确标注“已实现、代码验证、当前环境验证、仅设计”的能力矩阵。

> 复习手册负责告诉你“应该知道什么”；训练证据负责证明“你确实能做什么”。
