# 业务员 15 分钟演示脚本

更新时间：2026-06-03

## 1. 演示目标

让业务员知道试运行时怎么完成一次从需求单到报价预审的操作，并知道遇到问题时如何登记。

本演示只关注操作路径，不要求业务员理解后端、RAG、Celery、N8N 等技术细节。

## 2. 演示前准备

| 准备项 | 说明 |
|---|---|
| 服务状态 | `/health/ready` 为 ready |
| 账号 | 使用业务员或演示业务员账号，不使用共享管理员账号 |
| 样例文件 | 优先使用 `outputs/requirement_standardization_test/甲方需求单标准化确认测试.xlsx` |
| 问题记录 | 打开 `reports/trial_readiness/20260603_stage4/frontend_demo_issue_log.csv` |
| 边界说明 | 说明样例数据不是客户真实项目，不用于经营结论 |

## 3. 演示路线

### 0:00 - 1:00 登录

页面：

```text
/login
```

展示点：

- 输入账号密码登录。
- 登录后看自己有权限的入口。
- 看不到入口时不要借管理员账号，联系管理员补角色。

### 1:00 - 4:00 需求单标准化

页面：

```text
/admin/requirement-standardization
```

操作：

1. 上传样例 Excel。
2. 查看 Sheet 列表。
3. 检查列映射。
4. 查看原始行和标准化字段。
5. 筛选阻断行、未确认行。
6. 确认可报价行。

讲清楚：

- 系统不会替业务员拍板，人工确认仍然必要。
- 说明行、汇总行、空白行不要进入报价。
- 阻断行需要补清信息，不建议绕过。

### 4:00 - 6:00 发起报价

操作：

1. 只选择已确认且通过校验的行。
2. 点击发起报价。
3. 跳转到旧报价工作台或进入任务进度。

讲清楚：

- 大清单会分批报价。
- 任务失败时先记录任务号和错误提示。
- 不要重复提交同一份样例造成混淆。

### 6:00 - 11:00 报价预审

页面：

```text
/index.html
```

展示点：

- 预审总价。
- AI 返回行。
- 成本库参考价。
- 无底价提示。
- 疑似漏项提示。
- 人工改价和工程量联动。
- 保存草稿。
- 打回重填。
- 确认下发。

讲清楚：

- 成本库 active 命中时只是参考，不代表不用人工复核。
- 无底价项目可以人工确认，但不会自动变成 active 成本。
- AI 未返回的占位行必须人工补价，否则系统会阻断下发。

### 11:00 - 13:00 我的历史与草稿恢复

展示点：

- 从历史任务恢复。
- 从预审草稿继续。
- 区分已下发、待预审、失败、草稿。

讲清楚：

- 关闭页面前建议保存草稿。
- 草稿恢复后要重新检查关键价格。

### 13:00 - 15:00 问题登记

登记模板：

```text
reports/trial_readiness/20260603_stage4/frontend_demo_issue_log.csv
```

让业务员记录：

- 页面路径。
- 操作步骤。
- 输入文件。
- 任务号。
- 截图或错误提示。
- 是否阻断继续操作。

## 4. 业务员演示通过标准

- 业务员能说出从哪里进入报价工作台。
- 业务员能理解需求单标准化需要人工确认。
- 业务员能在预审弹窗找到成本依据、无底价提示和人工改价位置。
- 业务员知道保存草稿、打回、确认下发的区别。
- 业务员知道出问题要登记，不现场口头带过。

## 5. 不在本演示内讨论

- 合同、采购、回款。
- 项目进度跨部门正式规则。
- 完整经营 ROI。
- AI 自动替代人工报价责任。
- 正式生产上线时间。
