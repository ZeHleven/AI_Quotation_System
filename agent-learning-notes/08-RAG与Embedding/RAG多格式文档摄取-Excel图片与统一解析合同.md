# RAG 多格式文档摄取：Excel、图片与统一解析合同

## 核心结论

Excel 和图片不能简单“转成一段文本再切片”。

- Excel 是带 Sheet、表头、单元格关系、公式和业务区域的半结构化数据；
- 图片是像素，需要 OCR、版面、区域和视觉语义共同恢复；
- 两者都必须保留原始位置、版本、权限、解析置信度和派生关系。

生产链路：

```text
文件接入
→ 类型识别与安全检查
→ 格式专用解析
→ 统一结构化块
→ 清洗与质量门禁
→ 按信息单元切片
→ 生成文本、结构化与视觉索引
→ 权限过滤与多路召回
→ 回到原始文件验证
```

统一的不是“所有文件都按一种方式解析”，而是：

> 不同解析器输出同一种可追溯、可校验、可版本化的中间合同。

---

## 1. 先做文件路由

```text
扩展名 + MIME + 文件签名
→ 文件完整性、大小、加密和恶意内容检查
→ Word / PDF / Excel / 图片
→ 格式专用解析器
→ 失败降级或人工处理
```

不能只信扩展名。名为 `.xlsx` 的文件可能损坏，图片可能伪装成其他类型。

| 类型 | 优先解析 | 降级方式 |
|---|---|---|
| DOCX | OOXML 结构 | 版面渲染、OCR |
| 原生 PDF | 文本 + 版面 | OCR / 多模态 |
| 扫描 PDF | OCR + Layout | 多模态 / 人工 |
| XLSX / XLSM | Workbook、Sheet、Cell 结构 | 渲染区域、人工映射 |
| PNG / JPG / TIFF | OCR、区域检测 | 多模态理解、人工 |
| 图表 / 流程图 | 图文关系解析 | 保留原图并生成受控摘要 |

旧 `.xls`、加密文件和宏文件需要单独安全策略。无法可靠解析时应明确失败，不能静默得到空知识。

---

## 2. Excel 为什么不是普通文本

一个 Workbook 可能同时包含：

- 清单明细；
- 编制说明；
- 计算规则；
- 汇总表；
- 品牌表；
- 隐藏 Sheet；
- 公式和跨 Sheet 引用；
- 合并表头；
- 图片、批注、超链接和图表。

如果直接逐单元格拼接：

- 表头与数值失去对应关系；
- 单位、币种和数量含义丢失；
- 汇总行被误当作明细；
- 公式值与公式来源无法区分；
- 相同项目在不同 Sheet 中重复；
- 原始行无法回查；
- 隐藏内容可能意外泄露。

因此 Excel 摄取首先是“识别表格语义”，其次才是切片和 Embedding。

## 3. Excel 解析的五个阶段

### 3.1 Workbook 安全与基本信息

记录：

- 原始文件哈希；
- 文件名和 MIME；
- Workbook 类型；
- 是否包含宏、外部链接和加密；
- Sheet 列表；
- 隐藏 Sheet、隐藏行和隐藏列；
- 解析器及版本。

宏和外部链接只作为数据检查，不应在解析环境中执行。

### 3.2 Sheet 角色识别

常见角色：

```text
bill              明细清单
instruction       编制说明
rule              计算规则
summary           汇总
reference         品牌、费率或参考表
unknown           无法可靠分类
```

可结合：

- Sheet 名称；
- 表头词；
- 数据类型分布；
- 公式密度；
- 空行和合并单元格；
- 人工映射。

低置信度 Sheet 不要自动进入正式知识。

### 3.3 表头与区域识别

真实 Excel 可能有：

- 多行表头；
- 合并单元格；
- 顶部项目说明；
- 中间重复表头；
- 同一 Sheet 多个表格；
- 尾部合计和签字区域。

解析器要识别每个逻辑表格的：

- 表头范围；
- 数据范围；
- 字段路径；
- 单位行；
- 汇总和说明行；
- 原始行列位置。

### 3.4 字段标准化

例如：

```text
项目名称 / 清单名称 / 工作内容 → item_name
规格 / 项目特征 / 技术要求     → specification
数量 / 工程量                  → quantity
计量单位 / 单位                → unit
综合单价 / 单价                → unit_price
合价 / 金额                    → total_price
```

必须同时保存：

- 原字段名；
- 标准字段名；
- 原始值；
- 清洗值；
- 转换规则；
- 置信度；
- 人工确认状态。

标准化不能覆盖原始数据。

### 3.5 公式和值

公式单元格至少区分：

```json
{
  "display_value": 1200.0,
  "formula": "=B12*C12",
  "value_source": "cached_formula",
  "calculated_at": "unknown"
}
```

注意：

- 解析库不一定会重新计算公式；
- 缓存值可能过期；
- 外部 Workbook 引用可能失效；
- 汇总金额不应仅由 LLM 推断。

高风险金额应通过确定性计算重新验证。

## 4. Excel 的统一行模型

```json
{
  "document_id": "requirement_001",
  "document_version": "v2",
  "sheet": "装饰部分清单",
  "sheet_role": "bill",
  "table_id": "table_03",
  "row_index": 27,
  "row_type": "data_row",
  "fields": {
    "item_name": "墙面砖铺贴",
    "specification": "600×1200",
    "quantity": 125.5,
    "unit": "m²"
  },
  "raw_cells": {
    "A27": "墙面砖铺贴",
    "B27": "600*1200",
    "C27": 125.5,
    "D27": "㎡"
  },
  "confidence": 0.96,
  "acl": ["project:p001"],
  "source_hash": "..."
}
```

`row_type` 应区分：

- `data_row`
- `instruction_row`
- `summary_row`
- `header_row`
- `reference_row`
- `blank_row`
- `blocked_row`

说明、汇总和明细不能全部进入同一个召回池。

## 5. Excel 怎样切片

### 5.1 明细表

通常以“逻辑行 + 表头上下文”为基本块：

```text
Sheet：装饰部分清单
字段：项目名称 / 规格 / 工程量 / 单位
第 27 行：墙面砖铺贴 / 600×1200 / 125.5 / m²
```

必要时将连续、同类别行组成小批次，但每行仍保留稳定 ID。

### 5.2 说明和规则

按标题、段落或规则项切片，并关联其适用 Sheet、工程或行范围。

### 5.3 汇总表

汇总信息应保留层级：

```text
项目 → 单体 → 专业 → 分部 → 汇总金额
```

不能与明细行混排后让模型自行猜层级。

### 5.4 表格关系

对于跨 Sheet 关系，保存显式引用：

- 明细行对应的费率表；
- 材料行对应的品牌表；
- 汇总项对应的明细范围；
- 公式依赖的源单元格。

若核心问题需要精确筛选、聚合或计算，应优先走 SQL、DataFrame 或受控 Tool，而不是纯向量检索。

## 6. 图片解析的四层信息

### 第一层：原始资产

保存：

- 原图；
- 文件哈希；
- 宽高、格式、色彩和方向；
- 来源文档、页码或上传任务；
- 权限和版本。

### 第二层：区域

将图片拆成可定位区域：

- 标题；
- 段落；
- 表格；
- 图例；
- 标注；
- 尺寸线；
- 流程节点；
- CAD 视图；
- 统计图区域。

每个区域保存 `bbox` 或 Polygon。

### 第三层：机器提取

- OCR 文本；
- 表格结构；
- 视觉实体；
- 数值与单位；
- 图文关系；
- VLM 生成的摘要；
- 模型和 Prompt 版本；
- 置信度。

### 第四层：验证与来源

- OCR 和视觉结果是否一致；
- 数值是否通过格式或业务规则；
- 是否需要人工复核；
- 结论能否打开到原图区域；
- 派生摘要是否已经过确认。

VLM 摘要是派生信息，不是原始事实。

## 7. OCR、Layout 与多模态模型怎样分工

| 能力 | 擅长 | 不擅长 |
|---|---|---|
| OCR | 印刷文字、规则表格、票据 | 复杂关系和含义判断 |
| Layout | 阅读顺序、区域、表格和段落 | 深层业务语义 |
| VLM | 图文关系、流程、复杂图表和不规则页面 | 精确数值稳定性和确定性计算 |
| 规则引擎 | 单位、格式、合计和完整性 | 模糊视觉理解 |
| 人工审核 | 高风险、低置信度和歧义 | 不适合无限扩大处理量 |

推荐组合：

```text
图像预处理
→ OCR + Layout
→ 低置信度或复杂区域交给 VLM
→ Schema 和业务规则校验
→ 必要时人工确认
```

不要让 VLM 重新识别所有清晰文字，也不要让 OCR 解释复杂工程关系。

## 8. 图片怎样进入检索

### 文本化通道

将以下信息组织成可检索文本：

- OCR；
- 图题和附近说明；
- 关键实体；
- 数值与单位；
- 图中关系；
- 经验证的视觉摘要。

可复用普通 Embedding、BM25、RRF 和 Reranker。

### 视觉通道

若业务需要“以图搜图”、构件相似或视觉布局检索，可以增加图像或多模态 Embedding。

但必须单独评测：

- 图像向量能否召回正确区域；
- 文本 Query 与图片是否处于兼容空间；
- 图片版本和权限是否同步；
- 视觉通道的增益是否值得成本。

不要因为系统“支持图片”就默认必须建设视觉向量库。

### 原图回看

最终证据应指向：

```text
image_id
+ document_id / page
+ bbox
+ version
+ content_hash
```

高风险结论必须能够打开原始区域，不能只显示模型生成的描述。

## 9. 统一解析合同

不同格式可以输出统一 Block：

```json
{
  "block_id": "doc001_v2_sheet3_row27",
  "document_id": "doc001",
  "document_version": "v2",
  "modality": "table",
  "block_type": "excel_row",
  "text": "墙面砖铺贴，规格600×1200，工程量125.5m²",
  "structured_data": {
    "item_name": "墙面砖铺贴",
    "quantity": 125.5,
    "unit": "m²"
  },
  "source_locator": {
    "sheet": "装饰部分清单",
    "row": 27,
    "cell_range": "A27:D27",
    "page": null,
    "bbox": null
  },
  "derivation": {
    "parser": "excel_standardizer_v3",
    "ocr_model": null,
    "vision_model": null,
    "confidence": 0.96
  },
  "acl": ["project:p001"],
  "effective_at": "2026-07-01",
  "content_hash": "..."
}
```

核心字段：

- 身份：`document_id`、`version`、`block_id`
- 内容：`text`、`structured_data`
- 类型：`modality`、`block_type`
- 定位：Sheet/Row/Cell 或 Page/BBox
- 派生：解析器、OCR、VLM 和版本
- 治理：ACL、状态、生效时间、哈希

统一合同让后续索引、引用、权限、版本和 Trace 不必为每种格式重写一套逻辑。

## 10. 清洗和质量门禁

### Excel

- [ ] Sheet 角色识别可靠
- [ ] 多行表头和合并单元格已恢复
- [ ] 说明、汇总和明细已分类
- [ ] 单位、数字和日期标准化但保留原值
- [ ] 公式和值来源已区分
- [ ] 原始行列可回查
- [ ] 空白、重复和隐藏内容按策略处理
- [ ] 阻断行没有进入正式索引

### 图片

- [ ] 方向、分辨率和裁剪正确
- [ ] OCR 字符和数值置信度达到门槛
- [ ] 阅读顺序和区域关系正确
- [ ] 图题、图例与主体关联
- [ ] 原图、页码和 bbox 可打开
- [ ] VLM 摘要标记为派生数据
- [ ] 高风险低置信度内容已人工确认

### 通用

- [ ] 文件、解析器、Schema 和知识版本完整
- [ ] 权限已经写入 Block 和索引
- [ ] 旧版本能够失效
- [ ] 解析失败不会得到“成功但空内容”
- [ ] 内容哈希和数量可以对账

## 11. 检索与权限

```text
身份与项目范围
→ 文档状态 / 版本 / ACL 预过滤
→ 文本向量 + BM25 + 精确字段 + 结构化查询
→ 融合、去重和重排
→ 回事实库重新校验权限与版本
→ 组装证据
→ 渲染前再次鉴权
```

Excel 和图片常含敏感报价、合同、图纸和人员信息。权限不能只写在 Prompt 中，也不能只在页面隐藏：

- 检索前减少不可见候选；
- 返回证据前重新校验；
- 引用打开原图或 Workbook 时再次鉴权；
- 缓存键包含租户、项目和权限版本。

## 12. 更新与版本管理

### Excel 更新

同一 Workbook 新版本可能：

- 新增或删除 Sheet；
- 移动行；
- 修改公式；
- 改变表头；
- 调整隐藏状态。

不能只用行号作为稳定业务身份。可以结合：

```text
document_id
+ document_version
+ sheet logical id
+ business key
+ row content hash
```

### 图片更新

重新导出、裁剪或压缩会改变像素哈希。应区分：

- 原始资产版本；
- 派生 Crop；
- OCR 版本；
- VLM 摘要版本；
- 人工确认版本。

### 索引发布

```text
新文档版本进入 validating
→ 解析和质量门禁
→ 构建新 Block / 索引快照
→ 数量、权限和抽样验证
→ 切换 active manifest
→ 旧版本 superseded
→ 保留回滚与审计
```

## 13. 评测

### Excel 解析

- Sheet 角色准确率；
- 表头识别准确率；
- 字段映射准确率；
- 行类型准确率；
- 数量、单位和金额准确率；
- 公式来源完整率；
- 原始行追溯成功率。

### 图片解析

- OCR 字符和字段准确率；
- 区域检测 IoU；
- 阅读顺序准确率；
- 表格结构准确率；
- 关键实体、数值和单位准确率；
- 原图区域定位成功率。

### 检索与生成

- Recall@K、MRR、nDCG；
- 跨行、跨 Sheet 和跨区域问题正确率；
- 引用支持度；
- 权限与版本正确率；
- 无答案拒答准确率；
- 端到端任务成功率和人工修正率。

必须包含：

- 多 Sheet；
- 多行表头；
- 隐藏和参考 Sheet；
- 公式与缓存值；
- 低清、旋转和复杂图表；
- 权限不可见；
- 旧版本；
- 无答案。

## 14. 常见失败

| 错误设计 | 后果 | 正确做法 |
|---|---|---|
| Excel 全部单元格拼成文本 | 字段和值错位 | Sheet、表格、行和字段建模 |
| 每一行独立 Embedding | 丢失表头和适用范围 | 行块继承表头、Sheet 和规则上下文 |
| LLM 直接重算公式 | 金额不可审计 | 保存公式并使用确定性计算校验 |
| 所有 Sheet 全量入库 | 汇总、说明和隐藏内容污染召回 | Sheet 角色、状态和人工映射 |
| 图片只保留 OCR | 丢失布局和图文关系 | 保存区域、bbox、图题和视觉摘要 |
| 图片只保留 VLM 描述 | 无法验证，可能幻觉 | 保留原图、派生关系和模型版本 |
| 低置信度仍自动 active | 错误知识进入生产 | 质量门禁和人工确认 |
| 只在前端做权限 | 检索或引用泄露 | 预过滤、事实库复核和渲染鉴权 |

## 15. 当前报价中台的真实映射

### 已经实现

Excel：

- `.xlsx/.xlsm` 报价需求解析；
- 多 Sheet 识别；
- 人工列映射；
- 行类型、标准字段和原始行追溯；
- 数量来源和多工程量候选；
- 阻断行校验、人工确认和版本回滚；
- 标准清单接入报价链路。

图片与图纸：

- PDF 页面渲染；
- OCR 和视觉模型；
- 页面、CAD 视图和区域 Crop；
- 视觉证据、证据合并和质量复核；
- 原始资产、阶段产物和失败报告；
- Excel 业务结果和 Debug 产物。

招标资料证据：

- 文档、Sheet、页码和 Evidence Block；
- active manifest；
- 项目 scoped token；
- MySQL 事实源与独立 Milvus 集合；
- BM25、向量、RRF 和检索路由；
- Evidence ID、版本和上下文读取审计。

### 不能夸大的边界

- Excel 标准化当前主要服务报价输入，不等于所有 Excel 已进入通用 RAG 知识库；
- 图纸视觉链路是专项业务流水线，不等于已经建设通用图片向量检索；
- 当前没有证据证明视觉 Embedding 在真实数据上优于文本化检索；
- 不同摄取链路仍可继续统一 Block、Artifact Manifest 和质量指标；
- 低置信度视觉结论仍需要规则或人工确认。

### 下一步合理方向

1. 抽取 Excel、PDF、图片共同的 `DocumentBlock` 合同；
2. 统一文件、解析器、Block、Embedding 和 active manifest 版本；
3. 让 Excel 行和图片区域都能打开原始位置；
4. 建立多格式 Gold Query—Evidence 测试集；
5. 证明视觉通道有增益后，再决定是否上线多模态向量。

## 16. 面试回答模板

### 60 秒版本

> 多格式文档不能全部转成纯文本。Word 和 PDF 重点恢复标题、段落、版面和页码；Excel 要先识别 Sheet 角色、逻辑表格、多行表头、字段、公式和行类型；图片则组合 OCR、Layout 和多模态模型，保留区域、bbox、图题和原图。不同解析器最终输出统一 Block，包含稳定 ID、结构化字段、原始位置、权限、版本、哈希、解析器和置信度。切片按条款、表格行或视觉信息单元，而不是固定字数；查询时结合向量、BM25、精确字段和结构化工具，并在检索前、证据返回和原文打开时校验权限。低置信度内容不能直接进入 active 知识。

### 项目版本

> 报价中台已经有 Excel 多 Sheet 标准化和图纸 PDF/OCR/视觉证据链，但我会区分专项业务解析与通用 RAG 摄取。Excel 目前主要进入报价流程，图纸目前主要形成结构化证据和清单候选，并不代表已经上线通用图片向量检索。下一步应先统一 Block、版本、权限、原始位置和多格式评测，再用真实 Gold 集判断是否值得增加视觉 Embedding。

---

## 一句话总结

多格式 RAG 摄取的核心，是让 Excel 的表格关系和图片的视觉关系都变成可追溯、可校验、带权限和版本的结构化证据，而不是粗暴转换为一段无法回查的文本。
