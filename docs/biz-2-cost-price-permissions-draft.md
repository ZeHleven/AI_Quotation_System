# BIZ-2 成本价权限清单草案

> 状态：权限草案已形成，待业务确认与后续开发排期（2026-05-27）
> 用途：上云前安全边界、角色分工、成本库操作权限和后续开发依据
> 边界：本文只定义权限规则，不改代码、不新增 Alembic、不改变报价规则和价格口径。

## 1. 核心结论

成本价是公司核心机密。上云前必须把“谁能看、谁能改、谁能导出、谁能启用正式成本价”明确下来。

建议原则：

- 普通业务员只在自己的报价预审中看到必要的成本参考，不应浏览、导出完整成本库。
- 成本部业务员负责维护成本库 `draft`、核价和启用 `active`。
- 管理员负责系统管理和必要的成本库管理，不应替代成本部做价格口径判断。
- 老板可查看和审批关键成本数据，但日常不参与录入。
- `draft` 不能进入报价参考，只有 `active` 才能进入报价、底价兜底和 RAG 同步。
- 导出、批量启用、RAG 同步、角色授权都属于高风险操作，上云前必须有审计。

## 2. 当前系统权限现状

当前代码层已有角色：

```text
system_admin / admin / staff / manager / viewer
```

当前成本库能力大致为：

| 操作 | 当前系统角色 |
|------|--------------|
| 查看成本库列表/详情 | `system_admin` / `admin` / `staff` |
| 新建成本条目 | `system_admin` / `admin` |
| 更新成本条目和价格 | `system_admin` / `admin` |
| 启用 `draft -> active` | `system_admin` / `admin` |
| 停用/归档 | `system_admin` / `admin` |
| 成本 Excel 导入确认 | `system_admin` / `admin` |
| 同步 active 到 RAG | `system_admin` / `admin` |
| 权限授权 | `system_admin` |

当前内网验证阶段可接受，但上云前需要收紧。尤其是 `staff` 可只读成本库这一点，上云前建议改为“只有成本部、管理员、老板可看完整成本库”，普通业务员只看自己报价所需的行级参考。

## 3. 建议业务角色

| 业务角色 | 定位 | 建议系统权限 |
|----------|------|--------------|
| 老板 | 查看经营和关键成本，审批重大规则 | 可查看完整成本库、查看导出记录、审批/启用 active；不做日常录入 |
| 系统管理员 | 管账号、权限、环境、备份、故障 | 管理角色和系统配置；可操作成本库，但价格判断应由成本部确认 |
| 成本部业务员 | 成本库维护和核价负责人 | 查看/新增/编辑 `draft`，审核启用 `active`，归档错误条目 |
| 普通报价业务员 | 做报价、预审、补价、下发 | 只能在报价预审中查看必要成本参考；不能浏览完整成本库和导出 |
| 只读观察者 | 看看板和统计 | 只能看汇总，不看成本明细和价格字段 |

建议后续新增更细角色，避免把成本部业务员都授予 `admin`：

```text
cost_viewer      成本库只读
cost_editor      可新建/编辑 draft
cost_approver    可启用 active / 归档 / 撤回启用
cost_exporter    可导出成本数据
```

如果短期不新增角色，内网阶段可以临时用 `admin` 承载成本部审核权限，但上云前不建议继续这样做。

## 4. 成本数据分级

| 数据类型 | 敏感等级 | 查看范围 |
|----------|----------|----------|
| 项目名称、规格、单位 | 中 | 报价相关人员可在报价中查看 |
| 成本库参考价 | 高 | 报价预审中按需展示；完整库仅成本部/管理员/老板 |
| 对甲税前综合单价 | 高 | 成本部/管理员/老板 |
| 劳务发包综合单价 | 高 | 成本部/管理员/老板 |
| 班组标底税前价 | 高 | 成本部/管理员/老板 |
| 人工费、主材费、辅材费拆分 | 很高 | 成本部/管理员/老板，普通业务员不应全量查看 |
| 成本库导出文件 | 很高 | 严格审批、留痕、水印 |
| RAG 同步内容 | 高 | 仅同步 `active`，同步记录管理员可查 |

## 5. 权限矩阵草案

| 操作 | 老板 | 系统管理员 | 成本部业务员 | 普通报价业务员 | 只读观察者 |
|------|:----:|:----------:|:------------:|:--------------:|:----------:|
| 查看自己的报价预审成本参考 | 是 | 是 | 是 | 是 | 否 |
| 查看完整成本库列表 | 是 | 是 | 是 | 否 | 否 |
| 查看成本价格历史 | 是 | 是 | 是 | 否 | 否 |
| 新建成本条目 `draft` | 可 | 是 | 是 | 否 | 否 |
| 编辑 `draft` 条目 | 可 | 是 | 是 | 否 | 否 |
| 编辑 `active` 价格 | 可 | 是 | 是 | 否 | 否 |
| 启用 `draft -> active` | 是 | 是 | 是 | 否 | 否 |
| 撤回 `active -> draft` | 是 | 是 | 是 | 否 | 否 |
| 归档 `draft/active -> archived` | 是 | 是 | 是 | 否 | 否 |
| 批量导入成本 Excel | 否 | 是 | 是 | 否 | 否 |
| 确认导入落库为 `draft` | 否 | 是 | 是 | 否 | 否 |
| 同步 active 到 RAG | 否 | 是 | 可 | 否 | 否 |
| 查看 RAG 同步记录 | 是 | 是 | 是 | 否 | 否 |
| 导出成本库 | 审批/可导出 | 可导出 | 按授权 | 否 | 否 |
| 查看报价运营详情 | 是 | 是 | 可 | 自己相关 | 仅汇总 |
| 角色授权/撤销 | 否 | `system_admin` | 否 | 否 | 否 |

说明：

- “可”表示业务上允许，但建议减少日常操作。
- “按授权”表示需要单独授权，不默认开放。
- 导出、批量启用、批量归档、同步 RAG 都应写审计。

## 6. 无底价 draft 审核权限

根据无底价规则草案，报价下发成功后，无底价人工确认条目会进入成本库 `draft` 待审核。

处理权限：

| 操作 | 允许角色 |
|------|----------|
| 查看无底价沉淀 draft | 老板、系统管理员、成本部业务员 |
| 修改名称/规格/单位/分类 | 系统管理员、成本部业务员 |
| 修改价格 | 系统管理员、成本部业务员 |
| 启用为 `active` | 老板、系统管理员、成本部业务员 |
| 归档错误候选 | 系统管理员、成本部业务员 |
| 查看来源报价任务 | 老板、系统管理员、成本部业务员 |

普通报价业务员可以在本单报价预审中看到自己填写的无底价价格，但不能进入成本库审核这些 draft。

## 7. 操作 SOP

### 7.1 普通报价业务员

可以做：

1. 发起报价。
2. 在预审单中查看自己报价相关的成本参考。
3. 对无底价行人工确认或修正单价、合计。
4. 确认推送或打回。

不可以做：

- 浏览完整成本库。
- 导出成本库。
- 启用 `active`。
- 修改成本库正式价格。
- 同步 RAG。

### 7.2 成本部业务员

可以做：

1. 查看成本库完整列表和价格历史。
2. 新增 `draft` 成本条目。
3. 编辑 `draft` 和必要的 `active` 条目。
4. 审核无底价沉淀的 `draft`。
5. 启用 `draft -> active`。
6. 归档错误或过期条目。
7. 必要时发起 active 成本库同步到 RAG。

必须遵守：

- 启用 active 前检查名称、规格、单位、价格口径和重复项。
- 修改价格必须填写原因。
- 归档 active 必须填写原因。
- 批量操作前必须二次确认。

### 7.3 系统管理员

可以做：

1. 管理账号、角色、功能开关和服务状态。
2. 处理成本库异常数据。
3. 协助成本部导入、回滚、同步。
4. 查看审计记录。

不建议做：

- 在没有成本部确认的情况下修改正式价格。
- 代替成本部大批量启用 active。
- 为普通业务员开放完整成本库。

### 7.4 老板

可以做：

1. 查看成本库和关键价格。
2. 查看成本库导出和高风险操作记录。
3. 审批关键权限和上云策略。
4. 必要时启用或确认关键 active 条目。

建议不做日常数据维护，避免责任链不清。

## 8. 高风险操作清单

以下操作上云前必须纳入审计：

- 成本库导出
- 批量导入确认
- 批量启用 `active`
- 批量归档
- 修改 active 价格
- 撤回 active 为 draft
- 同步 active 到 RAG
- 授予或撤销成本相关角色
- 开启公网访问

审计至少记录：

- 操作人
- 操作时间
- 操作类型
- 目标条目
- 修改前后状态/价格
- 原因
- IP
- user agent
- trace_id

公网访问后，导出、批量启用、角色授权等操作建议要求钉钉二次验证。

## 9. 上云前必须完成的权限改造

| 项 | 建议 |
|----|------|
| 普通业务员完整成本库只读 | 上云前关闭 |
| 成本部角色 | 建议新增 `cost_viewer/cost_editor/cost_approver` 或等价角色 |
| 成本库导出 | 增加单独权限、审计、水印 |
| active 启用 | 从普通 admin 权限中拆出，至少在流程上要求成本部确认 |
| RAG 同步 | 仅允许管理员或成本部授权人员 |
| 价格历史 | 成本部/管理员/老板可看，普通业务员不可看 |
| 无底价 draft 审核 | 成本部/管理员/老板可处理 |
| 钉钉二次验证 | 公网访问前必须补齐 |

## 10. 后续开发建议

### 10.1 最小方案

短期内不新增角色：

- 继续用 `admin/system_admin` 管理成本库。
- 普通业务员只通过报价预审看必要成本参考。
- 成本部账号临时授予 `admin`。
- 用制度约束管理员不要代替成本部确认价格。

优点：改动小。  
缺点：权限过粗，不适合直接上云。

### 10.2 推荐方案

新增成本专项角色：

```text
cost_viewer
cost_editor
cost_approver
cost_exporter
```

并调整接口：

- 成本库列表：`cost_viewer+`
- 新建/编辑 draft：`cost_editor+`
- 启用 active/归档：`cost_approver+`
- 导出成本库：`cost_exporter` 或 `system_admin`
- RAG 同步：`cost_approver` / `admin` / `system_admin`
- 普通 `staff` 不再能访问完整成本库

涉及新增角色或权限表调整时，必须走 Alembic。

## 11. 待老板确认

| 问题 | 建议口径 |
|------|----------|
| 普通业务员能否看完整成本库 | 不建议 |
| 普通业务员能否在自己报价里看成本参考 | 可以 |
| 成本部业务员能否启用 active | 可以 |
| 管理员能否修改成本价 | 技术上可以，业务上需成本部确认 |
| 老板是否能查看/导出成本库 | 可以，但导出要留痕 |
| 是否需要新增成本专项角色 | 上云前建议新增 |
| 是否允许公网访问成本库 | 不建议，优先 VPN/内网云 |

## 12. 结论

成本价权限的核心不是“谁都不能看”，而是“按工作需要最小授权”：

- 报价业务员看自己报价需要的成本参考。
- 成本部维护成本库和启用 active。
- 管理员保障系统和审计。
- 老板看关键数据和权限边界。

上云前必须把普通业务员完整成本库只读权限收紧，并补齐成本专项角色、导出审计和高风险操作二次验证。
