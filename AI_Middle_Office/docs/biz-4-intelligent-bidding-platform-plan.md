# BIZ-4 智能投标中台产品规划

> 文档日期：2026-06-29  
> 当前状态：规划文档，仅定义产品主线、阶段边界和后续开发拆分口径；不新增代码、不新增数据库结构、不启动 Alembic。

## 1. 第一性原理

装饰工程企业的投标系统，本质上不是一个“AI 写 Word”的工具，而是把招标文件中的外部要求，转化为企业内部可判断、可报价、可响应、可交付、可复盘的经营作业流程。

核心对象有两个：

- 招标文件：甲方提出的需求、规则、边界、评分办法和风险约束。
- 投标文件：乙方基于自身能力、成本、经验和履约资源给出的报价、方案、承诺和证据。

因此系统价值不应只看“生成速度”，还要看：

- 是否不漏项：招标要求都被识别、归类和响应。
- 是否不废标：资格、格式、签章、暗标、报价、工期、有效期等硬性规则不出错。
- 是否报价有依据：经济标来自成本库、历史项目、供应链价格和人工确认，不由 AI 凭空编造。
- 是否方案可承诺：工期、人员、材料、施工组织和企业真实能力匹配。
- 是否过程可追溯：每一条响应、报价和风险提示都能回到招标原文、成本依据或企业证据。

一句话定位：

> BIZ-4 智能投标中台 = 招标文件解析 + 投标决策 + 响应矩阵 + 报价测算 + 投标书生成 + 合规体检 + 中标复盘的闭环系统。

## 2. 产品主线

推荐主流程：

```text
招标资料进入系统
  -> 投标项目建档
  -> 招标文件解析
  -> 投标决策辅助
  -> 响应矩阵
  -> 报价与成本测算
  -> 商务标/技术标/经济标生成
  -> 合规体检与废标风险检查
  -> 人工审核与导出
  -> 中标/未中标复盘
  -> 企业知识库、成本库、方案库回流
```

这条主线的关键判断是：先读懂甲方要求，再决定是否投，再生成响应内容。不能直接从“上传招标书 -> 生成投标书”开始，否则容易生成一份看起来完整但不可承诺、不可审计、甚至存在废标风险的文件。

## 3. 核心模块

### 3.1 投标项目建档

目标：给每次投标建立统一容器，承载资料、任务、人员、版本和结果。

建议字段：

- 项目名称、招标单位、招标代理、工程地点、工程类型。
- 投标截止时间、答疑截止时间、开标时间。
- 工程规模、预计工期、质量标准、最高限价或控制价。
- 上传资料：招标文件、工程量清单、图纸、补遗、答疑、合同范本、品牌表。
- 项目状态：待解析、待决策、编制中、待审核、已投标、已中标、未中标、放弃投标。
- 负责人：经营、预算、技术、法务或管理层。

### 3.2 招标文件解析

目标：把“甲方出的题”结构化。

系统应提取：

- 工程基本信息：名称、地点、范围、工期、质量、承包方式。
- 投标规则：截止时间、投标保证金、密封要求、电子投标要求、签章要求、格式要求。
- 资格条件：资质等级、业绩要求、项目经理、技术负责人、安全员、财务、信用。
- 评标办法：价格分、技术分、商务分、权重、扣分项、废标条款。
- 工程范围：装饰、强弱电、给排水、暖通、消防、家具、软装等边界。
- 清单与图纸要求：清单项目、工程量、项目特征、图纸编号、答疑和补遗关联。
- 材料与工艺要求：品牌档次、规格型号、环保等级、施工工艺、验收标准。
- 合同与商务风险：付款方式、结算方式、不可调价条款、违约责任、质保期限。
- 待确认问题：图纸缺失、清单矛盾、品牌不明确、范围边界不清、合同风险过高。

第一阶段输出物：

- 招标要求清单。
- 废标条款清单。
- 风险清单。
- 待确认问题清单。
- 招标文件摘要。

### 3.3 投标决策辅助

目标：先判断是否值得投，而不是每个标都机械生成文件。

建议判断维度：

- 资格符合度：资质、业绩、人员证书、信用要求是否满足。
- 企业能力匹配：同类项目经验、施工资源、项目经理可用性。
- 工期可实现性：工期是否紧张，是否存在夜间施工、交叉作业、节假日影响。
- 报价空间：最高限价、成本底线、利润率、风险预留。
- 现金流压力：付款节点、质保金比例、垫资压力。
- 竞争风险：业主关系、区域竞争、历史中标价水平。
- 废标风险：硬性条款、暗标要求、材料品牌限制、格式复杂度。

输出结论：

- 建议投。
- 谨慎投。
- 不建议投。

同时给出原因、关键风险和需要人工确认的问题。

### 3.4 响应矩阵

目标：把招标书要求转化为投标书编制作业的中枢表。

推荐字段：

| 字段 | 含义 |
| --- | --- |
| requirement_id | 要求编号 |
| requirement_type | 资格、商务、技术、报价、材料、合同、格式、暗标 |
| source_file | 来源文件 |
| source_location | 页码、章节、表格、原文位置 |
| original_text | 招标原文 |
| parsed_requirement | 系统提炼后的要求 |
| response_strategy | 我方响应策略 |
| response_text | 投标书中建议写入的响应内容 |
| compliance_status | 满足、部分满足、不满足、待确认 |
| risk_level | 高、中、低 |
| owner | 经营、预算、技术、法务、管理层 |
| evidence | 证照、业绩、人员、报价表、施工方案、材料证明 |
| output_section | 商务标、技术标、经济标、偏离表、承诺函等 |
| reviewer_note | 人工复核意见 |

响应矩阵应驱动后续文档生成、偏离表生成、合规检查和人工审核。

### 3.5 报价与成本测算

目标：经济标不能只是填价格，必须能解释价格。

应复用现有 BIZ-2 报价能力：

- `cost_items.active` 成本库。
- 报价任务 `quote_jobs`。
- 成本库前置参考。
- 成本库匹配、漏项检测、底价兜底。
- 无底价 draft 沉淀。
- 人工改价、草稿保存、成本证据链。
- 报价运营复核详情。

投标场景需要增强：

- 从招标清单生成经济标报价行。
- 将清单项目、项目特征、品牌要求、施工做法与成本库匹配。
- 区分直接成本、措施费、管理费、利润、税金、风险预留。
- 支持保守价、竞争价、底线价等多版本报价策略。
- 标记低于成本、明显偏高、工程量缺失、单位不一致、无底价项目。
- 生成综合单价分析、主要材料价格表和报价说明。

边界要求：

- 不自动把 AI 估价直接变成成本库 `active`。
- 无底价项目仍应走人工确认和 `draft` 待审核。
- 成本敏感信息按现有 RBAC 和成本专项角色控制展示。

### 3.6 投标文件生成

目标：先生成结构化投标内容，再按模板导出 Word、PDF、Excel。

商务标：

- 投标函。
- 法定代表人身份证明和授权委托书。
- 企业资质、营业执照、安全生产许可证。
- 企业业绩。
- 项目管理班子。
- 工期、质量、安全、付款响应。
- 偏离表。
- 承诺函。

技术标：

- 项目理解。
- 施工部署。
- 重难点分析。
- 施工进度计划。
- 劳动力、材料、机械计划。
- 质量保证措施。
- 安全文明施工措施。
- 成品保护措施。
- 环保与扬尘控制。
- 与甲方、设计、监理、消防、机电等单位配合措施。
- 售后维保方案。

经济标：

- 投标报价汇总表。
- 分部分项清单报价。
- 措施项目费。
- 材料品牌响应表。
- 综合单价分析表。
- 主要材料价格表。
- 报价说明。

模板原则：

- 不同业主、代理公司、平台的格式差异很大，必须支持模板化。
- 系统生成的是初稿和结构化内容，最终投标文件必须经过人工审核。
- 暗标项目应支持匿名化检查和敏感词检查。

### 3.7 合规体检与废标风险检查

目标：交卷前自动体检，降低废标概率。

检查项：

- 招标文件要求是否全部进入响应矩阵。
- 是否遗漏章节、附件、承诺函、偏离表。
- 是否漏签字、漏盖章、漏日期。
- 投标有效期是否一致。
- 工期、质量标准、质保期是否响应。
- 报价是否超过最高限价。
- 清单是否漏项、错项、单位异常、数量异常。
- 项目经理、资质、业绩是否满足资格要求。
- 材料品牌是否低于招标要求。
- 技术标是否违反暗标要求。
- 页码、目录、封面、文件命名、电子投标格式是否符合要求。
- 响应内容是否出现企业无法履约的过度承诺。

输出物：

- 投标文件体检报告。
- 高风险阻断项。
- 中低风险提醒项。
- 建议人工复核清单。

### 3.8 企业投标知识库

目标：让系统越用越懂企业，而不是每次重新生成。

建议沉淀：

- 企业标准介绍。
- 资质证照库。
- 人员证书库。
- 项目业绩库。
- 标准施工方案库。
- 常用承诺函模板。
- 材料品牌库。
- 供应商和价格库。
- 历史投标书。
- 中标、未中标原因。
- 项目实际成本和投标成本偏差。

长期目标：

- 同类工程自动推荐历史技术方案。
- 同类清单自动推荐报价依据。
- 同类业主自动提示投标风险。
- 投标结果反哺经营分析和成本库治理。

## 4. 阶段规划

### BIZ-4a 招标文件解析与风险识别

目标：先读懂招标文件，形成结构化要求和风险清单。

范围：

- 投标项目建档。
- 招标资料上传和版本管理。
- 招标文件解析。
- 招标要求清单。
- 废标条款清单。
- 风险清单。
- 待确认问题清单。

暂不做：

- 自动生成完整投标书。
- 自动经济标报价。
- 自动决策是否投标。

验收口径：

- 能从典型装饰工程招标文件中提取工期、质量、资格、评分、清单、材料、合同风险。
- 每条要求保留来源文件和位置。
- 高风险条款可被人工确认、关闭或转入响应矩阵。

### BIZ-4b 响应矩阵与投标决策

目标：把招标要求转成可分工、可审核、可追踪的响应矩阵，并辅助判断是否投标。

范围：

- 响应矩阵生成。
- 响应状态维护。
- 负责人分配。
- 证据材料绑定。
- 投标决策评分。
- 建议投、谨慎投、不建议投结论。

验收口径：

- 招标要求能映射到商务标、技术标、经济标、偏离表或承诺函。
- 不满足或待确认要求能突出显示。
- 投标决策报告能解释风险来源，而不是只给分数。

### BIZ-4c 商务标和技术标初稿生成

目标：基于响应矩阵和企业知识库生成可编辑初稿。

范围：

- 商务标结构化内容生成。
- 技术标结构化内容生成。
- 企业资质、业绩、人员资料引用。
- 模板化 Word 导出。
- 初版偏离表和承诺函生成。

验收口径：

- 输出内容能回溯到响应矩阵或企业知识库。
- 章节完整度可检查。
- 人工能在线调整响应文字和模板内容。

### BIZ-4d 经济标与成本库联动

目标：把招标清单转成有成本依据的经济标初稿。

范围：

- 招标清单解析。
- 成本库匹配。
- 多版本报价策略。
- 无底价项目提示。
- 综合单价分析。
- 报价说明生成。
- 经济标 Excel 导出。

验收口径：

- 成本库命中、无底价、人工改价、低于成本风险都有清晰标识。
- 经济标合计、分项合计和报价说明一致。
- 成本证据链可追溯，不暴露给无权限角色。

### BIZ-4e 投标文件合规体检

目标：交付前做废标风险检查。

范围：

- 章节完整性检查。
- 签章、日期、投标有效期检查。
- 工期、质量、资质、人员、报价硬性规则检查。
- 暗标匿名检查。
- 清单漏项和单位异常检查。
- 体检报告导出。

验收口径：

- 高风险废标项必须明显提示。
- 体检报告能定位到原文要求、投标文件位置和建议修复动作。
- 人工确认后保留审计记录。

### BIZ-4f 企业投标知识库

目标：将企业能力、历史方案、证据材料和投标模板体系化。

范围：

- 资质证照库。
- 人员证书库。
- 企业业绩库。
- 技术方案库。
- 投标模板库。
- 材料品牌响应库。
- 历史投标书检索。

验收口径：

- 生成投标文件时能自动引用合适业绩、人员、模板和方案。
- 过期证照、人员证书和失效模板能提示。
- 知识库变更有权限控制和审计记录。

### BIZ-4g 中标复盘与经营分析

目标：把投标结果回流到经营决策和企业知识沉淀。

范围：

- 中标、未中标结果登记。
- 竞争对手和中标价记录。
- 评分项得失分析。
- 投标成本与实际施工成本偏差分析。
- 按业主、区域、工程类型、项目经理统计中标率。
- 可复用方案和报价经验沉淀。

验收口径：

- 每个投标项目有可复盘结果。
- 能识别高胜率业主、低利润项目、常见丢分项。
- 复盘结果能反哺成本库、方案库和后续投标决策。

## 5. MVP 建议

第一期 MVP 建议只做四件事：

1. 招标文件上传、项目建档和解析。
2. 响应矩阵自动生成。
3. 风险点、废标条款和待确认问题提取。
4. 商务标、技术标 Word 初稿生成，并做基础合规检查。

MVP 暂缓：

- 完整经济标自动报价。
- 中标率经营分析。
- 复杂投标模板市场。
- 多代理格式全覆盖。
- 自动盖章、自动提交电子投标平台。

原因：

- 真实痛点优先级是少漏项、少废标、缩短初稿编制时间。
- 经济标已经有 BIZ-2 报价能力基础，但投标经济标需要更高的模板和合规要求，适合作为第二期接入。
- 企业知识库需要先有投标项目和响应矩阵作为沉淀入口，不宜先建空库。

## 6. 与现有系统的衔接

可复用能力：

- 文件存储：复用现有 MinIO 文件对象能力。
- 鉴权：复用 Phase 0 RBAC 和现有角色机制。
- 成本库：复用 `cost_items.active`、状态流转、权限和审计。
- 报价链路：复用 `quote_jobs`、预审、成本证据链、无底价 draft。
- 需求单标准化：复用 BIZ-2l 的清单字段标准化思路。
- 项目进度：后续可与 BIZ-3 执行任务衔接，把中标项目转成执行任务。
- 经营看板：后续可把投标机会、中标率和报价利润纳入经营总览。

需要新增能力：

- 招标文件结构化解析。
- 响应矩阵。
- 投标项目生命周期。
- 投标模板库。
- 合规体检规则。
- 投标复盘数据。

安全与权限：

- 成本底价、利润率、竞争策略属于敏感信息。
- 普通业务员可查看投标编制所需的受限信息。
- 成本、预算、管理员和老板按角色查看完整成本和利润测算。
- 投标导出、模板变更、成本引用、废标风险人工放行需要审计。

## 7. 推荐数据对象草案

后续进入设计阶段时，可围绕这些对象拆表和接口：

- `bid_projects`：投标项目。
- `bid_project_files`：招标资料、补遗、答疑、图纸、清单。
- `tender_requirements`：招标要求清单。
- `tender_risks`：风险、废标条款、待确认问题。
- `bid_response_matrix_rows`：响应矩阵。
- `bid_decision_reports`：投标决策报告。
- `bid_quote_versions`：投标报价版本。
- `bid_document_drafts`：商务标、技术标、经济标草稿。
- `bid_compliance_reports`：合规体检报告。
- `bid_outcome_reviews`：中标、未中标复盘。
- `bid_templates`：投标模板。
- `enterprise_bid_assets`：证照、业绩、人员、方案等企业投标资料。

设计原则：

- 新增数据库字段和表必须走 Alembic revision。
- 不依赖 `AUTO_CREATE_TABLES` 或启动兼容迁移。
- 大文本、解析结果、审计 trace 应考虑 `LONGTEXT` 或独立对象存储。
- 原始文件、解析结果、人工修订、导出文件都应保留版本。

## 8. 风险边界

必须避免：

- AI 自动承诺企业无法履约的工期、质量或技术措施。
- AI 自动降低材料品牌档次以压价。
- AI 将无底价估价直接写入正式成本库 active。
- 技术标暗标项目暴露公司名称、人员姓名或企业标识。
- 投标文件未人工审核就直接作为最终交付。
- 成本敏感信息被普通角色下载或外泄。

必须保留：

- 招标原文来源。
- AI 解析结果。
- 人工确认记录。
- 响应矩阵版本。
- 报价依据和成本证据。
- 合规体检报告。
- 最终导出文件版本。
