# 试运行账号权限与安全口径 Runbook

更新时间：2026-06-03

## 1. 适用范围

本 Runbook 用于小范围内网试运行阶段的账号、权限、初始密码和账号维护说明。

本阶段不新增业务权限模型，不改变报价、成本库、项目进度、看板和审计规则，只把现有 RBAC 能力收束成可执行的试运行口径。

## 2. 安全口径

试运行阶段遵循：

- 不共用管理员账号。
- 不再使用 `admin / 123` 作为正常账号口径。
- 自注册保持关闭：`ALLOW_SELF_REGISTRATION=false`。
- 公网访问保持关闭：`PUBLIC_ACCESS_ENABLED=false`。
- 新建用户必须使用个人账号。
- 初始密码只作为临时密码，首次登录后必须修改。
- `system_admin` 只用于账号、角色、权限和救援，不用于日常报价操作。
- 成本库敏感能力使用成本专项角色控制。
- 成本库导出只给有明确授权的账号。

## 3. 当前系统已有能力

### 3.1 正常账号维护入口

正常维护入口：

```text
/admin/permissions
```

当前已有能力：

- `system_admin` 新建用户。
- 新建用户设置初始密码。
- 新建用户设置额度。
- 新建用户分配初始角色。
- 新用户 `must_change_password=true`，首次登录后应改密。
- `system_admin` 授予角色。
- `system_admin` 撤销角色。
- 查看角色授权历史。
- `admin` 可查看用户列表和调整额度。

### 3.2 仍不作为日常流程的能力

以下不作为日常维护方式：

- 直接改数据库。
- 使用共享管理员账号。
- 使用 `create_admin.py` 批量创建用户。
- 把救援脚本当作日常密码重置工具。

`create_admin.py` 只保留为应急救援脚本，必须显式传入 `--confirm-rescue`，并且不再内置默认密码。

## 4. 角色说明

| 角色 | 试运行用途 | 建议授予对象 | 说明 |
|---|---|---|---|
| `system_admin` | 系统最高管理 | 仅 1-2 个系统负责人 | 可创建用户、分配角色、撤销角色；不要作为日常业务账号 |
| `admin` | 管理员 | 内部系统管理员/运营负责人 | 可看管理类页面和大部分运营数据，不负责系统级授权 |
| `staff` | 普通业务员 | 报价业务员、试运行参与人 | 可使用报价、需求单标准化、基础项目协作能力 |
| `quote_user` | 报价使用 | 需要报价但不需要完整 staff 能力的人 | staff 会隐含报价能力 |
| `quote_operator` | 报价运营/看板 | 报价运营复核人员 | 可看部分报价运营和看板入口 |
| `viewer` | 管理层只读 | 老板、只读观察者 | 用于看经营总览，不做业务操作 |
| `manager` | 项目/管理角色 | 项目负责人、管理人员 | 可参与项目进度管理和看管理视图 |
| `cost_viewer` | 成本库查看 | 成本报价部查看人员 | 可查看完整成本库 |
| `cost_editor` | 成本库编辑 | 成本库维护人员 | 隐含 `cost_viewer` |
| `cost_approver` | 成本库启用/归档/审核 | 成本负责人 | 隐含 `cost_editor`、`cost_viewer` |
| `cost_exporter` | 成本库导出 | 极少数授权人员 | 导出能力应单独审批 |
| `project_viewer` | 项目只读 | 项目观察者 | 只看项目进度 |
| `project_member` | 项目成员 | 项目执行人员 | 可参与项目任务 |
| `project_manager` | 项目经理 | 项目负责人 | 隐含项目成员和只读能力 |

## 5. 试运行推荐账号模型

| 账号类型 | 建议角色 | 用途 |
|---|---|---|
| 系统负责人 | `system_admin` | 创建账号、分配角色、救援 |
| 试运行管理员 | `admin` | 查看运营数据、协助排查 |
| 报价业务员 | `staff` | 需求单标准化、报价工作台、报价历史 |
| 成本库查看人员 | `cost_viewer` | 查看成本库完整信息 |
| 成本库维护人员 | `cost_editor` | 维护 draft 成本条目 |
| 成本审核人员 | `cost_approver` | 核定 active、归档、同步相关操作 |
| 成本导出人员 | `cost_exporter` | 仅在明确授权时导出 |
| 项目负责人 | `project_manager` 或 `manager` | 项目进度和关键节点推进 |
| 管理层只读 | `viewer` | 看经营总览和核心指标 |

小范围试运行建议先准备 3-5 个真实个人账号，避免一次性开太多角色。

## 6. 新建用户流程

1. 使用 `system_admin` 登录。
2. 进入：

```text
/admin/permissions
```

3. 点击新建用户。
4. 填写：
   - 用户名。
   - 临时密码。
   - 额度。
   - 初始角色。
   - 创建原因/备注。
5. 创建后通知用户首次登录并修改密码。
6. 在账号初始化表中记录：
   - 用户名。
   - 姓名。
   - 部门。
   - 角色。
   - 创建人。
   - 是否已改密。

模板见：

```text
reports/trial_readiness/20260603_stage2/account_initialization_template.csv
```

## 7. 角色变更流程

1. 由业务负责人或试运行负责人提出角色变更原因。
2. `system_admin` 在 `/admin/permissions` 中授予或撤销角色。
3. 备注中写清楚原因，例如：

```text
试运行第 1 周，成本部张三需要查看成本库完整信息，授予 cost_viewer。
```

4. 查看角色事件确认记录已经写入。
5. 通知用户重新登录，使新的 `role_version` 生效。

## 8. 密码维护口径

### 8.1 用户自己改密码

用户登录后如果看到必须改密提示，应立即修改密码。

当前正常改密接口：

```text
POST /api/v1/auth/change_password
```

### 8.2 管理员重置密码

试运行当前不把脚本重置密码作为日常流程。建议口径：

- 用户还记得旧密码：用户自己改密。
- 用户忘记密码且仍可通过系统管理员处理：先记录问题，后续补正式“管理员重置密码”能力。
- 系统管理员账号不可用：使用救援脚本恢复 `system_admin`。

救援脚本示例：

```powershell
cd C:\Users\12521\Documents\Codex\2026-04-25\ai-pycharm\Clear_test\AI_Middle_Office
$env:RESCUE_ADMIN_PASSWORD="临时强密码"
python create_admin.py --confirm-rescue --username admin
```

执行后：

- 该账号会成为 `system_admin`。
- 账号会被启用。
- `must_change_password=true`。
- 下次登录必须修改临时密码。

## 9. 账号停用口径

试运行期间原则：

- 人员退出试运行后，应撤销不再需要的角色。
- 离职或不再参与时，应停用账号。
- 当前如 UI 未提供停用入口，不建议直接改数据库；先在试运行问题清单中登记，后续作为账号维护补强项。

账号停用记录模板见：

```text
reports/trial_readiness/20260603_stage2/account_change_log.csv
```

## 10. 试运行账号最低通过线

进入小范围真实试运行前，至少满足：

- 有 1 个可用 `system_admin` 个人账号。
- 有 1 个非 system_admin 的普通业务员账号。
- 有 1 个管理层只读或运营查看账号。
- 若演示成本库，至少有 1 个成本专项账号。
- 所有试运行账号都有个人用户名。
- 所有临时密码已记录发放状态。
- 共享管理员账号不参与日常业务操作。
- 账号初始化表已填写。

## 11. 当前已知缺口

- 管理员日常重置普通用户密码的正式 UI/API 仍需后续补强。
- 管理员日常停用账号的正式 UI/API 仍需后续补强。
- 当前阶段先通过文档和救援脚本避免最危险的 `admin / 123` 和共享账号问题。
