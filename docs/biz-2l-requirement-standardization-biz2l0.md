# BIZ-2l-0 甲方需求单标准字段与典型场景确认

> 状态：已完成文档层确认（2026-05-25）
> 范围：仅确认标准字段、字段别名、典型异常场景、人工确认口径和 BIZ-2l-1 输入合同。
> 边界：不编码、不写数据库、不改报价逻辑、不改价格口径、不自动沉淀成本库。

## 1. 阶段目标

BIZ-2l-0 解决的问题不是“让系统认识所有甲方模板”，而是先定义一套稳定的中间标准：

- 甲方需求单无论字段名、顺序、表头层级、Sheet 数量如何变化，后续都先转换成统一的标准报价输入。
- 系统可以猜测字段语义，但猜错时必须允许业务员快速修正。
- 低置信度、缺少数量、缺少单位、疑似合计行、疑似说明行等情况不直接进入报价。
- 甲方表格中的单价、金额、合价等字段只作为原始信息保留，不参与系统定价。

本阶段的产物是给 BIZ-2l-1 只读解析器使用的“字段和场景合同”。

## 2. 核心决策

| 决策 | 结论 |
|------|------|
| 是否依赖大量真实甲方需求单 | 否。真实样本数量有限且样式离散，不能作为启动前提。 |
| 是否先建设甲方模板库 | 否。首版不做客户模板记忆，也不自动学习人工修正。 |
| 是否改变报价链路 | 否。BIZ-2l-0 和 BIZ-2l-1 都不接报价。 |
| 是否读取甲方表格里的单价/合价 | 只保留为原始字段，不作为报价价格。 |
| 是否允许低置信度自动报价 | 否。低置信度必须人工确认。 |
| 是否新增数据库结构 | 否。后续如需持久化模板、修正历史或客户偏好，单独走 Alembic。 |

## 3. 标准报价行字段

### 3.1 必填核心字段

| 字段 | 类型 | 必填 | 说明 | 缺失处理 |
|------|------|------|------|----------|
| `item_name` | string | 是 | 标准施工项目/材料名称 | 缺失则该行不能自动进入报价 |
| `quantity` | number | 是 | 标准化数量 | 缺失、非数字、范围值均需人工确认 |
| `unit` | string | 是 | 标准化计量单位 | 缺失则需人工确认 |

### 3.2 业务辅助字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `spec` | string | 否 | 规格、型号、项目特征、做法、工艺说明 |
| `remark` | string | 否 | 无法安全结构化但需要保留的说明 |
| `location` | string | 否 | 房间、区域、楼层、部位等位置描述 |
| `work_area` | string | 否 | 与 `location` 类似，若甲方表格区分区域和部位可同时保留 |

### 3.3 追溯与确认字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `source_file` | string | 是 | 原始文件名 |
| `source_sheet` | string | 是 | 原始 Sheet 名 |
| `raw_row_index` | number | 是 | 原始 Excel 行号 |
| `raw_fields` | object | 是 | 原始列名和值 |
| `raw_text` | string | 是 | 该行拼接后的原始文本 |
| `field_mapping` | object | 是 | 原字段到标准字段的映射关系 |
| `row_type` | string | 是 | `data_row`、`header_row`、`section_row`、`note_row`、`summary_row`、`empty_row`、`ambiguous_row` |
| `confidence` | string | 是 | `high`、`medium`、`low` |
| `warnings` | array | 是 | 异常提示码列表 |
| `requires_confirmation` | boolean | 是 | 是否必须人工确认 |

### 3.4 可选匹配字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `unit_raw` | string | 否 | 甲方原始单位文本 |
| `unit_family` | string | 否 | 单位族，如 `length`、`area`、`count`、`set` |
| `normalized_name` | string | 否 | 归一化后的名称，用于后续匹配 |
| `cost_candidates` | array | 否 | BIZ-2l-1 可不输出；BIZ-2l-3 之后仅作候选展示，不自动定价 |

## 4. 字段别名规则

字段别名用于系统猜列，不代表百分百确定。强别名可提高置信度，弱别名只能作为辅助信号。

| 标准字段 | 强别名 | 弱别名/辅助词 |
|----------|--------|---------------|
| `item_name` | 项目名称、施工项目、工作内容、清单名称、材料名称、名称、项目 | 描述、内容、施工内容 |
| `spec` | 规格、型号、项目特征、特征描述、规格型号、做法、工艺 | 描述、备注、说明 |
| `quantity` | 数量、工程量、数量/工程量、工程数量 | 数、量、计量 |
| `unit` | 单位、计量单位、报价单位 | 计价单位 |
| `remark` | 备注、说明、附注、施工说明 | 其他说明 |
| `location` | 区域、房间、楼层、部位、位置 | 空间、施工区域 |

### 4.1 价格类字段处理

以下字段不得进入系统定价逻辑：

- 单价
- 综合单价
- 合价
- 金额
- 总价
- 税前价
- 含税价
- 备注价

处理规则：

- 在 `raw_fields` 中保留。
- 可在预审中提示“甲方原表包含价格列，系统未采用该价格”。
- 不映射为 `cost_reference`，不覆盖 AI 报价，不覆盖成本库底价。

## 5. 单位与数量规则

### 5.1 单位族

| 单位族 | 常见写法 | 处理口径 |
|--------|----------|----------|
| `length` | m、M、米、延米、米/延米 | 保留清洗后的单位，内部可标记为长度族 |
| `area` | ㎡、m2、M2、平方米、平米 | 保留清洗后的单位，内部可标记为面积族 |
| `volume` | m3、立方米、方 | 保留清洗后的单位，内部可标记为体积族 |
| `count` | 个、只、块、片、根、张 | 保留清洗后的单位，内部可标记为数量族 |
| `set` | 套、组、项 | 保留清洗后的单位，内部可标记为套/项族 |

### 5.2 数量识别

| 场景 | 处理 |
|------|------|
| 单独数字，如 `20` | 可识别为数量 |
| 数量单位粘连，如 `20㎡`、`18m` | 拆成 `quantity=20`、`unit=㎡` |
| 近似值，如 `约20` | 识别数量，但加 `APPROXIMATE_QUANTITY` |
| 范围值，如 `20-30` | 不自动取值，加 `RANGE_QUANTITY`，需人工确认 |
| 多个数字，如 `2遍 20㎡` | 优先把工程量识别为数量，把遍数放入 `spec`，加 `MULTIPLE_NUMBERS` |
| 空数量 | 加 `MISSING_QUANTITY`，不能自动进入报价 |
| 0 或负数 | 加 `INVALID_QUANTITY`，不能自动进入报价 |

## 6. 行类型分类

| 行类型 | 说明 | 是否进入报价 |
|--------|------|--------------|
| `data_row` | 明确包含项目、数量、单位的有效行 | 可进入标准化预审 |
| `header_row` | 表头行 | 不进入报价 |
| `section_row` | 区域/章节行，如“客厅”“一、拆除工程” | 不进入报价，可作为后续行的 `location` 或分组 |
| `note_row` | 说明、备注、施工要求 | 不进入报价，可并入相关行备注 |
| `summary_row` | 小计、合计、总计 | 不进入报价 |
| `empty_row` | 空行 | 不进入报价 |
| `ambiguous_row` | 无法判断的行 | 不自动进入报价，需人工确认 |

## 7. 典型场景矩阵

| 编号 | 场景 | 示例 | BIZ-2l-1 处理要求 |
|------|------|------|------------------|
| S01 | 标准表头 | 项目名称 / 规格 / 数量 / 单位 / 备注 | 高置信度识别 |
| S02 | 字段别名 | 工作内容 / 项目特征 / 工程量 / 计量单位 | 通过别名识别 |
| S03 | 无表头 | 第一行直接是“拆除复合木地板 20㎡” | 作为低/中置信度行解析，需人工确认 |
| S04 | 多级表头 | 上层“工程内容”，下层“名称/规格” | 合并表头语义后识别 |
| S05 | 多 Sheet | 拆除工程、安装工程分别在不同 Sheet | 每个 Sheet 单独输出，保留 `source_sheet` |
| S06 | 名称数量单位混写 | `窗帘盒/灯槽拆除 18m` | 拆出名称、数量、单位 |
| S07 | 规格混写 | `墙面乳胶漆 两遍 120㎡` | `两遍` 进入 `spec`，`120` 进入数量 |
| S08 | 说明行 | `备注：现场保护由施工方负责` | 标记 `note_row`，不报价 |
| S09 | 合计行 | `小计`、`合计`、`总计` | 标记 `summary_row`，不报价 |
| S10 | 区域行 | `客厅`、`主卧`、`一、拆除工程` | 标记 `section_row`，可作为后续行位置/分组 |
| S11 | 价格列存在 | 数量、单位、单价、合价同时存在 | 价格列保留原始值，不参与报价 |
| S12 | 合并单元格 | 多行共享同一区域或项目类别 | 可向下填充分组信息，但需记录警告 |
| S13 | 单位缺失 | 项目名称和数量存在，单位为空 | 加 `MISSING_UNIT`，需人工确认 |
| S14 | 数量缺失 | 项目名称和单位存在，数量为空 | 加 `MISSING_QUANTITY`，不能自动报价 |
| S15 | 旧 `.xls` | 甲方发来 `.xls` | 继续提示另存为 `.xlsx`，不新增旧格式解析 |
| S16 | 图片/PDF | 图片或 PDF 需求单 | 不属于 BIZ-2l-1 首版范围，沿用现有图片识别或后续另立阶段 |

## 8. 置信度规则

| 置信度 | 条件 |
|--------|------|
| `high` | 强别名表头识别成功，且 `item_name`、`quantity`、`unit` 均明确 |
| `medium` | 核心字段齐全，但至少一个字段来自弱别名、混写拆分或上下文推断 |
| `low` | 缺少核心字段、多个数字无法判断、无表头推断、疑似说明/合计/区域行 |

强制人工确认条件：

- `confidence=low`
- `MISSING_ITEM_NAME`
- `MISSING_QUANTITY`
- `MISSING_UNIT`
- `RANGE_QUANTITY`
- `INVALID_QUANTITY`
- `AMBIGUOUS_ROW_TYPE`
- `MULTIPLE_NUMBERS`
- `PRICE_COLUMN_PRESENT`

## 9. 警告码

| 警告码 | 含义 | 默认处理 |
|--------|------|----------|
| `MISSING_ITEM_NAME` | 缺项目名称 | 不自动报价 |
| `MISSING_QUANTITY` | 缺数量 | 不自动报价 |
| `MISSING_UNIT` | 缺单位 | 需人工确认 |
| `INVALID_QUANTITY` | 数量为 0、负数或非法文本 | 不自动报价 |
| `RANGE_QUANTITY` | 数量为范围值 | 需人工确认 |
| `APPROXIMATE_QUANTITY` | 数量为约数 | 需人工确认 |
| `MULTIPLE_NUMBERS` | 同一行多个数字，需要判断哪个是工程量 | 需人工确认 |
| `POSSIBLE_SUMMARY_ROW` | 疑似合计/小计行 | 默认不报价 |
| `POSSIBLE_NOTE_ROW` | 疑似说明行 | 默认不报价 |
| `POSSIBLE_SECTION_ROW` | 疑似区域/章节行 | 默认不报价 |
| `AMBIGUOUS_HEADER` | 表头不清晰 | 需人工确认列映射 |
| `MERGED_CELL_EXPANDED` | 合并单元格被展开 | 保留警告，供人工核对 |
| `MULTI_SHEET_DETECTED` | 多 Sheet 文件 | 每个 Sheet 单独输出 |
| `PRICE_COLUMN_PRESENT` | 原表包含价格列 | 提示未采用甲方价格 |
| `LOW_CONFIDENCE` | 低置信度 | 必须人工确认 |

## 10. 人工确认口径

业务员在 BIZ-2l-2 中应能完成以下动作：

- 修改列映射：把系统猜错的列改为项目名称、规格、数量、单位、备注等标准字段。
- 修改行内容：编辑项目名称、规格、数量、单位、备注。
- 剔除行：把说明行、合计行、空行、无法报价行排除。
- 确认低置信度行：只有人工确认后才能进入报价。
- 查看原始行：每个标准行都能追溯原始 Sheet、行号和原字段。

默认规则：

- `high` 置信度行可默认选中，但仍允许修改。
- `medium` 置信度行默认选中并提示复核。
- `low` 置信度行默认不进入报价，必须人工确认。
- `summary_row`、`note_row`、`empty_row` 默认不进入报价。
