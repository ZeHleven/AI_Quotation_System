# AI 应用安全与隐私：Prompt 注入、内容安全、敏感数据与脱敏

## 核心结论

LLM 输出应视为不可信建议，用户输入、网页、文档、图片和工具返回都应视为不可信数据。

```text
不可信输入
→ 隔离与分类
→ 最小上下文
→ 模型生成
→ 输出安全检查
→ 权限与业务校验
→ 人工或受控执行
```

Prompt 中写“不要泄露、不要越权”只是软约束。真正安全边界必须由代码、权限、数据隔离、工具作用域和人工审批建立。

---

## 1. 威胁建模

先识别：

- 谁可以输入数据；
- 模型能读取哪些系统和资料；
- 模型能调用哪些工具；
- 输出会进入页面、数据库、Shell 还是外部消息；
- 哪些动作不可逆；
- 哪些数据属于个人、财务、商业或安全敏感信息。

一条典型风险链：

```text
恶意文件含隐藏指令
→ RAG 召回
→ 模型把数据当命令
→ 提出读取其他项目资料
→ 工具用管理员身份执行
→ 敏感数据进入输出和日志
```

安全设计要在每一跳阻断，不能只依赖模型识别攻击。

---

## 2. Prompt Injection

### 直接注入

用户直接要求模型忽略原指令、泄露系统信息或调用越权工具。

### 间接注入

攻击指令藏在：

- 网页；
- PDF、Word、邮件；
- RAG 知识库；
- 工具返回；
- OCR 文本；
- 图片或二维码；
- 其他 Agent 消息。

间接注入更危险，因为内容表面上是“业务资料”。

### Jailbreak 与 Prompt Injection

- Prompt Injection：输入让模型偏离系统预期；
- Jailbreak：试图绕过模型自身安全策略，可视为注入的一类。

无论分类如何，工程目标都是限制攻击的影响范围。

### 防御纵深

```text
输入分类与大小限制
→ 指令和外部数据显式隔离
→ 只提供最小相关上下文
→ 限制模型可见工具
→ 工具参数 Schema
→ 服务端重新鉴权
→ 高风险动作人工批准
→ 输出校验与审计
→ 注入回归测试
```

RAG 和微调不能自动消除 Prompt Injection。恶意内容进入知识库后仍可能被召回。

---

## 3. 不当输出处理

模型输出可能包含：

- HTML/JavaScript；
- SQL；
- Shell 命令；
- URL；
- 文件路径；
- 工具参数；
- 错误金额或伪造引用。

禁止把模型文本直接：

- 拼接进 SQL；
- 交给 Shell；
- 当 HTML 原样渲染；
- 作为权限判断；
- 执行转账、删除或下发；
- 写入可信知识库。

正确流程：

```text
模型输出
→ Schema 解析
→ 编码/转义
→ 参数化接口
→ 资源和权限校验
→ 业务规则
→ 风险审批
```

---

## 4. 敏感信息分类

可按业务分级：

| 等级 | 示例 | 处理原则 |
|---|---|---|
| 公开 | 官网资料、公开标准 | 可正常处理 |
| 内部 | 流程文档、普通报价模板 | 受控访问，不公开传播 |
| 机密 | 客户报价、合同、成本底价 | 最小授权、加密、审计 |
| 高敏 | 密钥、Token、身份证、账号 | 默认不进入模型和日志 |

还要识别：

- 个人身份信息；
- 联系方式；
- 财务信息；
- 商业秘密；
- 鉴权凭证；
- 系统 Prompt 与内部架构；
- 训练、评测和日志中的原始业务资料。

敏感性取决于组合。单个字段看似普通，组合后也可能识别个人或客户。

---

## 5. 隐私生命周期

### 收集

- 明确业务目的；
- 只收集必要字段；
- 告知用途、保留和共享范围；
- 不默认把用户数据用于训练。

### 传输给模型前

```text
数据分类
→ 权限过滤
→ 删除无关字段
→ 脱敏或令牌化
→ 选择允许的模型/地域
→ 记录数据处理决策
```

### 存储

- 传输和静态加密；
- 数据与密钥分离；
- 按字段和资源控制访问；
- 定义保留期；
- 支持删除、更正和访问审计；
- 备份中的数据也受同样治理。

### 进入日志、Trace 和评测集

默认保存：

- 哈希、ID、版本；
- 字段统计；
- 脱敏摘要；
- 错误码；
- 证据引用。

谨慎保存完整 Prompt、工具参数和原始文档。评测集中的生产样本必须经过授权、脱敏、去重和访问控制。

## 6. 脱敏、令牌化、加密与哈希

| 方法 | 作用 | 是否可恢复 |
|---|---|---|
| Masking | 展示部分字符，如手机号中间隐藏 | 通常不需要恢复 |
| Redaction | 删除或替换敏感内容 | 否 |
| Tokenization | 用无意义 Token 替代，映射单独保存 | 可受控恢复 |
| Encryption | 使用密钥加密 | 可解密 |
| Hashing | 生成不可逆摘要，用于比对 | 通常不可恢复 |

常见错误：

- 只按字段名识别，漏掉正文中的身份证或密钥；
- 同一数据在输入脱敏，却在异常堆栈泄露；
- 开发环境脱敏，导出的 CSV 和备份未脱敏；
- 用普通哈希保存低熵密码；
- 日志脱敏后，Trace 或审计详情仍保存原文。

### 双层检测

```text
确定性规则：手机号、身份证、密钥格式
+ 语义检测：商业秘密、合同敏感条款
```

语义检测也会误报和漏报，高风险数据应采用默认拒绝、明确白名单和人工复核。

## 7. 内容安全

内容安全策略要按具体业务定义，而不是只有“有害/无害”：

- 违法或危险指导；
- 暴力、仇恨、骚扰；
- 色情与未成年人风险；
- 自伤风险；
- 欺诈和社会工程；
- 恶意代码；
- 个人信息和商业秘密；
- 伪造事实与误导性报价；
- 不适合当前业务的内容。

处理动作可以是：

```text
allow
→ 正常返回

transform
→ 删除敏感字段、降低细节、改为安全说明

review
→ 转人工

block
→ 拒绝并记录安全类别
```

输入过滤、输出过滤和工具行为控制要分开。文本回答安全，不代表工具动作安全。

---

## 8. 安全测试集

至少覆盖：

- 直接“忽略所有规则”；
- PDF 中隐藏指令；
- RAG 文档诱导跨项目读取；
- 图片中的越权指令；
- Base64、错别字、多语言和分段载荷；
- 诱导输出系统 Prompt；
- 诱导泄露成本底价、Token 或其他用户数据；
- 模型输出脚本、HTML、SQL；
- 越权工具参数；
- 高风险内容和边界内容。

指标：

```text
攻击成功率
注入阻断率
敏感信息泄露率
误拦截率
高风险转人工率
越权动作实际执行数
```

严重泄露或越权应作为硬门槛，不能被平均质量分抵消。

## 9. 报价中台的真实映射

### 已具备

- JWT、RBAC、`role_version` 和管理员依赖；
- 成本库、报价、Agent 工具存在资源级和角色级控制；
- Tender Evidence MCP 使用短期 scope，并保持只读；
- Agent 执行 Trace 会对 `secret/token/password/authorization` 等字段脱敏并限制长度；
- 部分外发 OCR 文本支持敏感文本遮罩；
- 高风险报价、证据不足和低置信度结果进入人工复核；
- Prompt、工具输出和结构化结果存在 Schema 与业务校验。

### 仍需补强

- 通用 JSON 日志格式化器目前没有统一的 PII/密钥深度脱敏层；
- 字段名脱敏不能识别正文中的手机号、身份证或商业秘密；
- 尚未形成统一的数据分类、保留期、删除和第三方模型传输策略；
- 没有统一的输入/输出内容安全服务和策略版本；
- 尚缺系统化的多模态 Prompt Injection 红队集；
- 不同 Trace、导出、评测数据和备份的脱敏策略仍需统一。

## 10. 面试回答模板

### 如何防 Prompt Injection？

> 我不会承诺完全识别所有注入，而是做防御纵深：把外部内容标为不可信数据，控制上下文和工具暴露；工具使用最小权限和服务端重新鉴权；高风险动作必须人工批准；输出做 Schema、业务和安全校验；最后用直接、间接和多模态攻击集持续回归。

### 如何防止敏感信息泄露？

> 从数据生命周期治理：先分类和最小化，调用模型前做权限过滤与脱敏，按合规选择供应商；日志、Trace、评测集和导出只保留必要字段并设置访问和保留期；输出再做 DLP 检查。Prompt 禁止泄露只能作为补充，不能替代权限和数据控制。

### 内容安全与权限控制有什么区别？

> 内容安全判断输入输出是否属于禁止或高风险类别；权限控制判断当前主体能否访问资源或执行动作。回答文本安全不代表用户有权读取数据，内容违规也不能靠 RBAC 自动识别。
