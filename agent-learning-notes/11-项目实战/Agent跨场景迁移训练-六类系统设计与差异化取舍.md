# Agent 跨场景迁移训练：六类系统设计与差异化取舍

## 1. 训练目标

报价中台是能力证据，不应成为唯一答案模板。

跨场景训练要求在陌生业务中重新决定：

- 接入层如何设计；
- State 保存什么；
- Workflow 与 Agent 怎样分工；
- Tool 权限多大；
- RAG 是否必要；
- 哪些步骤异步；
- 哪些动作必须人工确认；
- 审计记录什么；
- 怎样评测任务是否成功。

## 2. 不变的八层骨架

```text
入口与身份
→ 任务与状态
→ Workflow / Planner
→ Context / RAG / Memory
→ Tool / MCP
→ Policy / Human Gate
→ 异步执行与持久化
→ Trace / Evaluation / Feedback
```

骨架可以复用，组件、数据和风险边界必须重新设计。

## 3. 场景差异矩阵

| 场景 | 核心目标 | 关键状态 | 主要工具 | 人工门禁 | 核心评测 |
|---|---|---|---|---|---|
| 企业知识助手 | 有依据地回答内部问题 | 会话、权限、证据 | 搜索、文档读取 | 高风险结论 | Recall、引用、无答案 |
| 客服 Agent | 解决问题并控制升级 | 工单、用户、情绪、SLA | CRM、订单、退款 | 退款、补偿、投诉 | 解决率、升级率、满意度 |
| 手机智能助理 | 在个人设备执行动作 | 会话、设备、位置、授权 | 日历、通讯录、应用 | 发送、支付、删除 | 任务成功、误操作、延迟 |
| 代码 Agent | 修改仓库并通过验证 | Repo、分支、补丁、测试 | 搜索、编辑、测试、Git | 合并、发布、密钥 | 测试通过、回滚率、安全 |
| 合同审核系统 | 识别风险并给出证据 | 合同版本、条款、规则 | OCR、检索、规则、批注 | 法律结论、签署 | 条款召回、证据、漏检率 |
| 高并发 Agent 平台 | 多租户稳定运行 Agent | 租户、Run、配额、路由 | 模型、工具、队列、存储 | 高风险工具和发布 | SLO、成本、隔离、成功率 |

## 4. 企业知识助手

### 设计重点

- 身份和部门权限必须进入检索过滤；
- 文档版本和有效期进入元数据；
- 无答案优先于编造；
- 引用必须定位到文件、页码或段落；
- 对话 Memory 不能覆盖企业事实。

### 必做训练

1. 设计 50 条权限与无答案测试集；
2. 制造旧版本文档和同名冲突；
3. 比较 Dense、BM25、RRF 与 Rerank；
4. 记录答案正确率、引用支持率和越权召回率；
5. 设计文档更新和索引蓝绿切换。

## 5. 客服 Agent

### 设计重点

- Workflow 负责退款、升级和 SLA 等确定性流程；
- Agent 负责意图理解、信息收集和回复草稿；
- CRM、订单、物流和退款工具必须按用户资源授权；
- 情绪、投诉和高金额进入人工；
- 重试不能重复退款或重复创建工单。

### 必做训练

- 实现工单状态机；
- 设计退款幂等键；
- 制造 CRM 超时和订单半成功；
- 观察首响时间、一次解决率、人工升级率；
- 编写 Prompt Injection 和社会工程测试。

## 6. 手机智能助理

### 设计重点

- 设备权限是动态的，不能只在登录时判断；
- 读取日历和发送消息属于不同风险级别；
- 位置、联系人和录音属于高度敏感数据；
- 离线、弱网和系统取消必须可恢复；
- 对“发送、支付、删除、公开发布”采用确认门。

### 必做训练

- 画出语音输入到设备动作的时序图；
- 设计短期授权令牌；
- 制造 App 切后台、网络切换和用户撤销；
- 定义误操作率、确认率、端到端延迟和隐私事件指标。

## 7. 代码 Agent

### 设计重点

- 先读取仓库规则和测试边界；
- 检索对象是代码、符号、调用图和提交历史；
- 工具需要目录、命令和网络沙箱；
- Patch 必须经过静态检查、测试和 Diff 审核；
- 不能让 Agent 直接推送主分支或访问生产密钥。

### 必做训练

1. 给一个小仓库实现 Bug 修复 Agent；
2. 限制可编辑目录；
3. 制造测试失败、命令超时和恶意仓库指令；
4. 记录补丁成功率、测试通过率、回滚率和 Token 成本；
5. 对比单 Agent 与 Planner/Worker/Reviewer。

## 8. 合同审核系统

### 设计重点

- OCR 和版面恢复决定条款边界；
- 规则库负责确定性红线；
- RAG 提供法规、模板和历史条款证据；
- 模型生成风险候选，不直接替代法律结论；
- 合同版本、修订、批注和人工决定必须审计。

### 必做训练

- 构造缺页、扫描倾斜、表格跨页和修订痕迹；
- 建立条款级 Gold；
- 测量条款召回、风险漏检、误报和证据支持率；
- 设计法律人员确认和版本回滚。

## 9. 高并发 Agent 平台

### 设计重点

- 多租户配额、数据和工具隔离；
- Model Gateway 做路由、限流、熔断和成本统计；
- Run、Step、Tool Call 和 Checkpoint 形成统一状态；
- 长短任务分队列，支持背压和公平调度；
- 统一 Trace、Eval Run、Prompt/Tool/Model 版本；
- 高风险工具和版本发布有组织级审批。

### 必做训练

- 估算 QPS、并发槽、队列等待和 Token 吞吐；
- 设计租户级限流与预算；
- 制造单租户洪峰、模型 429、队列积压和 Worker 宕机；
- 验证租户隔离、降级、公平性和恢复时间。

## 10. 同一能力怎样迁移

### 状态

| 报价中台 | 迁移场景 |
|---|---|
| quote_job | ticket、assistant_run、code_task、contract_review |
| requirement_row | user_intent、repo_issue、contract_clause |
| preview_draft | reply_draft、patch_draft、risk_draft |
| confirm_push | refund、send、merge、legal_approve |

### RAG

- 报价：成本事实和项目资料；
- 知识助手：部门文档和权限；
- 客服：产品知识、政策和历史工单；
- 代码：仓库、符号和依赖；
- 合同：条款、法规和模板；
- 平台：由租户自定义，平台负责隔离和评测。

### Human-in-the-loop

人审点不是固定页面，而是风险函数：

```text
影响范围 × 不可逆性 × 金额 × 隐私 × 证据不足 × 置信度
```

## 11. 限时系统设计模板

每题 35 分钟：

### 前 5 分钟：澄清

- 用户是谁；
- 核心任务和成功标准；
- 数据敏感度；
- 哪些动作不可逆；
- 流量、延迟和成本约束。

### 中间 15 分钟：主链路

- 画入口、状态、RAG/Memory、Tool、异步和持久化；
- 标出事实源；
- 标出权限和人工门；
- 说明同步与异步边界。

### 接下来 10 分钟：可靠性与评测

- 超时、重试、幂等；
- Checkpoint 和恢复；
- 日志、指标和 Trace；
- 离线测试集和在线 SLO；
- 灰度与回滚。

### 最后 5 分钟：取舍

- 为什么不用纯 Workflow；
- 为什么不用全自动；
- 哪些部分先做 MVP；
- 最大风险和后续演进。

## 12. 迁移训练题

对每道题都提交架构图、API、状态机、故障清单和指标：

1. 设计十万员工使用的企业知识助手；
2. 设计支持退款的电商客服 Agent；
3. 设计可操作日历和消息的手机助理；
4. 设计能修改代码并发起 PR 的代码 Agent；
5. 设计合同风险审核与批注系统；
6. 设计支持一千租户的 Agent 平台；
7. 把其中一个方案写成最小代码；
8. 把报价中台的一个故障迁移到该方案并重新排障。

## 13. 迁移验收标准

- [ ] 不使用“报价”名词也能完整讲系统
- [ ] 能指出每个场景的事实源
- [ ] 能重新设计状态和工具权限
- [ ] 能说明 RAG 是否必要以及索引边界
- [ ] 能设计异步、取消、恢复和幂等
- [ ] 能给出人工门和审计字段
- [ ] 能定义场景特有的成功率
- [ ] 能说出 MVP 与生产版差异

> 迁移能力的本质不是换业务名词，而是重新识别约束、风险、状态和证据。
