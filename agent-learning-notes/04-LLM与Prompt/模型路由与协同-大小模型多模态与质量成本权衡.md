# 模型路由与协同：大小模型、多模态与质量成本权衡

## 核心结论

模型选型不是“永远调用最强模型”，而是：

> 在能力、风险、延迟、成本、上下文、数据合规和当前健康度约束下，选择满足任务质量门槛的最低总成本方案。

```text
任务识别
→ 能力与合规过滤
→ 小模型/规则优先处理
→ 低置信度或高风险升级大模型
→ 结果校验
→ 失败时安全回退或人工审核
```

大小模型协同的价值来自可验证分工，而不是把一个请求随意调用多个模型。

---

## 1. 模型能力矩阵

模型不能只按参数量排名。每个候选模型都要记录：

| 维度 | 问题 |
|---|---|
| 任务质量 | 在本业务评测集上是否达标？ |
| 模态 | 是否支持文本、图片、音频或视频？ |
| 工具能力 | Tool Calling 和参数生成是否稳定？ |
| 结构化输出 | 是否支持 JSON/Schema 约束？ |
| 上下文 | 最大窗口和长上下文质量如何？ |
| 延迟 | TTFT、生成速度、P95 是否达标？ |
| 成本 | 输入、输出、缓存和托管成本如何？ |
| 合规 | 数据能否发送给该供应商和区域？ |
| 稳定性 | 限流、错误率、版本变更如何？ |
| 可运维性 | 是否可观测、可回滚、可替换？ |

公开榜单只能提供初筛，最终要用自己的数据、Prompt、Schema 和质量门评测。

## 2. 模型路由

### 2.1 静态规则路由

按任务类型直接指定模型：

```text
图片清单抽取 → 视觉模型
短文本分类   → 小模型或规则
复杂风险分析 → 强推理模型
Embedding    → 专用向量模型
Rerank       → 专用重排模型
```

优点是可解释、易审计，适合早期和高风险业务。

### 2.2 级联路由

先调用成本更低的模型，置信度不足再升级：

```text
规则/小模型
  ├─ 通过质量门 → 返回
  └─ 不确定     → 大模型
                    ├─ 通过 → 返回
                    └─ 高风险 → 人工审核
```

关键不是模型自报“置信度”，而是使用：

- Schema 是否通过；
- 必填字段是否完整；
- 规则是否一致；
- 证据是否覆盖；
- 独立分类器或验证器得分；
- 业务风险等级。

### 2.3 动态路由

动态路由还会考虑：

- 当前延迟和错误率；
- 供应商限额；
- Token 与预算；
- 上下文长度；
- 租户或用户等级；
- 数据地域；
- 灰度版本。

生产路由需要保存：

```text
候选集合
过滤原因
路由策略版本
实际模型与参数
Fallback 是否发生
最终质量和成本
```

### 2.4 Fallback 的边界

备用模型必须满足同一关键语义：

- Schema 兼容；
- 工具能力兼容；
- 上下文足够；
- Prompt 已适配；
- 数据合规；
- 质量达到当前风险门槛。

高风险报价或审批任务中，备用模型不达标时应安全失败或转人工，不能为“接口成功率”牺牲正确性。

## 3. 小模型和大模型如何协同

### 小模型适合

- 意图分类；
- 路由；
- 内容审核；
- 实体抽取；
- 查询改写；
- 文档相关性粗排；
- 格式和简单规则检查；
- 大批量低风险任务。

### 大模型适合

- 模糊需求理解；
- 多证据综合；
- 复杂规划和推理；
- 长文档分析；
- 高难度结构生成；
- 需要跨模态理解的任务。

### 四种协同模式

#### 模式一：小模型分流，大模型执行

```text
小模型判断任务、语言、风险
→ 路由到专用大模型
```

#### 模式二：小模型先做，大模型兜底

适合大量简单请求，但升级条件必须可测量。

#### 模式三：大模型生成，小模型验证

小模型可检查格式、分类或安全，但不能验证超出其能力范围的复杂事实。

#### 模式四：专用模型流水线

```text
OCR/版面模型
→ 视觉语言模型
→ 文本大模型
→ Embedding/Rerank
→ 规则校验
```

这通常比让一个通用大模型包办所有步骤更可控。

### 协同的成本风险

- 多次调用可能让总成本反而更高；
- 小模型误路由会直接损害质量；
- 级联增加端到端延迟；
- 多模型版本和 Prompt 更难治理；
- 同一数据可能跨供应商流转，扩大合规面。

因此要比较“每个成功任务成本”，而不是单次模型价格。

## 4. 多模态模型基础

多模态模型接受文本之外的图片、音频或视频输入。一个简化视觉语言架构是：

```text
图片
→ 图像预处理/视觉编码器
→ 视觉特征
→ 投影或对齐模块
→ 语言模型上下文
→ 文本或结构化结果
```

不同模型实现不同，不能把这张简图当成所有架构的固定实现。

### 多模态输入也消耗预算

图片会被缩放、切块或编码为视觉表示；视频还要抽帧。输入成本受以下因素影响：

- 分辨率；
- 图片数量；
- 视频帧数；
- 裁剪方式；
- 模型的视觉 Token 规则；
- OCR 或局部放大次数。

“上下文窗口足够”不代表可以无限上传高清图片。

### OCR 与视觉语言模型如何选

| 任务 | 更合适的方法 |
|---|---|
| 清晰印刷文字批量识别 | OCR |
| 表格结构、图文关系 | 版面模型或 VLM |
| 图纸符号与空间关系 | VLM + 专用规则 |
| 精确数值和金额 | OCR/VLM 后再做程序校验 |
| 视觉问答与综合解释 | VLM |

OCR 输出文本更易审计，VLM 擅长图文关系，但都可能识别错误。高风险数据要保留页码、坐标、裁剪图和置信度。

### 多模态工程链路

```text
文件安全检查
→ 解码与标准化
→ 分页/抽帧/切图
→ OCR 或视觉模型
→ 结构化 Schema
→ 证据定位
→ 业务规则校验
→ 低置信度人工复核
```

必须记录：

- 原始文件哈希；
- 页码或时间戳；
- 区域坐标；
- 预处理参数；
- 模型和 Prompt 版本；
- 输出与证据；
- 是否人工修正。

## 5. 质量、速度与成本的权衡

### 三类延迟

```text
TTFT：等待首 Token
TPOT / ITL：后续 Token 生成间隔
E2E：端到端总耗时
```

### 成本

闭源 API：

```text
输入 Token 费用
+ 输出 Token 费用
+ 缓存/多模态费用
+ 重试与多候选费用
```

自部署：

```text
GPU 与服务器
+ 空闲容量
+ 运维与监控
+ 网络和存储
+ 升级与故障成本
```

### 质量不能只看一个准确率

报价中台至少要看：

- 需求行完整率；
- 字段和金额正确率；
- 证据有效率；
- 幻觉与无答案率；
- 人工修改和打回率；
- 任务成功率；
- P95 延迟；
- 每个成功报价成本。

### Pareto 思维

若模型 A 更贵、更慢，质量却没有明显提高，它被模型 B 支配，不应默认使用。

选型步骤：

```text
1. 先定义最低质量和安全门槛
2. 淘汰不达标模型
3. 在达标模型中比较 P95 延迟和成功任务成本
4. 设计简单任务降级和复杂任务升级
5. 灰度并持续监控分布漂移
```

不要把“平均准确率最高”直接等同于生产最优。

## 6. 路由评测

离线数据集应包含：

- 简单、普通、复杂任务；
- 长上下文；
- 图片模糊和表格复杂场景；
- 无答案和冲突证据；
- 高风险与低风险；
- 不同语言和文件格式。

评测指标：

```text
任务质量
路由准确率
不必要升级率
错误降级率
Fallback 成功率
每成功任务成本
P50/P95 延迟
人工接管率
```

路由器也需要版本、回归、灰度和回滚。

## 7. 报价中台的真实映射

### 已具备

- `model_gateway.py` 已封装 OpenAI 风格、DashScope 和智谱等模型调用；
- 视觉报价可在 GLM 视觉模型和 DashScope 视觉模型之间配置；
- DeepSeek 等文本模型按具体业务用途配置；
- 网关记录供应商、模型、状态、耗时、字符量和成本估算；
- 已有超时、重试和进程内熔断状态；
- 图片、PDF、图纸会经过切图、OCR/VLM、证据提取和业务校验；
- Embedding 与 BM25/RRF、Rerank 等专用能力已经分工；
- 高风险结果进入预审和人工确认。

### 尚未形成

- 没有统一的大小模型级联策略；
- 没有基于真实质量、成本和实时健康度的动态路由器；
- 熔断状态主要是进程内状态，并非分布式共享控制面；
- 供应商调用契约和精确 Token 计费尚未完全统一；
- 多模态质量评测仍需积累更多真实金标；
- 当前主要使用外部模型 API，不是自部署大小模型集群。

## 8. 面试回答模板

### 模型路由应该考虑什么？

> 先用模态、工具能力、Schema、上下文和数据合规过滤候选，再根据任务风险、离线质量、P95 延迟、预算和实时健康度选择。路由决策必须可审计，Fallback 也要满足同一关键契约；高风险场景不达标就转人工或安全失败。

### 小模型和大模型怎样协同？

> 小模型适合分类、抽取、粗排和安全检查，大模型处理复杂推理和多证据综合。常见方式是小模型分流或先做、大模型兜底，也可以大模型生成后由确定性规则和专用模型验证。升级条件应来自 Schema、证据和业务规则，不能只信模型自报置信度。

### 多模态模型能代替 OCR 吗？

> 不能简单替代。清晰文字批量识别用 OCR 更便宜、可审计；复杂版面、图文关系和图纸符号可用 VLM。生产中通常组合使用，并保留页码、坐标和裁剪图，再对数值和业务规则做程序校验。

### 如何权衡成本、速度和准确率？

> 先设质量和安全最低门槛，淘汰不达标方案；再比较 P95 延迟与每成功任务成本，而不是只看单价或平均准确率。对简单任务用低成本模型，高风险或不确定任务升级，并用灰度数据持续调整。
