# BIZ-3a-1 单人试运行版

更新时间：2026-06-01

## 定位

BIZ-3a-1 面向系统正式多人推广前的单人试运行。当前只要求负责人本人使用项目进度条，不要求其他岗位登录填报，也暂不接钉钉或企微。

目标是先验证三件事：

- 默认 8 阶段和权重是否符合真实工程节奏。
- `25 / 50 / 80 / 100` 进度规则是否容易判断。
- 每天维护项目是否真的能降低沟通和记忆成本。

## 新增能力

后端新增接口：

- `POST /api/v1/admin/projects/trial-template`

该接口不新增数据库表，复用 BIZ-3a 的 `projects`、`project_stages`、`project_tasks` 和 `project_task_events`。

创建后会自动生成：

- 1 个工程项目。
- 默认 8 个阶段。
- 18 个常用试运行任务。
- 阶段负责人和任务负责人全部指向当前登录用户。
- 任务来源标记为 `source_type=system`、`source_id=single_user_fitout_v1`。

前端 `/admin/projects` 新增“单人试运行”入口，用于快速创建模板项目。

## 模板任务

| 阶段 | 任务 |
|---|---|
| 立项 | 确认项目基本信息；整理现场照片和原始需求 |
| 报价 | 完成需求清单标准化；完成 AI 报价预审；确认报价版本并发给客户 |
| 合同 | 确认合同范围和付款节点；完成合同签订或待签状态记录 |
| 设计深化 | 确认平面和关键节点做法；确认设计变更清单 |
| 材料确认 | 确认主材品牌和规格；确认材料样板或图片 |
| 采购 | 确认采购清单和到货周期；确认供应商下单状态 |
| 施工 | 确认开工条件；记录现场施工进展；确认变更和签证事项 |
| 验收结算 | 完成现场验收问题记录；完成结算资料整理 |

若填写计划开始和计划完成日期，系统会按 30 天模板节奏自动折算任务截止时间。

## 单人使用规则

每天只做一次更新即可：

| 任务状态 | 进度 | 单人判断口径 |
|---|---:|---|
| 未开始 | 0% | 还没处理 |
| 开始 | 25% | 已看过、已准备、已开始跟进 |
| 推进 | 50% | 已有实质进展，但没有形成可确认结果 |
| 提交 | 80% | 已完成到自己认为可确认的程度 |
| 完成 | 100% | 自己最终确认无待办 |
| 阻塞 | 保持原进度 | 需要客户、供应商、现场或内部条件变化后才能继续 |

单人阶段可以自己点“提交”后再点“完成”，用这一步保留一次复核动作。

## 回退与阻塞闭环

试运行时允许回退进度，但必须填写回退原因。

- `25% 已开始` 可回退到 `0% 未开始`
- `50% 进行中` 可回退到 `25% 已开始`
- `80% 已提交` 可回退到 `50% 进行中`
- `100% 已完成` 可由项目管理人回退到 `80% 已提交`

阻塞任务会在任务列表直接显示阻塞原因和下一步。解除阻塞时必须填写“如何解决”，系统会在项目动态中记录操作人、时间和解决说明。

## 试运行建议

首个真实项目建议连续跑 3-5 天，重点记录：

- 哪些模板任务没有用。
- 哪些任务缺失，需要补进模板。
- 哪些阶段权重感觉偏大或偏小。
- 阻塞原因是否足够表达真实卡点。
- 进度条是否能让你快速判断项目状态。

试运行结束后再决定是否进入 BIZ-3b：多人协同、通知提醒、钉钉/企微接入。

## 验收口径

通过条件：

- 能一键创建单人试运行项目。
- 默认生成 18 个任务，且都分配给当前用户。
- 任务仍按 BIZ-3a 的 2580 规则推进。
- 项目总进度仍按阶段权重自动汇总。
- 不影响普通新建项目、新建任务、项目看板和我的任务。
